## 3. 关键算法/流程详解

### 3.1 Orchestrator.run 主流程（`orchestrator.py:669-869`）

```python
def run(self, task: str) -> ResearchState:
    # 1. 初始化状态
    state = ResearchState(original_task=task, start_time=time.time(), status="initialized")

    # 2. 读取迭代配置
    min_iterations = AGENT_CONFIG.get("min_iterations", 2)
    max_iterations = AGENT_CONFIG.get("max_iterations", 5)
    quality_threshold = AGENT_CONFIG.get("quality_threshold", 80)
    enable_diminishing_returns_check = AGENT_CONFIG.get("enable_diminishing_returns_check", True)

    try:
        # ========== 阶段 1: 任务拆解 ==========
        state.status = "planning"
        state.task_plan = self.decompose_task(task)

        # ========== 阶段 2: 并行研究 ==========
        state.status = "researching"
        state.worker_results = self.dispatch_workers(state.task_plan)

        # ========== 阶段 3: 综合初始报告 ==========
        state.status = "synthesizing"
        current_report = self.synthesize_results(task, state.task_plan, state.worker_results)

        # ========== 阶段 4: 迭代优化循环 ==========
        state.status = "iterating"
        previous_score = 0

        for iteration in range(1, max_iterations + 1):
            # 4.1 质量评估
            quality_result = self.check_quality(current_report, task, state.query_type)
            current_score = quality_result.get("overall_score", 0)
            score_improvement = current_score - previous_score

            # 记录本次迭代
            iteration_record = IterationRecord(
                iteration=iteration,
                report=current_report,
                quality_score=current_score,
                quality_result=quality_result,
                score_improvement=score_improvement,
            )
            state.iteration_history.append(iteration_record)

            # 4.2 是否达标？
            if iteration >= min_iterations and current_score >= quality_threshold:
                break  # 质量通过，结束

            # 4.3 收益递减检测（可选）
            if enable_diminishing_returns_check and iteration >= 2:
                dr_result = self.check_diminishing_returns(...)
                if dr_result.get("diminishing_returns_detected"):
                    break  # 收益递减，提前结束

            # 4.4 补充研究（如未达最大迭代）
            if iteration < max_iterations:
                gap_result = self.analyze_gaps(...)
                if gap_result.stop_recommendation.should_stop:
                    break

                supplementary_tasks = gap_result.supplementary_tasks
                if supplementary_tasks:
                    supplementary_results = self.dispatch_supplementary_workers(supplementary_tasks)
                    current_report = self.refine_report(...)

            previous_score = current_score

        # ========== 阶段 5: 完成 ==========
        state.final_report = current_report
        state.quality_score = state.iteration_history[-1].quality_score
        state.status = "completed"
        state.end_time = time.time()

    except Exception as e:
        state.status = "failed"
        state.error_msg = str(e)

    return state
```

**关键设计点**：

1. **三重终止条件**（4.2-4.4）：分别保证"足够好"、"不再进步"、"差距分析建议停"。
2. **previous_score 追踪**：通过差值计算 `score_improvement` 用于收益递减判断。
3. **状态集中管理**：所有中间产物（plan / results / report / iteration_history）都存入 `ResearchState`。

### 3.2 SearchWorker.execute OODA 循环（`workers.py:141-225`）

```python
def execute(self, subtask) -> dict:
    # 1. 初始化
    self.ooda_cycles = []
    self.all_results = []
    self.budget.queries_used = 0
    self.budget.cycles_used = 0

    # 2. 评估复杂度 + 调整预算
    task_complexity = self._assess_task_complexity(subtask)
    self._adjust_budget(task_complexity)

    # 3. 获取搜索查询
    search_queries = subtask.search_queries or self._expand_queries(...)

    # 4. OODA 循环
    cycle_num = 0
    while not self._should_terminate():
        cycle_num += 1

        # O: 观察 - 执行搜索
        observe_result = self._observe(search_queries, subtask)

        # O: 定向 - 评估来源 + 识别空白
        orient_result = self._orient(observe_result, subtask)

        # D: 决策 - 继续 or 终止
        decide_result = self._decide(orient_result, subtask)

        # A: 行动 - 执行决策
        act_result = self._act(decide_result, search_queries, subtask)

        # 记录循环
        self.ooda_cycles.append(OODACycle(
            cycle=cycle_num,
            observe=observe_result.get("summary", ""),
            orient=orient_result.get("direction", ""),
            decide=decide_result.get("decision", ""),
            act=act_result.get("action_result", ""),
        ))

        # 决策终止
        if decide_result.get("should_terminate"):
            self.termination_reason = decide_result.get("termination_reason", "决策终止")
            break

        # 更新查询
        if decide_result.get("new_queries"):
            search_queries = decide_result["new_queries"]

    # 5. 去重 + LLM 分析
    unique_results = self._deduplicate_results(self.all_results)
    result = self._analyze_results(subtask, unique_results)

    # 6. 附加元信息
    result["ooda_cycles"] = [...]
    result["research_budget_used"] = "5/5 查询"
    result["termination_reason"] = "信息充足"

    return result
```

### 3.3 并行调度算法（`orchestrator.py:237-314`）

```python
def dispatch_workers(self, task_plan) -> list[dict]:
    # 1. 确定实际并行数（取三者最小值）
    actual_workers = min(
        len(task_plan.subtasks),
        self.max_workers,
        task_plan.query_type.recommended_worker_count or self.max_workers,
    )

    results = []

    # 2. 使用线程池并行执行
    with ThreadPoolExecutor(max_workers=actual_workers) as executor:
        # 提交所有任务
        future_to_task = {}
        for subtask in task_plan.subtasks:
            worker = self.worker_factory()           # 每个 Worker 独立实例
            future = executor.submit(worker.execute, subtask)
            future_to_task[future] = subtask

        # 收集结果（完成的优先产出）
        for future in as_completed(future_to_task):
            subtask = future_to_task[future]
            try:
                result = future.result(timeout=AGENT_CONFIG["timeout_per_worker"])
                subtask.status = "completed"
                results.append(result)
            except Exception as e:
                subtask.status = "failed"
                results.append({"task_id": subtask.id, "success": False, "error": str(e)})

    return results
```

**关键设计**：

- **每 Worker 独立实例**（`worker_factory()`）：避免共享状态冲突。
- **`as_completed` 优先取已完成**（`orchestrator.py:284`）：让前端能实时看到最先完成的 Worker。
- **超时控制**（`timeout=120`，`orchestrator.py:287`）：单 Worker 超时不影响其他。

### 5.2 JSON 多重解析策略（`tools.py:292-320`）

```python
def extract_json(text: str) -> dict:
    # 策略 1：匹配 Markdown JSON 代码块 ```json ... ```
    json_match = re.search(r"```json\s*(.*?)\s*```", text, re.DOTALL)
    if json_match:
        try:
            return json.loads(json_match.group(1))
        except json.JSONDecodeError:
            pass

    # 策略 2：暴力提取第一个 { 到最后一个 }
    try:
        start = text.find("{")
        end = text.rfind("}") + 1
        if start != -1 and end > start:
            return json.loads(text[start:end])
    except json.JSONDecodeError:
        pass

    return {}
```

**解读**：LLM 输出 JSON 时常出现 markdown 包裹、前后多余文字等"轻微不规范"情况。该函数采用**降级策略**：先尝试规范化（代码块），失败则暴力提取大括号，失败则返回空字典。

    queries_used: int = 0

### 5.5 SSE 事件流实现（`api.py:389-451`）

```python
@app.get("/research/{task_id}/stream", tags=["研究任务"])
async def stream_task_progress(task_id: str):
    task = task_manager.get_task(task_id)
    if not task:
        raise HTTPException(status_code=404, detail=f"任务 {task_id} 不存在")

    async def event_generator():
        last_progress_count = 0

        while True:
            task = task_manager.get_task(task_id)
            if not task:
                break

            # 发送新进度事件
            current_progress = task["progress"]
            if len(current_progress) > last_progress_count:
                for event in current_progress[last_progress_count:]:
                    yield f"data: {json.dumps(event, ensure_ascii=False)}\n\n"
                last_progress_count = len(current_progress)

            # 检查是否完成
            if task["status"] in ["completed", "failed"]:
                final_event = {...}
                yield f"data: {json.dumps(final_event, ensure_ascii=False)}\n\n"
                break

            await asyncio.sleep(0.5)  # 每0.5秒检查一次

    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
        },
    )
```

**解读**：
- `media_type="text/event-stream"` 标识 SSE 协议；
- `yield f"data: {json.dumps(...)}\n\n"` 严格遵守 SSE 协议（每个事件以 `\n\n` 结尾）；
- `await asyncio.sleep(0.5)` 让事件循环有机会处理取消（FastAPI 文档明确要求）；
- `last_progress_count` 记录已发送位置，避免重复推送。

- `argparse.RawDescriptionHelpFormatter` 保留 epilog 换行；
- `action="store_true"` 用于布尔开关；
- `default=None` 配合 SDK 内 `or AGENT_CONFIG[...]` 使用默认值。

## 7. 并发与同步设计

### 7.1 并发层次

| 层次 | 工具 | 并发数 | 同步机制 |
|------|------|--------|----------|
| API 多任务 | `TaskManager.executor` (ThreadPool) | 3 | 线程间共享 `tasks` 字典（受 GIL 保护） |
| 单任务多 Worker | `Orchestrator.dispatch_workers` (ThreadPool) | ≤6 | `as_completed` 取结果 |
| Worker 内部 | 顺序 | 1 | 单线程 OODA 循环 |
| LLM / 搜索 | 网络请求（同步阻塞） | - | `time.sleep(0.3)` 防限流 |

### 7.2 共享状态保护

- `TaskManager.tasks` 字典被多线程读写，但每个 dict 操作都是原子的（CPython 实现），无需加锁；
- 进度事件是"追加 + 读最后位置"，天然适合无锁；
- `ResearchState` 在 `Orchestrator.run()` 内是单线程的（不会跨线程），无并发问题。

### 7.3 死锁与异常处理

- Worker 失败：`future.result()` 抛出 → 捕获后转为 `success=False` 结果；
- Worker 超时：`future.result(timeout=120)` 抛 `TimeoutError` → 同上处理；
- LLM 调用失败：`LLMResponse.success=False` → 上层使用默认值继续。

## 8. 性能优化点

| 优化点 | 实现位置 | 效果 |
|--------|----------|------|
| Worker 并行 | `dispatch_workers` (orchestrator.py:269) | 端到端时间缩短 3~5 倍 |
| LLM 异步流式 | `LLMClient.chat_stream` (tools.py:116) | 改善流式体验（当前未在 Worker 使用） |

## 9. 已知坑与边界条件

1. **任务拆解 JSON 解析失败**：若 LLM 返回非预期格式，`extract_json` 返回 `{}`，后续因 `result.get("subtasks", [])` 为空而崩溃。改进：默认提供 1 个"通用研究"任务兜底。
2. **`time.sleep(0.3)` 简单防限流**：仅对单一调用方足够，多任务并发时仍可能触发博查 API 速率限制。改进：引入令牌桶或指数退避。
3. **TaskManager 内存泄漏**：所有任务数据常驻内存，删除任务仅 `del task_manager.tasks[task_id]`。改进：定期归档或使用 Redis。
4. **临时修改全局配置**（`api.py:230-251`）：通过修改 `AGENT_CONFIG` 字典实现请求级配置，存在竞态风险（多个并发请求相互覆盖）。改进：改为实例级配置对象。
5. **OODA `_decide` 仅基于关键词匹配**（`workers.py:330-351`）：简化实现，可能误判。改进：调用 LLM 做更智能的决策。
6. **`_identify_information_gaps` 也用关键词匹配**（`workers.py:397`）：未实际做语义差距检测。

## 10. 本章设计原理与依据

### 原理 1：依赖注入（Dependency Injection）

- **核心思想**：通过构造函数注入依赖，而非内部硬编码 new，便于替换与测试。
- **在本项目中的体现**：`Orchestrator(worker_factory=...)`、`TaskManager.executor` 都是依赖注入。
- **为什么有效**：单元测试时可注入 mock；生产环境可替换为不同实现。
- **佐证**：[设计模式] Dependency Injection — Martin Fowler

### 原理 2：工厂模式（Factory Pattern）

- **核心思想**：通过工厂函数/方法创建对象，将"创建逻辑"与"使用逻辑"解耦。
- **在本项目中的体现**：`WorkerFactory`（`workers.py:738`）、`search_worker_factory`（`workers.py:768`）。
- **为什么有效**：便于新增 Worker 类型，无需修改 Orchestrator。

### 原理 3：模板方法模式（Template Method Pattern）

- **核心思想**：父类定义算法骨架，子类实现具体步骤。
- **在本项目中的体现**：`BaseWorker.execute()`（`workers.py:86`）是抽象方法，由 `SearchWorker`/`WriterWorker` 等实现。
- **为什么有效**：保证所有 Worker 都有 `execute` 接口；新增 Worker 类型只需继承 `BaseWorker`。

### 原理 4：观察者模式（Observer Pattern）

- **核心思想**：被观察对象状态变化时通知所有观察者。
- **在本项目中的体现**：`Orchestrator.on_progress` 回调（`orchestrator.py:127-148`）。
- **为什么有效**：核心逻辑与 UI 渲染解耦，支持 CLI/SDK/API 三种使用方式。

### 原理 5：上下文管理器（Context Manager）

- **核心思想**：通过 `with` 语句管理资源的获取与释放。
- **在本项目中的体现**：`with ThreadPoolExecutor(max_workers=...) as executor:`（`orchestrator.py:269`）。
- **为什么有效**：保证线程池被正确关闭（即使异常），避免资源泄漏。
- **佐证**：[官方] concurrent.futures — Python Docs

### 原理 6：dataclass 优于 dict

- **核心思想**：使用类型化的 dataclass 代替裸 dict，提升可读性与类型安全。
- **在本项目中的体现**：`SubTask`、`ResearchState`、`TaskPlan` 等 11 个 dataclass。
- **为什么有效**：IDE 自动补全；类型检查工具可验证；字段含义清晰。
- **佐证**：[官方] dataclasses — Python Docs

### 原理 7：状态机管理生命周期

- **核心思想**：用有限状态机管理复杂对象的生命周期，避免状态混乱。
- **在本项目中的体现**：`ResearchState.status` 的 7 个状态（initialized/planning/researching/synthesizing/iterating/completed/failed）。
- **为什么有效**：状态转移显式、可追踪、可调试。
- **佐证**：[设计模式] State Pattern — GoF

### 原理 8：Pydantic 自动校验

- **核心思想**：通过类型注解 + 验证规则，自动完成数据校验。
- **在本项目中的体现**：所有 API 模型（`ResearchRequest` 等）。
- **为什么有效**：避免手动 `if x is None: raise` 模板代码；自动 OpenAPI 文档生成。
- **佐证**：[官方] Pydantic Models

### 原理 9：ThreadPoolExecutor 的 as_completed

- **核心思想**：用 `as_completed` 迭代器实现"先完成先取"。
- **在本项目中的体现**：`orchestrator.py:284` 的 `for future in as_completed(future_to_task)`。
- **为什么有效**：用户能实时看到最先完成的任务，而不必等待全部完成；提升长任务的体验。
- **佐证**：[官方] concurrent.futures — Python Docs

### 原理 10：分阶段事件机制

- **核心思想**：将流程拆分为多个阶段，每个阶段发出语义化事件，便于观测与回调。
- **在本项目中的体现**：30+ 进度事件（`decomposing/decomposed/dispatching/...`）。
- **为什么有效**：UI 可针对性渲染不同阶段的样式；日志可结构化；测试可断言特定事件。
