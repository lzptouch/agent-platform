# 04 接口文档

> **文档目的**：定义 Deep Research Agent 的所有对外接口（HTTP API、CLI、Python SDK、SSE 流式），便于调用方使用与集成。
>
> **目标读者**：调用方开发者、API 集成商、前端开发者。

---

## 1. 接口总览

| 接口形态 | 入口 | 适用场景 |
|----------|------|----------|
| Python SDK | `from deep_research import DeepResearchAgent` | 嵌入其他 Python 应用 |
| CLI | `python -m deep_research "..."` | 命令行快速体验 |
| FastAPI 服务 | `uvicorn deep_research.api:app` | 提供 Web 服务给前端 / 其他客户端 |
| SSE 流式 | `GET /research/{task_id}/stream` | 实时监听任务进度 |

## 2. Python SDK 接口

### 2.1 `DeepResearchAgent` 类

#### 构造函数

```python
from deep_research import DeepResearchAgent

agent = DeepResearchAgent(
    verbose: bool = True,           # 是否显示进度
    save_output: bool = True,       # 是否保存输出文件
    output_dir: str = None,         # 输出目录（None 则用 config 默认值）
)
```

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `verbose` | bool | `True` | 是否在控制台显示进度（图标、阶段信息） |
| `save_output` | bool | `True` | 是否将报告保存到文件 |
| `output_dir` | str | `None` | 输出目录，None 则用 `OUTPUT_CONFIG["output_dir"]`（默认 `./research_output`） |

#### 方法 1：`research(task, max_workers=None, callback=None)`

执行深度研究任务（同步）。

```python
def research(
    self,
    task: str,
    max_workers: int = None,
    callback: Callable[[str, dict], None] = None,
) -> str:
    """执行深度研究任务"""
```

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `task` | str | 必填 | 研究任务描述（自然语言） |
| `max_workers` | int | `None` | 最大并行 Worker 数，None 则用 `AGENT_CONFIG["max_workers"]`（默认 6） |
| `callback` | Callable | `None` | 自定义进度回调，签名 `(stage: str, data: dict) -> None` |

**返回**：`str` — 研究报告（Markdown 格式）

**异常**：
- 当底层 LLM / 搜索 API 全部失败时，抛出 `Exception`；
- 部分失败被捕获，错误信息会出现在报告中。

**示例**：

```python
from deep_research import DeepResearchAgent

agent = DeepResearchAgent(verbose=True)
report = agent.research(
    task="2024年中国新能源汽车市场分析报告",
    max_workers=6,
)
print(report)

# 自定义回调
def my_callback(stage: str, data: dict):
    if stage == "worker_completed":
        print(f"Worker 完成: {data.get('task_name')}")

agent = DeepResearchAgent(verbose=False)
report = agent.research("...", callback=my_callback)
```

#### 方法 2：`research_stream(task, max_workers=None)`

流式执行深度研究任务（生成器）。

```python
def research_stream(
    self,
    task: str,
    max_workers: int = None,
) -> Generator[Tuple[str, dict], None, None]:
    """流式执行深度研究任务"""
```

**Yields**：`tuple[str, dict]` — 每轮产出 `(stage, data)`：
- `("progress", {"stage": <内部阶段名>, "data": <进度数据>})` — 进度事件
- `("result", {"report": ..., "quality_score": ..., "status": ..., "duration": ...})` — 最终结果

**示例**：

```python
agent = DeepResearchAgent(verbose=False)
for event_type, event_data in agent.research_stream("研究任务"):
    if event_type == "progress":
        print(f"[{event_data['stage']}]", event_data['data'])
    elif event_type == "result":
        print("完成！")
        print("质量分:", event_data["quality_score"])
        print(report := event_data["report"])
```

### 2.2 回调函数的 `stage` 参数

完整阶段列表：

| 阶段名 | 含义 | data 字段示例 |
|--------|------|---------------|
| `decomposing` | 正在分析任务 | `{}` |
| `decomposed` | 任务拆解完成 | `{"subtask_count": N, "subtasks": [...]}` |
| `dispatching` | 正在分发 Workers | `{"worker_count": N, "query_type": "..."}` |
| `worker_started` | Worker 开始 | `{"task_id": ..., "task_name": ..., "priority": ...}` |
| `worker_completed` | Worker 完成 | `{"task_id": ..., "task_name": ..., "confidence_level": ...}` |
| `worker_failed` | Worker 失败 | `{"task_id": ..., "task_name": ..., "error": ...}` |
| `synthesizing` | 正在生成报告 | `{"result_count": N}` |
| `synthesized` | 报告生成完成 | `{"report_length": N}` |
| `quality_checking` | 正在质量检查 | `{}` |
| `quality_checked` | 质量检查完成 | `{"score": N, "needs_revision": bool, "revision_priority": "..."}` |
| `iteration_start` | 迭代开始 | `{"iteration": N, "max_iterations": M, "min_iterations": K}` |
| `iteration_evaluated` | 迭代评估完成 | `{"iteration": N, "score": N, "improvement": N, "passed": bool}` |
| `iteration_continue` | 继续优化 | `{"iteration": N, "reason": "..."}` |
| `iteration_end` | 迭代结束 | `{"iteration": N}` |
| `quality_passed` | 质量通过 | `{"iteration": N, "score": N}` |
| `analyzing_gaps` | 正在分析差距 | `{"iteration": N}` |
| `gaps_analyzed` | 差距分析完成 | `{"iteration": N, "gap_count": N, "task_count": N}` |
| `dispatching_supplementary` | 正在分发补充任务 | `{"task_count": N}` |
| `supplementary_worker_started` | 补充 Worker 开始 | `{"task_id": ..., "task_name": ...}` |
| `supplementary_worker_completed` | 补充 Worker 完成 | `{"task_id": ..., "task_name": ..., "success": bool}` |
| `supplementary_worker_failed` | 补充 Worker 失败 | `{"task_id": ..., "task_name": ..., "error": ...}` |
| `refining_report` | 正在修订报告 | `{}` |
| `report_refined` | 报告修订完成 | `{"new_length": N}` |
| `no_supplementary_tasks` | 无补充任务 | `{"iteration": N}` |
| `diminishing_returns_stop` | 收益递减终止 | `{"iteration": N, "score": N, "reasoning": ...}` |
| `gap_analysis_stop` | 差距分析建议停止 | `{"iteration": N, "reasoning": ...}` |
| `completed` | 任务完成 | `{"duration": N, "quality_score": N, "iterations": N, ...}` |
| `failed` | 任务失败 | `{"error": "..."}` |

## 3. CLI 接口

### 3.1 命令格式

```bash
python -m deep_research [TASK] [OPTIONS]
```

### 3.2 参数

| 参数 | 简写 | 类型 | 默认 | 说明 |
|------|------|------|------|------|
| `task` | - | str | 必填 | 研究任务描述（位置参数） |
| `--workers` | `-w` | int | None | 最大并行 Worker 数（默认 6） |
| `--output` | `-o` | str | None | 输出目录（默认 `./research_output`） |
| `--quiet` | `-q` | flag | False | 安静模式（不显示进度，仅输出报告） |
| `--no-save` | - | flag | False | 不保存输出文件 |

### 3.3 示例

```bash
# 基础用法
python -m deep_research "2024年电动汽车市场分析报告"

# 指定 Worker 数
python -m deep_research "人工智能在医疗领域的应用" --workers 4

# 指定输出目录
python -m deep_research "区块链技术发展趋势" --output ./reports

# 安静模式（管道友好）
python -m deep_research "医疗AI应用" --quiet > report.md

# 不保存文件
python -m deep_research "测试任务" --quiet --no-save
```

### 3.4 退出码

- `0`：研究成功完成
- `1`：研究失败（异常）
- `2`：参数错误（argparse 标准）

## 4. HTTP API 接口（FastAPI）

### 4.1 启动服务

```bash
# 安装依赖
pip install fastapi uvicorn

# 启动（开发模式）
uvicorn deep_research.api:app --reload --port 8000

# 启动（生产模式）
uvicorn deep_research.api:app --host 0.0.0.0 --port 8000 --workers 4

# 或通过 python -m
python -m deep_research.api
```

启动后访问：

- Swagger UI：`http://localhost:8000/docs`
- ReDoc：`http://localhost:8000/redoc`
- 健康检查：`http://localhost:8000/health`

### 4.2 API 总览

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 服务信息 |
| GET | `/health` | 健康检查 |
| POST | `/research` | 提交研究任务 |
| GET | `/research` | 列出所有任务 |
| GET | `/research/{task_id}` | 获取任务状态 |
| GET | `/research/{task_id}/result` | 获取任务结果 |
| GET | `/research/{task_id}/stream` | SSE 流式进度 |
| DELETE | `/research/{task_id}` | 删除任务 |

### 4.3 数据模型

#### `ResearchRequest`（POST /research 请求体）

```json
{
  "task": "2024年中国新能源汽车市场分析报告",
  "max_workers": 6,
  "max_iterations": 5,
  "quality_threshold": 80
}
```

| 字段 | 类型 | 必填 | 默认 | 范围 | 说明 |
|------|------|------|------|------|------|
| `task` | string | ✅ | - | min_length=1 | 研究任务描述 |
| `max_workers` | int \| null | ❌ | null (6) | 1~10 | 最大并行 Worker 数 |
| `max_iterations` | int \| null | ❌ | null (5) | 1~10 | 最大迭代次数 |
| `quality_threshold` | int \| null | ❌ | null (80) | 0~100 | 质量通过阈值 |

#### `ResearchResponse`（POST /research 响应）

```json
{
  "task_id": "acde739c",
  "status": "pending",
  "message": "研究任务已提交，正在启动...",
  "created_at": "2025-11-30T18:30:20.421756"
}
```

#### `TaskStatus`（GET /research/{task_id} 响应）

```json
{
  "task_id": "acde739c",
  "status": "running",
  "progress": {
    "current_stage": "iteration_evaluated",
    "iteration": 1,
    "score": 75,
    "last_update": "2025-11-30T18:30:25.123456"
  },
  "original_task": "2024年中国新能源汽车市场分析",
  "created_at": "2025-11-30T18:30:20.421756",
  "started_at": "2025-11-30T18:30:21.123456",
  "completed_at": null,
  "quality_score": null,
  "iteration_count": null,
  "error_message": null
}
```

#### `TaskResult`（GET /research/{task_id}/result 响应）

成功完成时：

```json
{
  "task_id": "acde739c",
  "status": "completed",
  "report": "# 2024年中国新能源汽车市场分析报告\n\n## 执行摘要\n...",
  "quality_score": 85,
  "iteration_count": 2,
  "duration": 245.6,
  "metadata": {
    "original_task": "2024年中国新能源汽车市场分析",
    "created_at": "2025-11-30T18:30:20.421756",
    "completed_at": "2025-11-30T18:34:25.987654"
  }
}
```

任务失败时：

```json
{
  "task_id": "acde739c",
  "status": "failed",
  "report": null,
  "metadata": {"error": "任务拆解失败: ..."}
}
```

### 4.4 POST /research（提交任务）

提交异步研究任务，立即返回 task_id。

**请求**：

```bash
curl -X POST "http://localhost:8000/research" \
  -H "Content-Type: application/json" \
  -d '{
    "task": "2024年中国新能源汽车市场分析",
    "max_workers": 6,
    "max_iterations": 5,
    "quality_threshold": 80
  }'
```

**响应**（200 OK）：

```json
{
  "task_id": "acde739c",
  "status": "pending",
  "message": "研究任务已提交，正在启动...",
  "created_at": "2025-11-30T18:30:20.421756"
}
```

**错误码**：
- `422`：请求体校验失败（缺字段、字段范围错误）

### 4.5 GET /research/{task_id}（查询状态）

**请求**：

```bash
curl "http://localhost:8000/research/acde739c"
```

**响应**（200 OK）：见 `TaskStatus`

**错误码**：
- `404`：任务不存在

### 4.6 GET /research/{task_id}/result（获取结果）

**请求**：

```bash
curl "http://localhost:8000/research/acde739c/result"
```

**响应**：
- `200 OK`（任务已完成或失败）：见 `TaskResult`
- `202 Accepted`：任务正在执行（pending 或 running）

**错误码**：
- `404`：任务不存在
- `202`：任务进行中

### 4.7 GET /research/{task_id}/stream（SSE 流式进度）

**请求**：

```bash
curl -N "http://localhost:8000/research/acde739c/stream"
```

**响应**（`Content-Type: text/event-stream`）：

```
data: {"stage": "decomposing", "data": {}, "timestamp": "..."}

data: {"stage": "decomposed", "data": {"subtask_count": 3}, "timestamp": "..."}

data: {"stage": "worker_completed", "data": {"task_name": "..."}, "timestamp": "..."}

...

data: {"stage": "final", "data": {"status": "completed", "quality_score": 85, ...}, "timestamp": "..."}
```

**事件格式**：每个事件为 `data: <JSON>\n\n`

**前端调用示例**：

```javascript
const eventSource = new EventSource('http://localhost:8000/research/acde739c/stream');

eventSource.onmessage = (event) => {
    const data = JSON.parse(event.data);
    console.log(`[${data.stage}]`, data.data);

    if (data.stage === 'final') {
        console.log('研究完成！');
        console.log('质量分:', data.data.quality_score);
        eventSource.close();
    }
};

eventSource.onerror = (error) => {
    console.error('SSE 连接错误:', error);
    eventSource.close();
};
```

## 5. 错误码与异常处理

| HTTP 状态码 | 含义 | 触发场景 |
|-------------|------|----------|
| `200 OK` | 成功 | 正常响应 |
| `202 Accepted` | 任务进行中 | 查询结果但任务未完成 |
| `400 Bad Request` | 错误请求 | 删除运行中任务 |
| `404 Not Found` | 资源不存在 | 任务 ID 不存在 |
| `422 Unprocessable Entity` | 校验失败 | 请求体字段缺失或范围越界 |
| `500 Internal Server Error` | 服务器错误 | 未知异常 |

API 错误响应格式：

```json
{"detail": "任务 acde739c 不存在"}
```

## 6. 鉴权与限流约定

**当前版本无鉴权与限流**（开发阶段）。

**生产部署建议**：

1. **JWT 鉴权**：在 FastAPI 中加入 `Depends(get_current_user)` 依赖。
2. **API Key 鉴权**：通过 Header `X-API-Key` 传递。
3. **限流**：使用 `slowapi` 库限制每 IP 每分钟请求数。
4. **CORS**：当前 `allow_origins=["*"]`（`api.py:204`）允许所有，生产应限制为白名单。

## 7. 输入输出示例

### 7.1 完整 Python 客户端示例

```python
import requests
import time

BASE = "http://localhost:8000"

# 1. 提交任务
resp = requests.post(f"{BASE}/research", json={
    "task": "2024年中国新能源汽车市场分析",
    "max_workers": 6,
})
task_id = resp.json()["task_id"]
print(f"任务 ID: {task_id}")

# 2. 轮询状态
while True:
    status_resp = requests.get(f"{BASE}/research/{task_id}")
    status = status_resp.json()["status"]
    print(f"状态: {status}")
    if status in ["completed", "failed"]:
        break
    time.sleep(5)

# 3. 获取结果
result_resp = requests.get(f"{BASE}/research/{task_id}/result")
result = result_resp.json()

if result["status"] == "completed":
    print(f"\n质量分: {result['quality_score']}")
    print(f"迭代次数: {result['iteration_count']}")
    print(f"耗时: {result['duration']:.1f}s")
    print("\n报告:\n", result["report"])
else:
    print(f"任务失败: {result.get('metadata', {}).get('error')}")
```

### 7.2 完整 SSE 监听示例

```python
import httpx

BASE = "http://localhost:8000"

# 1. 提交任务
resp = httpx.post(f"{BASE}/research", json={"task": "AI Agent 发展趋势"})
task_id = resp.json()["task_id"]

# 2. SSE 监听
with httpx.stream("GET", f"{BASE}/research/{task_id}/stream") as response:
    for line in response.iter_lines():
        if line.startswith("data: "):
            import json
            event = json.loads(line[6:])
            print(f"[{event['stage']}]", event.get('data', {}))
            if event['stage'] == 'final':
                print("\n最终结果:", event['data'])
                break
```

## 8. 本章设计原理与依据

### 原理 1：RESTful API 设计原则

- **核心思想**：使用 HTTP 动词（GET/POST/DELETE）表达操作，URL 表达资源。
- **在本项目中的体现**：`/research` 表示"研究任务"集合；`/research/{id}` 表示单个任务；`POST` 创建、`GET` 读取、`DELETE` 删除。
- **为什么有效**：符合行业惯例，降低 API 学习成本。

### 原理 2：异步任务模式（Long Polling / SSE）

- **核心思想**：长耗时任务不阻塞 HTTP 请求，立即返回 task_id，客户端轮询或订阅进度。
- **在本项目中的体现**：`POST /research` 立即返回 `task_id`，客户端通过 `GET /research/{id}` 轮询或 `/stream` 订阅。
- **为什么有效**：HTTP 请求有超时限制（通常 30s~2min），研究任务常耗时数分钟，必须异步化。

### 原理 3：SSE 协议选型

- **核心思想**：用 SSE（HTTP 单向流）推送进度，浏览器/客户端原生支持。
- **在本项目中的体现**：`GET /research/{task_id}/stream` 用 `text/event-stream` 推送。
- **为什么有效**：HTTP 友好、自动重连、文本协议便于调试。

### 原理 4：HTTP 状态码语义化

- **核心思想**：用状态码表达结果类别，而非全部 200 + body 表达。
- **在本项目中的体现**：
  - `200` 正常响应
  - `202` 任务进行中（GET /result 但未完成）
  - `404` 资源不存在
  - `400` 删除运行中任务（不允许的操作）
- **为什么有效**：客户端可基于状态码做不同的处理逻辑。

### 原理 5：Pydantic 数据校验

- **核心思想**：所有 API 输入输出都用 Pydantic 模型定义，自动校验 + 生成文档。
- **在本项目中的体现**：`ResearchRequest` / `ResearchResponse` / `TaskStatus` / `TaskResult`。
- **为什么有效**：自动 OpenAPI schema 生成；类型安全；字段约束（`min_length`, `ge`, `le`）。

### 原理 6：CLI argparse 最佳实践

- **核心思想**：位置参数放必填项，可选参数放命名参数；提供 `--help` 与示例。
- **在本项目中的体现**：`python -m deep_research TASK --workers N --output DIR`。
- **为什么有效**：符合 Unix 哲学；可管道组合（`--quiet` + stdout 重定向）。

### 原理 7：依赖注入让 API 与核心逻辑解耦

- **核心思想**：HTTP 层仅做"参数解析 + 调用核心逻辑 + 返回结果"。
- **在本项目中的体现**：`run_research_task` 调用 `Orchestrator.run`，不直接操作 LLM。
- **为什么有效**：核心逻辑可在 CLI/SDK/API 共用，避免重复。
