## 3. 逐模块详解

### 3.1 模块 1: `src/config/config.yaml`

**职责**：集中管理 API Key、模型名、Prompt 模板。

**对外接口**：

```yaml
serper_api_key: ""     # str
openai_api_key: ""     # str
model_name: "gpt-4o"   # str
template: |            # multi-line string ...
```

**本模块设计原理与依据**：

- **原理：配置与代码分离**
  - 核心思想：可变参数不应硬编码，应在配置文件中。
  - 本项目中：API Key、模型、Prompt 模板全部外置；改 Prompt 无需改代码。
  - 为什么有效：安全（Key 不入代码仓库）；灵活（不同环境用不同配置）。

### 3.2 模块 2: `src/serper_service.py`

**职责**：封装 Serper.dev API；支持中英文地域自动判断。

**关键类/函数**：
- `SerperClient.__init__`（`serper_service.py:8`）：加载 config，构造 Headers
- `SerperClient.serper(query)`（`serper_service.py:21`）：POST Serper API
- `SerperClient._contains_chinese(query)`（`serper_service.py:35`）：正则判断中文
- `SerperClient.extract_components(response)`（`serper_service.py:40`）：从 organic 抽取字段

**依赖**：`requests`、`yaml`、`re`、`os`

**本模块设计原理与依据**：

- **原理：自动国际化（i18n Auto-detection）**
  - 核心思想：根据查询语言自动切换 API 参数，提升结果质量。
  - 本项目中：中文查询 → `gl=cn, hl=zh-cn`（`serper_service.py:27`）。
  - 为什么有效：让 Google 返回针对目标地域优化的结果。

- **原理：哨兵值与异常透传**
  - 核心思想：API 调用失败让异常自然向上抛出，由上层决定如何处理。
  - 本项目中：`requests.request(...)` 不包 try/except，直接返回 `response.json()` 或抛异常。

### 3.3 模块 3: `src/web_crawler.py`

**职责**：单 URL HTTP 抓取 + BeautifulSoup 主内容提取。

**关键类/函数**：
- `WebScraper.__init__(user_agent='macOS')`（`web_crawler.py:6`）：根据 UA 选 Headers
- `WebScraper._get_headers(ua)`（`web_crawler.py:10`）：构造 Headers
- `WebScraper.get_webpage_html(url)`（`web_crawler.py:31`）：GET 请求，8s 超时
- `WebScraper.convert_html_to_soup(html)`（`web_crawler.py:48`）：BeautifulSoup + lxml
- `WebScraper.extract_main_content(soup, rule)`（`web_crawler.py:53`）：提取 h[1-6]+p（rule=1 加 div）
- `WebScraper.scrape_url(url, rule)`（`web_crawler.py:64`）：公开入口

**依赖**：`requests`、`bs4`、`re`

**本模块设计原理与依据**：

- **原理：两段式 / 兜底策略**
  - 核心思想：先快路径（rule=0），失败再升级到慢路径（rule=1）。
  - 本项目中：`fetch_web_content.py:26-28` 调用，先 rule=0，< 800 字符升级到 rule=1。
  - 为什么有效：平衡速度与覆盖率。

- **原理：User-Agent 伪装**
  - 核心思想：模拟真实浏览器 UA，避免被网站屏蔽。
  - 本项目中：macOS/Windows 两套 UA（`web_crawler.py:13-29`）。

### 3.4 模块 4: `src/fetch_web_content.py`

**职责**：搜索 + 并发抓取的胶水层。

**关键类/函数**：
- `WebContentFetcher.__init__(query)`（`fetch_web_content.py:7`）：初始化共享列表 + Lock
- `WebContentFetcher._web_crawler_thread(thread_id, urls)`（`fetch_web_content.py:15`）：单 URL Thread 函数
- `WebContentFetcher._serper_launcher()`（`fetch_web_content.py:43`）：Serper 调用
- `WebContentFetcher._crawl_threads_launcher(url_list)`（`fetch_web_content.py:49`）：N 线程并发
- `WebContentFetcher.fetch()`（`fetch_web_content.py:60`）：主入口

**依赖**：`threading`、`time`、`SerperClient`、`WebScraper`

**本模块设计原理与依据**：

- **原理：胶水层（Glue Layer）**
  - 核心思想：把多个独立模块组合成完整业务流程。
  - 本项目中：`WebContentFetcher` 不做实质性工作，只把 Serper + 多线程爬虫粘合。
  - 为什么有效：单一职责；每模块可独立测试。

- **原理：Thread-Safe 共享状态**
  - 核心思想：多线程访问共享列表时必须用 Lock 保护。
  - 本项目中：`web_contents_lock`、`error_urls_lock`（`fetch_web_content.py:12-13`）。
  - 为什么有效：避免竞态条件；保证结果一致性。

### 3.5 模块 5: `src/retrieval.py`

**职责**：将网页内容切分、向量化、存入 Chroma，召回 top-K。

**关键类/函数**：
- `EmbeddingRetriever.__init__`（`retrieval.py:22`）：加载 config + 初始化 text_splitter
- `EmbeddingRetriever.retrievel_embeddings(contents, links, query)`（`retrieval.py:36`）：核心方法

**依赖**：`langchain.text_splitter`、`chromadb`、`sentence_transformers`、`yaml`、`os`

**本模块设计原理与依据**：

- **原理：元数据（Metadata）反向追溯**
  - 核心思想：向量化时把 URL 作为 metadata 一并存入，后续检索时能反向追溯到原文。
  - 本项目中：`metadatas = [{'url': link} for link in link_list]`（`retrieval.py:38`）。
  - 为什么有效：让"向量相似"与"原文 URL"建立显式关联。

- **原理：chunk_overlap=0 简单优先**
  - 核心思想：演示项目优先简单，无重叠切分；生产可改 overlap=200 等。
  - 本项目中：`chunk_overlap=0`（`retrieval.py:31`）。

### 3.6 模块 6: `src/llm_answer.py`

**职责**：组装 Prompt + ChatOpenAI 流式生成。

**关键类/函数**：
- `GPTAnswer.__init__`（`llm_answer.py:14`）：加载 config
- `GPTAnswer._format_reference(docs, link_list)`（`llm_answer.py:22`）：Document → 字符串
- `GPTAnswer._rearrange_index(indices)`（`llm_answer.py:35`）：索引去重
- `GPTAnswer.get_answer(query, docs, ...)`（`llm_answer.py:47`）：ChatOpenAI 流式

**依赖**：`langchain.chat_models`、`langchain.prompts`、`langchain.schema`、`yaml`、`os`

**本模块设计原理与依据**：

- **原理：PromptTemplate 模板化**
  - 核心思想：Prompt 用占位符 `{var}` 表达，由 `PromptTemplate.format()` 动态填充。
  - 本项目中：`PromptTemplate(input_variables=["profile", "context_str", "language", "query", "format"], template=template)`（`llm_answer.py:52-55`）。
  - 为什么有效：模板与数据分离；便于 A/B 测试不同 prompt。

- **原理：流式回调**
  - 核心思想：通过 callback 流式输出，避免阻塞。
  - 本项目中：`StreamingStdOutCallbackHandler`（`llm_answer.py:49`）。

### 3.7 模块 7: `src/locate_reference.py`

**职责**：从 LLM 答案中解析 `[n]` 引用，反向匹配 serper 元数据。

**关键类/函数**：
- `ReferenceLocator.__init__(answer, response)`（`locate_reference.py:5`）
- `ReferenceLocator.locate_source()`（`locate_reference.py:9`）：主入口
- `ReferenceLocator._handle_sentences_in_answer(content)`（`locate_reference.py:31`）：找含 `[n]` 的句子
- `ReferenceLocator._match_references(refs, sents)`（`locate_reference.py:46`）：匹配 URL + quoted sentence
- `ReferenceLocator._match_web_info(sents)`（`locate_reference.py:71`）：反向查 serper 元数据

**依赖**：`re`、`json`

**本模块设计原理与依据**：

- **原理：三段式正则解析**
  - 核心思想：把复杂的"引用+元数据匹配"拆成三个串行正则，逐步收敛。
  - 本项目中：`split → _handle_sentences → _match_references → _match_web_info`。
  - 为什么有效：每步独立可测；正则可调；不影响其他步骤。

- **原理：哨兵值 -1 表示失败**
  - 核心思想：解析失败时返回 -1，而非抛异常。
  - 本项目中：`if len(splitted_answer) != 2: return -1`（`locate_reference.py:17`）。

## 6. 整体模块划分原理与依据

### 原理 1：单一职责原则（Single Responsibility Principle）

- **核心思想**：每个模块只负责一个明确的职责。
- **本项目体现**：
  - `serper_service.py` 只做"调用搜索 API"
  - `web_crawler.py` 只做"抓单 URL"
  - `fetch_web_content.py` 只做"协调多线程"
  - `retrieval.py` 只做"向量化 + 召回"
  - `llm_answer.py` 只做"组装 Prompt + 调用 LLM"
  - `locate_reference.py` 只做"解析引用"
- **为什么有效**：变更影响范围可控；模块可独立测试。

### 原理 2：依赖倒置原则（Dependency Inversion Principle）

- **核心思想**：高层模块不依赖低层模块的具体实现。
- **本项目体现**：`WebContentFetcher` 通过 import 调用 `SerperClient` 与 `WebScraper`，但接口稳定，替换实现无需改协调层。
- **为什么有效**：替换底层实现无需改业务逻辑。

### 原理 3：开闭原则（Open-Closed Principle）

- **核心思想**：对扩展开放，对修改关闭。
- **本项目体现**：
  - 新增嵌入模型只需改 `retrieval.py:43` 一行
  - 新增 LLM 只需改 `config.yaml` 一行
  - 新增 Tool 只需在 Notebook 加一个函数
- **为什么有效**：新增功能不引入回归。

### 原理 4：层次化架构（Layered Architecture）

- **核心思想**：系统按层次组织，上层依赖下层，下层不依赖上层。
- **本项目体现**：
  - 搜索层（Serper）→ 抓取层（Crawler）→ 协调层（Fetcher）→ 检索层（Retriever）→ 生成层（GPT/Locate）
- **为什么有效**：层间职责清晰，避免循环依赖。

### 原理 5：关注点分离（Separation of Concerns）

- **核心思想**：将不同关注点分离到不同模块。
- **本项目体现**：
  - 配置（yaml）关注"运行时可调参数"
  - 协调（fetcher）关注"业务流程"
  - 检索（retrieval）关注"向量相似度"
  - 生成（GPT/Locate）关注"LLM 输出"
- **为什么有效**：修改一个关注点不影响其他。

### 原理 6：胶水层模式（Glue Layer Pattern）

- **核心思想**：复杂系统需要一个薄薄的协调层把独立模块粘起来。
- **本项目体现**：`WebContentFetcher` 作为胶水层，组合 Serper + WebScraper；`llm_answer.py` 的 `__main__` 作为最终胶水，组合 fetch + retrieve + generate + locate。
- **为什么有效**：每个底层模块可独立测试，组合后形成完整业务流程。

### 原理 7：配置驱动（Configuration-Driven）

- **核心思想**：通过外部配置文件驱动系统行为，便于多环境适配。
- **本项目体现**：`config.yaml` 集中 API Key、模型名、Prompt 模板。
- **为什么有效**：同一套代码可在不同环境（开发/生产）使用不同配置。

### 原理 8：Notebook 优于脚本的场景（Notebook-First）

- **核心思想**：教学/实验/论文复现项目，Notebook 比 .py 脚本更直观。
- **本项目体现**：`RAG(Milvus+BGE).ipynb` 用 cell 展示完整 Agent 流程，每个 cell 独立可执行；Pipeline `.py` 用于集成。
- **为什么有效**：教学友好（边讲解边演示）；实验友好（独立 cell）；复现友好（一键顺序执行）。

### 原理 9：元数据驱动检索（Metadata-Driven Retrieval）

- **核心思想**：向量与元数据（URL、title 等）一起存储，召回时一并返回。
- **本项目体现**：Pipeline 版 `metadatas = [{'url': link}]`（`retrieval.py:38`）；Notebook 用 `output_fields=["text"]` 控制返回字段。
- **为什么有效**：让"语义相似"和"原文追溯"建立显式关联。

### 原理 10：胶水代码与核心代码分离

- **核心思想**：核心逻辑应独立可测，胶水代码只负责"把核心逻辑连起来"。
- **本项目体现**：`SerperClient.serper()`、`EmbeddingRetriever.retrievel_embeddings()` 等核心方法无业务耦合；`WebContentFetcher.fetch()`、`llm_answer.py` 的 `__main__` 是胶水。
- **为什么有效**：核心代码可单独单元测试；胶水代码变动不影响核心。
