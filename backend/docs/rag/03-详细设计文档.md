## 3. 关键算法/流程详解

### 3.1 多线程抓取（`fetch_web_content.py:49-58`）

```python
def _crawl_threads_launcher(self, url_list):
    threads = []
    for i in range(len(url_list)):
        thread = threading.Thread(target=self._web_crawler_thread, args=(i, url_list))
        threads.append(thread)
        thread.start()
    for thread in threads:
        thread.join()
```

**关键设计点**：
1. **`args=(i, url_list)`** 让每个 Thread 知道自己是第几个、拿到 URL 列表；
2. **`thread.start()` 后立即继续**，所有线程并发；
3. **`thread.join()` 阻塞**，直到全部完成才返回；
4. **共享列表**用 `threading.Lock` 保护（`fetch_web_content.py:12-13`）。

### 3.2 两段式抓取（`fetch_web_content.py:26-28` + `web_crawler.py:53-62`）

```python
# 第一段：仅 h1-6 + p（精准但可能漏内容）
content = scraper.scrape_url(url, 0)
# 若内容 < 800 字符，升级到 rule=1（含 div，更激进）
if 0 < len(content) < 800:
    content = scraper.scrape_url(url, 1)
```

**设计权衡**：rule=0 快但可能漏掉 div 包裹的内容；rule=1 慢但覆盖广。两段式实现"快路径优先 + 慢路径兜底"。

### 3.3 Chroma 向量化与召回（`retrieval.py:36-55`）

```python
metadatas = [{'url': link} for link in link_list]
texts = self.text_splitter.create_documents(contents_list, metadatas=metadatas)
embedding = SentenceTransformerEmbeddings(model_name='.../all-MiniLM-L6-v2')

retriever = db.as_retriever(search_kwargs={"k": min(self.TOP_K, len(texts))})
```

**关键设计**：
- `metadatas=[{url}]` 把 URL 作为元数据，后续引用定位时可反向追溯；
- `chunk_overlap=0`：无重叠，简单高效；
- `min(TOP_K, len(texts))`：若 texts 少于 20，避免 Chroma 报错。

### 3.4 Milvus Hybrid Search（Notebook cell 22）

```python
def hybrid_search(col, query_dense, query_sparse, sparse_weight=1.0, dense_weight=1.0, limit=10):
    sparse_req = AnnSearchRequest(
        data=[query_sparse], anns_field="sparse_vector",
        param={"metric_type": "IP"}, limit=limit
    )
    dense_req = AnnSearchRequest(
        data=[query_dense], anns_field="dense_vector",
        param={"metric_type": "IP"}, limit=limit
    )
    rerank = WeightedRanker(sparse_weight, dense_weight)
    res = col.hybrid_search([sparse_req, dense_req], rerank=rerank, limit=limit, output_fields=["text"])[0]
    return [hit.get("text") for hit in res]
```

**关键设计**：
- **两次 AnnSearchRequest**：分别对 `sparse_vector` 和 `dense_vector` 字段做最近邻搜索；
- **WeightedRanker**：加权重排融合两路结果，sparse=0.7, dense=1.0（Notebook cell 22 调用处）；
- **`metric_type="IP"`**：内积（Inner Product），BGE-M3 的稠密向量与稀疏向量都用 IP 距离。

### 3.5 引用解析三段式（`locate_reference.py:9-29`）

```python
def locate_source(self):
    # 第 1 段：按 "\nReferences:" 切分正文与引用块
    splitted_answer = self.gpt_answer.split("\nReferences:")
    if len(splitted_answer) != 2:
        return -1
    answer_content = splitted_answer[0]
    answer_references = splitted_answer[1]

    # 第 2 段：从正文找含 [n] 的句子
    sentences_with_index = self._handle_sentences_in_answer(answer_content)

    # 第 3 段：从引用块匹配 [n] URL: Quoted sentence:
    sentences_with_references = self._match_references(answer_references, sentences_with_index)

    # 第 4 段：反向查 serper_response 的 titles/snippets
    reference_cards = self._match_web_info(sentences_with_references)
    return reference_cards
```

**关键设计**：
- **`\nReferences:`** 作为正文/引用块分隔符，由 Prompt 强制约束（`config.yaml:10`）；
- **`-1` 异常返回**：LLM 未输出引用块时直接失败（避免静默错误）；
- **正则三层**：`(?<=[\n\.\!]).*?\[\d+\]`（句子）、`\[\d+\]`（索引）、`https://[^\n]+`（URL）。

## 5. 关键代码片段逐行解读

### 5.1 中英文地域自动判断（`serper_service.py:23-27`）

```python
serper_settings = {"q": query, "page": 2}
if self._contains_chinese(query):
    serper_settings.update({"gl": "cn", "hl": "zh-cn",})
```

**解读**：
- `page=2`：Serper 单页返回 10 条 organic 结果；
- `gl=cn`：地理位置（Geolocation）= 中国，让 Google 优先返回中文站点；
- `hl=zh-cn`：界面语言（Host Language）= 简体中文；
- 中英文参数差异化是 Serper 相比 Bing/Tavily 的一个亮点。

### 5.2 内容长度阈值过滤（`fetch_web_content.py:30`）

```python
if len(content) > 300:
    with self.web_contents_lock:
        self.web_contents.append({"url": url, "content": content})
```

**解读**：300 字符是经验阈值。低于此值的多为导航页、错误页、JS 渲染页面，加入反而污染检索。

### 5.3 RecursiveCharacterTextSplitter（`retrieval.py:29-32`）

```python
self.text_splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=0)
```

**解读**：LangChain 的 `RecursiveCharacterTextSplitter` 按 `["\n\n", "\n", " ", ""]` 递归切分，优先保留段落完整性。`chunk_size=1000` 适配 MiniLM 的 max_seq_length（512 token ≈ 2000 字符，留足余量）。

### 5.4 ChatOpenAI 流式回调（`llm_answer.py:49`）

```python
llm = ChatOpenAI(
```

### 5.5 Prompt 模板中的引用约定（`config.yaml:4-17`）

## 10. 本章设计原理与依据

### 原理 1：依赖注入（Dependency Injection）

- **核心思想**：通过构造函数注入依赖，便于替换与测试。
- **在本项目中的体现**：`WebContentFetcher(query)`、`EmbeddingRetriever()` 加载 config 后初始化；`SentenceTransformerEmbeddings(model_name=...)` 注入模型。
- **为什么有效**：便于替换嵌入模型（`retrieval.py:43`）与 API Key（`config.yaml`）。

### 原理 2：工厂模式（Factory Pattern）

- **核心思想**：通过工厂方法创建对象，将"创建逻辑"与"使用逻辑"解耦。
- **在本项目中的体现**：`WebScraper(user_agent=...)` 工厂方法根据参数返回不同 Headers（`web_crawler.py:10-29`）。

### 原理 3：上下文管理器（Context Manager）

- **核心思想**：通过 `with` 语句管理资源的获取与释放。
- **在本项目中的体现**：未直接使用 `with`，但 `thread.join()` 配合 `threading.Lock` 达到类似效果（`fetch_web_content.py:31`）。

### 原理 4：观察者模式（Observer Pattern）

- **核心思想**：被观察对象状态变化时通知所有观察者。
- **在本项目中的体现**：`StreamingStdOutCallbackHandler` 作为回调（`llm_answer.py:49`）。

### 原理 5：组合优于继承

- **核心思想**：通过组合而非继承复用功能。
- **在本项目中的体现**：`WebContentFetcher` 组合 `SerperClient` 与 `WebScraper`（`fetch_web_content.py:3-4`）。

### 原理 6：配置与代码分离

- **核心思想**：可变参数不应硬编码，应在配置文件中。
- **在本项目中的体现**：`config.yaml` 集中 API Key、模型名、Prompt 模板。

### 原理 7：长内容切分（RecursiveCharacterTextSplitter）

- **核心思想**：长文档必须切分为适合嵌入模型的 chunk，且优先保留段落完整性。
- **在本项目中的体现**：`retrieval.py:29` 的 `RecursiveCharacterTextSplitter(chunk_size=1000)`。
- **为什么有效**：LangChain 官方推荐（`https://python.langchain.com/docs/modules/data_connection/document_transformers/text_splitters/recursive_text_splitter`）。

### 原理 8：ThreadPool vs ProcessPool 选择

- **核心思想**：I/O 密集型用线程，CPU 密集型用进程。
- **在本项目中的体现**：`threading.Thread` 用于 HTTP 抓取（`fetch_web_content.py:53`）。
- **为什么有效**：避免引入 multiprocessing 的 pickle 复杂度。

### 原理 9：流式回调机制（Callback Pattern）

- **核心思想**：通过回调将核心逻辑与 UI/日志展示解耦。
- **在本项目中的体现**：`StreamingStdOutCallbackHandler`（`llm_answer.py:49`）、Notebook 中的 `for chunk in completion`（cell 4327）。

### 原理 10：两段式 / 兜底策略（Graceful Degradation）

- **核心思想**：先尝试快速方案，失败再升级到慢速但更可靠的方案。
- **在本项目中的体现**：抓取 `rule=0 → rule=1`（`fetch_web_content.py:26-28`）；Hybrid Search `dense + sparse` 互补；引用解析三层降级。
