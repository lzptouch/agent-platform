# 03_xiaohongshu-mcp — 系统架构文档

## 1. 项目定位

03_xiaohongshu-mcp 是一个**真实业务级别的 MCP Server**：
- 单一文件 1495 行 Python
- 暴露 7 个 LLM 可调用的工具
- 通过 Playwright 持久化浏览器操作小红书 Web 版
- 把"AI 决策"和"机械执行"用 MCP + Function Calling 分离

## 2. 整体架构

```
┌──────────────────────────────────────────────────────────┐
│  MCP Client (Claude Desktop / Cursor)                     │
│  ──────────────────────────────────────────                │
│  - 发送 user prompt + tools/list                          │
│  - 接收 tool_calls / 整合 tool 响应                       │
└────────────────────┬─────────────────────────────────────┘
                     │ stdio JSON-RPC
                     ▼
┌──────────────────────────────────────────────────────────┐
│  xiaohongshu_mcp.py (FastMCP Server)                      │
│  ┌─────────────────────────────────────────────────────┐  │
│  │  全局状态：browser_context / main_page / is_logged_in│  │
│  └─────────────────────────────────────────────────────┘  │
│  ┌────────────────┐  ┌────────────────┐  ┌─────────────┐ │
│  │ login          │  │ search_notes   │  │get_content  │ │
│  │ get_comments   │  │ analyze_note   │  │post_comment │ │
│  └────────────────┘  └────────────────┘  └─────────────┘ │
└────────────────────┬─────────────────────────────────────┘
                     │ Playwright (async)
                     ▼
┌──────────────────────────────────────────────────────────┐
│  Chromium (持久化 user_data_dir=browser_data/)            │
│  https://www.xiaohongshu.com                              │
└──────────────────────────────────────────────────────────┘
```

## 4. 调用链时序

```
1. Client: tools/list → Server 返回 7 个工具
2. Client: tools/call(name="login")
   Server: launch_persistent_context → 等待扫码 → 返回 "登录成功"
3. Client: tools/call(name="search_notes", keywords="AI")
   Server: 2 种备选选择器 → 返回 top 5 笔记
4. Client: tools/call(name="analyze_note", url=...)
   Server: get_note_content + 关键词分类 → 返回分析结果
5. Client: LLM 生成评论内容
6. Client: tools/call(name="post_comment", url=..., comment="...")
   Server: 3 种发送方式 → 返回 "已成功发布"
```

## 5. 本章设计原理与依据

### 5.1 Playwright Persistent Context 实现登录态持久化
- **核心思想**：用磁盘上的 `user_data_dir` 复用 cookies / localStorage
- **本项目中体现**：`launch_persistent_context(user_data_dir=BROWSER_DATA_DIR, headless=False)`（`xiaohongshu_mcp.py:62-67`）
- **为什么有效**：小红书强制扫码登录，不可能每次自动化都人工扫码
- **佐证来源**：[官方] Playwright Persistent Context 文档

### 5.2 MCP stdio Transport 让 LLM 直接操控本地浏览器
- **核心思想**：本地浏览器进程天然适合 stdio 通信
- **本项目中体现**：`xiaohongshu_mcp.py:1496` `mcp.run(transport='stdio')`
- **为什么有效**：零部署；浏览器与 MCP Server 同进程生命周期
- **佐证来源**：[官方] MCP stdio 规范

### 5.3 Multi-Channel Extraction（DOM Fallback 链）抗结构漂移
- **核心思想**：每个字段准备多个备选选择器，依次尝试，任一成功即可
- **本项目中体现**：标题 3 种、正文 5 种、评论 5 种 + JS 兜底
- **为什么有效**：小红书前端频繁改版（`data-v-xxx` hash 几乎每周变）；fallback 链显著延长程序寿命
- **佐证来源**：[博客] Web Scraping Robustness Patterns

### 5.4 Function Calling 把"AI 决策"与"机械执行"解耦
- **核心思想**：把"分析笔记"与"发布评论"拆成两个 Tool，强制 LLM 介入内容生成
- **本项目中体现**：`post_smart_comment` 不发评论，而是返回分析 + 指南（`xiaohongshu_mcp.py:1225-1266`），由 LLM 生成 `comment` 后再调用 `post_comment`
- **为什么有效**：硬编码评论模板会被小红书风控识别；让 LLM 实时生成更自然、更难被检测
- **佐证来源**：[论文] ReAct / Toolformer 论文

### 5.5 Async Programming + 串行 await 串接多步 DOM 操作
- **核心思想**：用 asyncio 把多个 `await page.goto()` 写成线性代码
- **本项目中体现**：整个文件 `async def` 工具函数 + `await main_page.query_selector(...)`
- **为什么有效**：Playwright Python SDK 原生 async；可与 FastMCP 异步装饰器无缝对接
- **佐证来源**：[官方] Playwright Async API 文档

### 5.6 JSON Schema inputSchema 让 LLM 准确知道每个工具参数
- **核心思想**：MCP `inputSchema` 自动从 Python 函数签名推导
- **本项目中体现**：`async def search_notes(keywords: str, limit: int = 5)` 自动变 JSON Schema
- **为什么有效**：LLM 通过 schema 学习"参数名 + 类型 + 是否必填 + 默认值"，调用准确率显著提升
- **佐证来源**：[官方] JSON Schema Draft 7

### 5.7 错误页识别 + 多通道重试保证健壮性
- **核心思想**：先检测错误页（"当前笔记暂时无法浏览"等），再开始抓数据；每个动作失败都有兜底
- **本项目中体现**：每个 Tool 开头都用 `error_page` JS 检测；发送评论用 3 种 fallback
- **为什么有效**：小红书有反爬限流、登录态过期、笔记删除等多种异常路径
- **佐证来源**：[博客] Web Scraping Reliability 工程实践

### 5.8 Module-level 全局变量做"跨 Tool 状态共享"
- **核心思想**：用 `browser_context = None` 等全局变量在多次 `@mcp.tool()` 调用间共享资源
- **本项目中体现**：`xiaohongshu_mcp.py:22-24` 的 `browser_context / main_page / is_logged_in`
- **为什么有效**：浏览器启动耗时 10+ 秒；用全局变量避免每次 Tool 调用都重新 launch
- **佐证来源**：[博客] Python 模块全局状态管理实践
