# 02_mcp-with-llm — 系统架构文档

## 1. 项目定位

02_mcp-with-llm 演示**"LLM 自主调用 MCP 工具"**的完整链路：
- LLM 通过 OpenAI Function Calling 协议发出 tool_call
- 客户端把 tool_call 翻译成 MCP `tools/call`
- 工具结果回写到 messages，让 LLM 做最终整合

核心创新点：**MCP Server Discovery + 动态系统提示词生成**。

## 3. 关键模块拆解

### 3.1 MCP Server（`mcp_server.py`）
- `SearchTool` 类封装 Serper.dev API（`mcp_server.py:20-60`）
- 三个 `@mcp.tool()` 装饰的工具：`web_search`（`mcp_server.py:62-117`）、`news_search`（`mcp_server.py:119-188`）、`weather_search`（`mcp_server.py:190-233`）
- 通过 `gl="cn"`、`hl="zh-cn"` 针对中文地理/语言优化（`mcp_server.py:40-41`）

### 3.2 LLM 客户端（`llm_client.py`）
- `LLMWithMCP` 类承担三大职责：
  1. **MCP 连接**：`initialize_mcp` 启动子进程并拉取工具列表（`llm_client.py:45-126`）
  2. **Schema 转换**：MCP `inputSchema` → OpenAI `tools` 字段（`llm_client.py:71-83`）
  3. **对话主循环**：两阶段 chat completion（`llm_client.py:296-374`）

### 3.3 简化演示（`simple_demo.py`）
- 单工具 `web_search` + 详细日志输出（`simple_demo.py:32-50`）
- 通过 `print_json` 工具方法展示 LLM 原始响应（`simple_demo.py:52-61`）

### 3.4 重构版（`llm_client_ali_v2.py`）
- 改用 **Streamable HTTP Transport** 连接高德地图官方 MCP（`llm_client_ali_v2.py:23, 53`）
- `MAX_TOOL_CALLS = 10`（`llm_client_ali_v2.py:77`）—— 循环最多 10 次工具调用，防止死循环

## 4. 关键调用链

### 4.1 MCP Server Discovery
```
ClientSession.initialize()           # 握手 capabilities
  → session.list_tools()             # 拉取所有 tool 定义
    → for tool in tools:
        openai_tool = {
          "type": "function",
          "function": {
            "name": tool.name,
            "description": tool.description,
            "parameters": tool.inputSchema
          }
        }
```

### 4.2 双阶段对话
```
[Round 1] chat.completions.create(messages, tools=...)
  ← assistant_message.tool_calls = [{"function":{"name":"web_search",...}}]

[执行工具] for tool_call in tool_calls:
  result = await session.call_tool(name, args)
  messages.append({"role":"tool","tool_call_id":..., "content": result})

[Round 2] chat.completions.create(messages)  # 不传 tools
  ← assistant_message.content  ← 最终回答
```

## 5. 本章设计原理与依据

### 5.1 MCP Server Discovery 实现零硬编码
- **核心思想**：工具元数据存放在 Server 端，客户端通过 `tools/list` 自动拉取
- **本项目中体现**：`llm_client.py:60-61` 调用 `await session.list_tools()`
- **为什么有效**：新增工具无需修改客户端代码，符合 Open/Closed 原则；多客户端共享同一 Server 时不会出现工具定义漂移
- **佐证来源**：[官方] MCP Protocol Specification "Tools"

### 5.2 OpenAI Function Calling 是 LLM 工具调用的工业标准
- **核心思想**：把工具的 `name + description + parameters (JSON Schema)` 注入到 chat 请求
- **本项目中体现**：`llm_client.py:71-83` 把 MCP `inputSchema` 转 OpenAI 格式
- **为什么有效**：Qwen/Claude/GPT 三大主流模型都遵循 OpenAI Function Calling 协议；同一套 schema 可跨厂商复用
- **佐证来源**：[官方] OpenAI Function Calling 文档

### 5.3 DashScope OpenAI 兼容接口降低接入门槛
- **核心思想**：阿里云百炼通过 `base_url=https://dashscope.aliyuncs.com/compatible-mode/v1` 暴露与 OpenAI 完全兼容的接口
- **本项目中体现**：`llm_client.py:31-34` 直接用 OpenAI SDK 调用 Qwen
- **为什么有效**：国内开发者无需学习新协议，本地 OpenAI 代码可直接平迁
- **佐证来源**：[官方] 阿里云百炼 OpenAI 兼容文档

### 5.4 stdio Transport 适合本地一对一双进程
- **核心思想**：客户端拉起 Server 子进程，通过 stdin/stdout 交换 JSON-RPC
- **本项目中体现**：`llm_client.py:49-57` 用 `StdioServerParameters` 启动 Python 子进程
- **为什么有效**：无需服务发现、无端口管理、单测最简；本项目刻意不引入 HTTP 是为了演示 stdio 的完整链路
- **佐证来源**：[官方] MCP stdio transport 规范

### 5.5 异步 I/O 让"工具调用 + LLM 调用"无缝串联
- **核心思想**：用 asyncio 把多次网络调用写成同步式代码
- **本项目中体现**：搜索工具（`mcp_server.py:44-57`）、MCP 客户端（`llm_client.py:56-58, 211-213`）全部 async
- **为什么有效**：单线程高并发；避免回调地狱；与 OpenAI 异步 SDK 配合最自然
- **佐证来源**：[官方] Python asyncio 官方文档

### 5.6 Serper.dev API 提供高质量 Google 搜索结果
- **核心思想**：第三方聚合 Google SERP 的 API，免去爬虫
- **本项目中体现**：通过 `X-API-KEY` header 直连 `google.serper.dev/search` 与 `/news`
- **为什么有效**：免费额度 2500 次/账号，足够 demo 使用；返回结构化 JSON，免去解析 HTML
- **佐证来源**：[官方] Serper.dev 官方文档

### 5.7 Function Calling 双阶段流程避免死循环
- **核心思想**：第一轮让模型决策工具，第二轮去掉 `tools` 参数迫使模型整合答案
- **本项目中体现**：`llm_client.py:364-369` 第二次调用故意不传 `tools`
- **为什么有效**：避免 LLM 在第二轮再次发起 tool_call 形成无限递归
- **佐证来源**：[论文] ReAct: Synergizing Reasoning and Acting in Language Models

### 5.8 Streamable HTTP Transport 让 MCP Server 可以远程托管
- **核心思想**：用 HTTP POST + SSE 替代 stdio，适合云端 MCP Server
- **本项目中体现**：`llm_client_ali_v2.py:23, 56-69` 用 `streamablehttp_client` 连接 `https://mcp.amap.com/mcp?key=...`
- **为什么有效**：高德地图官方 MCP 是云端 SaaS，必须用 HTTP；支持多客户端并发访问
- **佐证来源**：[官方] MCP Streamable HTTP Transport 规范

### 5.9 优雅降级保证 demo 始终可跑
- **核心思想**：MCP 不可用时回退到直连 API
- **本项目中体现**：`llm_client.py:117-126` 捕获 MCP 异常后使用 `_get_default_tools()`；`simulate_mcp_call` 直连 Serper
- **为什么有效**：让 demo 在 MCP Server 未启动时仍能完整运行
- **佐证来源**：[博客] 防御性编程最佳实践
