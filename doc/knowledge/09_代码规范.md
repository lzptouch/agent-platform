## 二、类型注解（现状：已遵循）

```python
def snapshot_before_write(
    run_id: str,
    workspace_root: Path,
    path: Path,
    tool: str,
) -> dict[str, Any]:
    """写前快照；失败不阻断写入。"""
```

- **公开函数必须有完整注解**（参数与返回值）；
- 协议/接口用 `Protocol`（如 `MCPEndpoint` 的结构、`CallUsage` 的计量结构）；
- 联合类型用 `X | None`（Python ≥3.10）；不用 `Optional[...]`；
- 泛型容器带参数：`list[dict]`、`dict[str, Any]`（不用裸 `list` / `dict`）。

## 四、错误处理（现状：已统一）

S1 起**统一错误体**，取代了早期的「自定义异常 + 异常处理器」方案：

```python
# app/core/errors.py（实际实现）
class ErrorCode:            # 错误码常量表
class AppError(Exception):  # 带 code / message / request_id 的基类
def new_request_id() -> str
def error_body(...) -> dict          # {code, message, detail, request_id}
def error_response(...) -> JSONResponse
def http_exception_response(exc) -> JSONResponse
```

**规则**：

1. **对外错误一律走统一错误体**：`{code, message, detail, request_id}`，响应头带 `X-Request-ID`；
2. 业务异常继承 `AppError` 并给出**稳定的 `code`**（前端可依赖，不依赖文案）；
3. 领域内异常可直接继承内置异常（如 `PluginError(RuntimeError)`、`SkillSpecError(ValueError)`），
   但**在边界处**（API 层）必须转成统一错误体；
4. **不吞异常**：旁路写账本/审计失败只告警不阻断主流程，但必须 `logger.warning` 记原因；
5. 内部模块**不 import HTTP 概念**（服务层不抛 `HTTPException`）。

**禁止**：在服务层直接 `raise HTTPException`（除 API 层）。

## 五、注释与文档字符串

| 场景 | 要求 |
|---|---|
| 模块 | 顶部模块级 docstring：职责 + 关键约定（不是复述文件名） |
| 类 | 一句话职责 + 关键字段语义/约束（如「名称唯一且创建后不可改名」） |
| 函数 | 公开函数写 docstring，说明**参数含义、返回、副作用、失败行为** |
| 特殊约定 | 在 docstring 里显式写「为什么这样」（设计决策）——如 `execute_sync` 为何自持槽位 |
| 行内注释 | 只写「为什么」，不写「是什么」 |

**例子**（当前代码的写法）：

```python
def _fire(self, task_id: str, slot_override: str | None = None) -> None:
    """按槽位触发一次任务。

    幂等：同 task 同槽位只跑一次（唯一约束在 DB 层）。
    无人值守：定时触发的 ask 直接降级为 deny（不挂起等待审批）。
    """
```

## 七、桌面壳（Electron）规范（现状）

| 项 | 规则 |
|---|---|
| 主进程 | `apps/desktop/src/main/`；**preload 只暴露白名单通道**，不暴露 `ipcRenderer` |
| 通道名 | 集中在 `apps/desktop/src/shared/protocol.ts`（含环境变量名） |
| 路径 | 一律经 `apps/desktop/src/main/paths.ts` 解析（打包态 / 开发态分支集中在一处） |
| 退出 | `before-quit` 停 sidecar；`taskkill /T /F` 杀进程树（Windows） |
| 依赖 | **运行时依赖必须在 `dependencies`**（放 devDependencies → asar 缺失 → 主进程启动即崩） |
| 注释 | 写「为什么」——如 `electron-updater` 为何不启用（无证书与发布通道） |

## 八、测试规范（现状）

| 项 | 规则 |
|---|---|
| 目录 | 后端 `apps/server/tests/`；前端与组件同目录 `*.spec.ts`；端到端 `tests/{web,desktop,common}` |
| 命名 | `test_<主题>.py` / `describe('中文语义')` |
| 阶段契约 | 每阶段一个 `test_s<n>_*.py`，冻结该阶段的判定语义 |
| 隔离 | 临时目录用 `tmp_path`；**不得写真实 `data/`**；插件安装只进用户数据目录 |
| 真实模型 | 只允许 L4（`tests/test_s5_live_qwen.py`），**无密钥自动跳过** |
| 断言 | 断言**行为**（状态、事件、字段），不断言文案 |
