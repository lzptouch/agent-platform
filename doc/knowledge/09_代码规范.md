# 代码规范

> **依据代码**：`apps/server/`、`apps/ui/`、`apps/desktop/`（2026-11-01 复核重写）
> 本篇是仓库级编码约定——新代码按此执行；与 `../analysis/` 的事实描述互补。

## 一、工程形态

- 三个 npm 工程：`apps/server`（Node ESM，`"type":"module"`）、`apps/ui`（Vite）、
  `apps/desktop`（tsc 双 tsconfig：main / preload）；
- TypeScript 全量；后端 `tsconfig`：`module=ESNext / target=ES2022 /
  moduleResolution=Bundler`；
- 每个工程独立 `npm run typecheck / test / build`；**提交前至少跑对应工程的
  typecheck + test**。

## 二、后端约定（`apps/server/src/`）

### 2.1 分层与依赖方向

```
http/routes ──→ domain/* ──→ db/{client,schema}
     │              └──→ shared/{config,errors,logger,llm}
mcp/、workers/ 只依赖 shared/ 与 domain/ 的类型
```

- **routes 只做事**：参数归一化、调用 domain、抛 `HttpError`；不写业务逻辑；
- **domain 不碰 HTTP**（不 import fastify 类型做业务签名）；
- **shared 不依赖任何上游**（config/errors/logger/llm 是叶子）。

### 2.2 ESM 与导入

- 相对导入**必须带 `.js` 后缀**（ESM Node 解析编译产物）；
- CJS 包（如 rrule v2）取默认导出再解构，并注释原因；
- 循环依赖用**注入**打破（例：`registerUsageProvider(aggregateRun)`，
  `http/context.ts:58`）。

### 2.3 错误与日志

- 业务错误抛 `HttpError(status, detail)` 或 `AppError(code, ...)`；
  **禁止**在路由里手写错误 JSON——统一走 `setErrorHandler`（`http/app.ts:91`）；
- 日志用 `getLogger("域.模块")`；DEBUG 级会被采样（0.2），关键路径用 INFO+；
- 工具执行结果**不抛穿**（返回 `{ok:false, error}` 回喂模型）。

### 2.4 数据层

- 表结构改动 = 改 `db/baseline-sql.ts` + `db/schema.ts` + `contract/tables.sql`
  三处同步（契约闸门校验）；
- 写操作走 `transaction()`（自带写锁退避）；幂等优先用**唯一约束**而非先查后插；
- 时间一律 `utcNow()`（UTC ISO8601 TEXT）；JSON 列用 `toJson/fromJson`。

### 2.5 配置

- 新配置项进 `shared/config.ts` 的 Zod schema（带默认值）；
- **阈值常量在 `LIMITS` 集中**（不散落业务代码）；
- 能力缺失用派生位（`has_api_key` 等）+ 明确报错，**禁止静默降级**。

## 三、前端约定（`apps/ui/src/`）

- `<script setup lang="ts">`；组件名多词（`ResultPanel`）；
- API 一律经 `api/` 封装层（96 个函数），**组件里不直接 fetch**；
- SSE 只走 `api/sse.ts` 的 `runSSE` / `streamAgent` / `streamResearchWithReconnect`；
- 用户输入渲染必须过 DOMPurify；错误提示用 `ApiError` 的归一文案；
- 测试为 `*.spec.ts` 与源码同目录（vitest）。

## 四、桌面壳约定（`apps/desktop/src/`）

- 主进程每个模块一个职责（backend/window/tray/…），纯逻辑拆纯函数便于单测
  （如 `parseSseBuffer`、`navigation` 守卫）；
- IPC 一律登记在 `main/ipc.ts`；preload 不直接暴露 `ipcRenderer`；
- 与后端的协议常量**只在** `shared/protocol.ts` 定义（前后两端共用）；
- 测试 `*.test.ts` 同目录（vitest，62 例）。

## 五、契约与文档纪律

1. **契约冻结产物**（`contract/`）是基准：改端点/事件/表 → 先改契约 → 改代码 →
   跑契约闸门（`apps/server` 的 vitest 5 文件）；
2. **数字口径**：文档里的数字必须与 `analysis/00` §5 常量表一致；
   `python3 tests/scripts/check_doc_numbers.py` 会校验；
3. **当前实现文档**（analysis/knowledge/design 大部分）不得引用已删除的实现路径
   （`tests/scripts/check_doc_paths.py`）；
4. 文档改动后跑：`python3 tests/scripts/check_doc_consistency.py` +
   `check_doc_paths.py` + `check_doc_numbers.py`；
5. 注释写**为什么**（决策与踩坑），不写「这段代码做什么」的复述；
   文件头注释标注「契约对齐/来源」与关键不变式。

## 六、Git 与发布

- 安装包发布走 `deploy/README.md` 手册（rebuild-native → build-desktop → verify）；
- `.env` 不入库（`.gitignore`）；密钥只走环境变量或桌面设置向导。
