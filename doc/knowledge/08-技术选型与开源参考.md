# 技术选型与开源参考

> **依据代码**：`apps/server/package.json`、`apps/ui/package.json`、`apps/desktop/package.json`、`tests/e2e/package.json`（2026-11-01 复核重写）
> 本篇只列**当前代码实际使用**的依赖与选型理由；历史选型（Python 栈）已随单运行时改造退场。

## 一、后端（`apps/server`，Node + TypeScript ESM）

| 依赖 | 用途 | 选型理由 |
|---|---|---|
| **fastify ^5** | HTTP 框架 | 高性能、schema 校验内建、钩子模型清晰；SSE 用裸 `reply.raw` 写，绕过压缩缓冲 |
| **@fastify/multipart** | 上传解析 | `req.parts()` 流式逐 part 校验 |
| **better-sqlite3 ^11** | SQLite 驱动 | **同步 API** = 事务推理简单（无异步交错）；`nativeBinding` 选项支持双 ABI 显式加载 |
| **zod ^3** | 配置校验 | 82 字段 Settings schema；校验失败打印问题 + 默认值兜底（不阻断桌面首启） |
| **openai ^4** | LLM 客户端 | OpenAI 兼容协议一家通吃（DashScope/DeepSeek/OpenAI 三个 provider 同构） |
| **croner ^9** | cron 触发器 | 带时区的 cron 解析与下次触发计算；纯 JS 无原生依赖 |
| **rrule ^2** | RFC 5545 循环规则 | `RRule.fromString().after()` 语义标准；CJS 包在 ESM 下取默认导出（`scheduler/service.ts:23`） |
| **js-yaml ^4** | SKILL.md frontmatter | YAML 子集解析 |
| **adm-zip** | Skill zip 导入 | 内存解包 + 逐 entry 遍历（配合路径穿越拦截） |
| **cheerio / pdf-lib / pdfjs-dist** | HTML 解析 / PDF | 依赖在列；pdfjs 接入待办（当前 PDF 抽取为极简实现，见 `../analysis/02` §3.1） |
| **pino** | 日志 | 依赖在列；当前日志为自研 JSON 行 + 轮转（`shared/logger.ts`） |
| **@modelcontextprotocol/sdk** | MCP | 依赖在列；外部 Server 协议腿未接线（`../analysis/02` §2.4） |
| **vitest** | 测试 | 69 例 / 5 文件（契约 / db / domain / packaging / response-shape） |

## 六、选型总原则

1. **单一运行时**：一切能在 Node 里解决的不引第二运行时（Python 仅作可选沙箱轨道）；
2. **零服务依赖**：桌面安装包不带数据库/缓存/队列服务（SQLite + 文件 + 内存索引）；
3. **原生依赖最小化**：唯一的原生模块是 better-sqlite3，且为它建了双 ABI 通道；
4. **协议兼容优先于框架锁定**：LLM 走 OpenAI 兼容协议，换 provider 改 base_url 即可。
