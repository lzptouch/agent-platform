# 批次 01 · 执行边界与输入限制

> **优先级**：P1 ｜ **规模**：2 人日 ｜ **依赖**：无 ｜ **台账**：`../analysis/12` D-36、SEC-3
> **状态**：✅ 已完成（2026-10-28）——交付实况见 [`../design/08`](../design/08-实现交付记录.md) §15
> **回滚**：`EXEC_RESOURCE_LIMITS=false` 退回旧执行行为；`UPLOAD_MAX_FILE_BYTES` 调大 / `UPLOAD_ALLOWED_EXTENSIONS` 置空即放开上传

## 一、目标

把「能跑但没有边界」的两处补上硬边界：
1. **代码执行**（`execute_bash` / `execute_python`）无资源上限、无隔离；
2. **文件上传**无大小与类型限制。

现状（事实）：`backend/app/services/code_executor.py` 只有命令黑名单 + 180 s 超时；
`backend/app/api/v1/files.py` 直接 `shutil.copyfileobj` 落盘。
`../analysis/10` §3 把沙箱能力标为 `level=policy_only`（诚实标注，没有原生沙箱）。

## 二、范围

### 2.1 代码执行资源限制（WP-1）

| 步 | 动作 | 完成判据 |
|---|---|---|
| 1.1.1 | 子进程加 `resource` 限制（POSIX：`RLIMIT_CPU`/`RLIMIT_AS`/`RLIMIT_NOFILE`/`RLIMIT_FSIZE`）；Windows 用 Job Object 或退化为「工作目录 + 路径白名单」 | 写一个死循环脚本被 CPU/内存上限终止 |
| 1.1.2 | 工作目录白名单：子进程 `cwd` 强制落在工作区内；`..` 逃逸在**启动前**拒绝（不依赖运行期拦截） | 逃逸路径在启动前被拒并留痕 |
| 1.1.3 | 网络出口开关（默认关）：能解析出「需要联网」的调用形态时拒绝或降级（可用宿主代理白名单） | 联网调用被明确拒绝 |
| 1.1.4 | 子进程输出上限（stdout/stderr 各自截断，超出即杀） | 超量输出不会撑爆内存 |
| 1.1.5 | 审计：`sandbox` 审计事件记录每次限制命中（哪个限制、为什么） | 审计可按 run 还原 |

### 2.2 上传限制（WP-2）

| 步 | 动作 | 完成判据 |
|---|---|---|
| 1.2.1 | 单文件大小上限（默认 50 MB）+ 单请求总量上限 | 超限返回 413 + 统一错误体 |
| 1.2.2 | 扩展名/ MIME 白名单（图片、文档、文本、代码；可执行文件拒绝） | 传 `.exe` 被拒并说明原因 |
| 1.2.3 | 落盘前用流式读取计数（不 `read()` 全量） | 大文件不会占满内存 |
| 1.2.4 | 前端上传前预检大小与类型，给出可读提示 | 前端先拦一道 |

## 三、不做

- 不做真正的容器/虚拟机隔离（单机版不引入 Docker 依赖）；
- 不做 Windows Job Object 的完整实现（先落「工作目录 + 路径白名单 + 超时 + 输出上限」的可用组合，Windows 资源限制留后续）。

## 四、验收标准

1. 新增 `backend/tests/test_s5_boundaries.py`（或并入 `test_s2_security.py`）：
   - 超大文件上传 → 413；
   - 禁止类型上传 → 4xx + 原因；
   - 子进程逃逸工作目录 → 启动前拒绝；
   - 子进程死循环 → 被时间/资源上限终止（用例带超时保护）。
2. 回归：后端 pytest ≥ 326 passed；e2e ≥ 39 passed。
3. 文档：`../analysis/12` 的 D-36 / SEC-3 关闭；`../analysis/10` 的沙箱等级说明同步更新（若实现了部分限制，如实写明仍非原生沙箱）。

## 五、回滚

| 变更 | 回滚 |
|---|---|
| 资源限制 | 配置开关 `exec_resource_limits=true` 置 false 即退回现状 |
| 上传限制 | 上限配置调大；类型白名单置空 |

## 六、交付实况（2026-10-28）

### 6.1 WP-1 代码执行资源限制

| 步 | 落地位置 | 说明 |
|---|---|---|
| 1.1.1 | `backend/app/services/exec/limits.py`（`run_with_limits` + POSIX 引导脚本） | CPU / 地址空间 / 句柄 / 单文件大小四项 rlimit；**Windows 无 `resource` → 退化为超时 + 输出上限**（已在返回值 `limit_hit` 如实标注） |
| 1.1.2 | `limits.detect_escape` + `code_executor._preflight` | 含 `..` 的路径 token 解析后越界 → **启动前**拒绝（不创建任何进程） |
| 1.1.3 | `limits.detect_network_usage` + `exec_network_enabled` | 识别 HTTP 客户端 / curl / wget / pip install / git clone 等形态；网络出口**默认关** |
| 1.1.4 | `limits._drain` + 轮询看门狗 | stdout / stderr 各自上限（默认 64KB），超出即杀并置 `limit_hit="output"` |
| 1.1.5 | `code_executor._audit` | 每次限制命中写 JSONL 审计（按 run 可还原） |

> **实现取舍**（与计划的偏差，已如实记录）：不用 `preexec_fn`（与线程不兼容，后端是多线程的），
> 改为 POSIX 上用引导脚本 `python -c <引导> <limits-json> <argv...>` 设置 rlimit 后 `os.execvp` 原地替换；
> 超时杀进程组（`start_new_session=True` + `killpg`）。

### 6.2 WP-2 上传限制

| 步 | 落地位置 | 说明 |
|---|---|---|
| 1.2.1 | `backend/app/core/uploads.py` + `api/v1/files.py` | 单文件 50MB / 单请求 100MB；超限 413 + 统一错误体（新增 `E_TOO_LARGE`） |
| 1.2.2 | `core/uploads.py` | 扩展名白名单（图片/文档/文本/代码）+ 可执行文件禁止清单 + MIME 校验；可执行 → 415 |
| 1.2.3 | `api/v1/files.py` | 1MB 分块流式落盘 + 计数；超限即删半成品文件 |
| 1.2.4 | `frontend/.../src/api/upload-policy.ts` + `FilesView.vue` | 前端预检大小与类型，给出可读中文提示；文件选择器 `accept` 同步收窄 |

> 顺带把 `POST /skills/import` 也纳入单文件上限（原先 `await file.read()` 整体读入内存）。

### 6.4 仍未覆盖（如实标注）

- **无容器 / 虚拟机级隔离**：`sandbox.level` 仍为 `policy_only`，`GET /permissions/sandbox` 的诚实标注不变；
- **Windows 无 rlimit**：CPU / 内存硬上限只在 POSIX 生效，Windows 靠墙钟超时 + 输出上限兜底；
- **网络出口开关是「形态识别」而非强制拦截**：能识别常见联网调用形态即拒绝，但无法阻止
  通过间接方式（写文件后由别的进程执行）联网；
- **上传白名单不含压缩包**：`.zip` 被拒（Skill 包走独立的 `/skills/import` 端点，不受此白名单约束）。
