## 一、目标

三处**结构上没做完**的收敛（功能可用，但形态与设计不一致）：

1. **调度服务仍是单文件**（`scheduler_service.py` 约 500 行），设计要求拆成 `rrule` / `idempotency` / `lease` / `delivery` 四模块、编排层只做编排（S7 已建 `services/scheduler/`，但 `rrule`/`delivery` 尚未被主链路完全接管）；
2. **MCP 配置仍是单级注册表**，设计要求「用户级 `~/.workbuddy/mcp.json` + 项目级 `<项目>/.workbuddy/mcp.json`，项目级覆盖」；
3. **MCP 的 SSE / HTTP 传输是协议映射骨架**，真实 SSE 流需要 `mcp` SDK 的服务端支持。

现状（事实）：S7 已交付 `services/scheduler/rrule.py`（RRULE 解析 + 槽位展开）与 `delivery.py`（三通道投递），
并已在 `_fire` 里接入无人值守降级与投递；`services/chains/mcp/transport.py` 提供了三种传输与连接复用。
**但**主链路的 cron 槽位计算、租约、幂等仍在 `scheduler_service.py` 里，RRULE 尚未接到调度注册上。
