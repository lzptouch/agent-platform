# 批次 04 · 流式与深链路补齐

> **优先级**：P2 ｜ **规模**：4 人日 ｜ **依赖**：批次 03（部分） ｜ **台账**：`../analysis/12` S-03-01、S-07-03、S-03-05、S-03-09、S-11-06、前端-S6-08
> **状态**：未开始

## 一、目标

补齐四条**长链路**的体验与可靠性缺口：

1. **LLM 非流式**：首 token 延迟 = 完整响应时间（`S-03-01`）；
2. **Deep Research 无 checkpoint**：进程重启后任务整体标 failed（`S-07-03`）；
3. **上下文事件过重**：`system_prompt` 事件把完整 prompt 下发前端（`S-03-05`）；
4. **恢复靠内存**：`resume_after_approval` 用 daemon 线程，进程退出即丢（`S-03-09`）、`tasks.json` 全量读写（`S-11-06`）、前端重订阅无退避上限（`前端-S6-08`）。

现状（事实）：S5 已引入上下文预算与九段压缩，`context_compressed` 事件已带前后 token；
但**模型调用本身仍是一次性返回**，长文本要等完整响应。

## 二、范围

| 步 | 动作 | 完成判据 |
|---|---|---|
| 4.1 | 模型改 `stream=True`：把增量 token 转成 `model_delta` 事件，前端逐字渲染；非流式路径（`run/sync`）保持不变 | 首个 token 延迟显著低于完整响应时间（有指标可比） |
| 4.2 | 流式下的工具调用：工具调用仍走完整 JSON 块（不变），只有文本增量 | 工具调用链路不受影响 |
| 4.3 | `system_prompt` 事件改为**按需下发**：默认只发摘要（长度 + 头尾），前端点开再拉全文（新增端点或复用 `run_events`） | 事件体积不随工具数线性增长 |
| 4.4 | Deep Research checkpoint：每个阶段结束落盘进度（阶段、输入摘要、产出指针），重启后**从最后阶段续跑** | 重启后续跑而非整体 failed |
| 4.5 | `resume_after_approval` 改**持久化任务**：审批恢复写成 `runs` 状态 + 启动时扫描可恢复的 run | 进程重启后待审批的 run 仍可恢复 |
| 4.6 | `tasks.json` 改增量追加（或以 `runs` 账本为主、文件为缓存） | 任务数增长时 IO 不再全量放大 |
| 4.7 | 前端 `streamResearchWithReconnect` 加**指数退避 + 最大重试次数**（或改为续传游标） | 断网恢复不再无限重连 |

## 三、验收标准

1. 新增 `backend/tests/test_s6_streaming.py`（6 例）：流式增量、工具调用不回归、上下文事件体积、checkpoint 续跑、审批恢复持久化、任务存储增量。
2. 前端新增单测：断流重连退避（`views/ResearchView` 或 `api/sse.spec.ts`）。
3. 回归：后端 pytest ≥ 326 passed；前端 vitest ≥ 64 passed；e2e ≥ 39 passed。
4. 文档：`../analysis/03`（事件协议）补新事件与体积口径；`../analysis/07`（Research 链路）补 checkpoint 语义。

## 四、回滚

| 变更 | 回滚 |
|---|---|
| 模型流式 | 配置开关 `llm_stream=false` 退回一次性返回 |
| 上下文事件精简 | 配置 `system_prompt_full=true` 退回全量下发 |
| checkpoint | 关闭即退回原行为 |
| 持久化恢复 | 恢复逻辑加开关 |
