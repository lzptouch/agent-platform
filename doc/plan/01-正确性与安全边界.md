## 一、为什么这批排第一

| # | 缺陷 | 危害 | 为什么必须最先修 |
| --- | --- | --- | --- |
| R-05 | Web 形态完全无鉴权 | 任何能访问该端口的人可读写全部会话、文件、权限规则 | 单机部署可接受，但**必须显式标注并提供开关**，不能默认裸奔 |
| R-06 | `save-as` 的 `dest` 无路径限制 | 可写任意绝对路径（绕过工作区约束） | 与 `revert` 端点的策略**不对称**——同一份代码里两套安全标准 |
| R-01 | `allow_dangerous_tools` 恒失效 | 用户显式允许危险工具仍被拒绝 | 配置项「可写可查可输出」但**永远不生效** = 误导性配置 |
| R-02 | Web Research 回答生成必然失败 | 整条 Web 链不可用 | 用 OpenAI 的 key 打 DeepSeek 端点 |
| R-03 | Serper 固定 `page=2` | 静默丢失搜索结果第一页 | 用户无感知地拿到不完整结果 |

> **共同点**：这 5 条**全部是「看起来实现了、实际不生效」或「默认不安全」**——
> 正是本轮复核的核心发现类型。P2 会修更多同类问题，但 P2 会大改执行链路；
> **在可能错的安全基线上继续叠功能是危险的**，所以 P1 必须先行。
>
> **二次复核订正（2026-10-30）**：原 **R-04**（误判为「新装库无内置权限规则」，曾列 P0）经全新库实测迁移链证伪——
> 内置规则**确实**被写入（28 条 builtin）。真问题是 **`0002` 与 `0004` 重复插入 → 8 条规则出现两次**（数据质量）。
> 已从 P0 表移除，作为 **P1-03**（数据质量项，降 P2）保留在本批。

### P1-01 · Web 形态最小鉴权　<sub>来源：`design/09` **R-05** ／ `analysis/12` **SEC-1b**</sub>

| 要素 | 内容 |
| --- | --- |
| **现象** | Web 形态下 `/api/v1/**` 全部端点无任何鉴权；API 层 **0 个鉴权型 `Depends`**（81 处 `Depends` 全是服务获取器） |
| **根因** | S1 的鉴权只做在桌面态（`main.py:152-165` 的 `desktop_guard` 中间件），Web 形态假设「单机自用」 |
| **整改** | ① 新增 `AGENT_API_KEY` 环境变量；② 在 `main.py` 注册 API Key 中间件（**与 `desktop_guard` 并存**，桌面态仍用会话令牌）；③ 未配置时**显式告警**（不默认开启，避免打断单机用户） |
| **验收断言** | ① 配置 `AGENT_API_KEY` 后，无 Key 请求 `/api/v1/health` → **401**；② 带正确 Key → **200**；③ 未配置 → **200** 且启动日志含「Web 形态未启用鉴权」告警 |
| **测试用例 ID** | `SEC-01`（Web 宿主 401 断言）、`SEC-01` |
| **回归风险** | 中间件顺序；桌面态与 Web 态的判定分支；SSE 端点的 Header 传递 |
| **回滚** | 中间件由 `AGENT_API_KEY` 是否为空控制，删环境变量即回到旧行为 |

> **不做**：不做用户体系 / RBAC / JWT——那是账号产品，不是单机工具的必需项。

### P1-02 · `save-as` 路径约束　<sub>来源：`design/09` **R-06** ／ `analysis/12` **SEC-4**</sub>

| 要素 | 内容 |
| --- | --- |
| **现象** | `POST /runs/{run_id}/artifacts/{artifact_id}/save-as` 的 `dest` 直接进 `shutil.copy2`，**无任何路径校验** |
| **根因** | 该端点在 S3 实现时只关注「能存出去」，未复用 `revert` 端点的权限判定模式 |
| **整改** | ① `dest` 走 `PermissionService.enforce(PermissionRequest(tool="write_file", path=dest))`；② 被拒 → **403 `E_PERMISSION`**（与 `revert` 一致）；③ 桌面态受 `allowed_roots` 约束，Web 态按权限规则判定 |
| **验收断言** | ① `dest` 指向工作区外且无对应 allow 规则 → **403 + `code="E_PERMISSION"`**；② 指向工作区内 → **200**；③ 审计 JSONL 记录该次判定 |
| **测试用例 ID** | `SEC-WS-04` |
| **回归风险** | 用户「存到桌面」等常见操作可能开始被拒——需确认默认规则下工作区外路径的决策是 `ask` 而非 `deny` |
| **回滚** | 单端点改动 |

### P1-03 · 内置权限规则去重与写入收敛　<sub>来源：`design/09` **R-04** ／ `analysis/12` **D-48**（2026-10-30 由 P0 降 P2，前提经实测订正）</sub>

> ⚠️ **前提订正**：本项首版的前提是「新装库无内置规则」，经全新库实测迁移链**证伪**——
> `0004` 的内置规则 INSERT 在条件块之外、无条件执行，新装库**确有** 28 条 builtin 规则。
> 因此本项从「补写缺失规则」改为「**消除重复 + 收敛写入位置**」。

| 要素 | 内容 |
| --- | --- |
| **现象** | 全新库上 `permission_rules` 有 **28 条 builtin 规则，其中 8 条出现两次**（16 行是 8 对重复） |
| **根因** | ① `0002_desktop.py:101-116` 与 `0004_security.py:117-157` **都**写入同一批内置规则；② 两处都写 `workspace_id=NULL`，而 SQLite 唯一约束 `(scope,pattern,workspace_id)` 对 NULL **不去重**（NULL≠NULL）；③ `0002` 用**普通 `INSERT`**（非 `INSERT OR IGNORE`）→ 重复行照插 |
| **整改** | ① 把内置规则写入从两个迁移中**收敛到启动时 upsert**（`PermissionService.ensure_builtin_rules()`，幂等，按 `(scope,pattern,workspace_id)` 去重）；② 迁移里只保留 schema 变更，删除数据写入；③ 提供一次性清理：删除新装库上的重复 builtin 行（保留每组优先级最高的一条）；④ （低优先）`0001_init` 改为只建基线表，消除 `create_all` 的 downgrade 语义不可靠 |
| **验收断言** | ① 全新库启动后 `(scope,pattern)` 分组**无 COUNT>1 的重复**；② `origin="builtin"` 条数 = 规则清单条数（无重复、无缺失）；③ 重复启动**不**产生新增（upsert 幂等）；④ 老库升级后重复被清理；⑤ `GET /permissions/rules` 返回的规则列表无重复 |
| **测试用例 ID** | `SEC-RULE-01`（规则存在且无重复）、`DB-MIGRATE-01`（迁移链冒烟）、`DB-MIGRATE-02`（重复清理幂等） |
| **回归风险** | 老库已存在的重复行的清理顺序；`hit_count` 在重复行上的归属 |
| **回滚** | 启动 upsert 幂等，删除该调用即回到旧行为（重复行保留，不影响判定结果） |

### P1-04 · `allow_dangerous_tools` 开关生效　<sub>来源：`design/09` **R-01** ／ `analysis/12` **D-29R**</sub>

| 要素 | 内容 |
| --- | --- |
| **现象** | 定时任务显式设置 `allow_dangerous_tools=true`，危险工具仍被拒绝 |
| **根因** | `scheduler_service.py:525` 的 `dangerous_tools_context.set(False)` 是**全仓唯一**写入点且恒为 `False`；`security/permissions.py:352-356` 读该 ContextVar 决定是否放行 |
| **整改** | ① 调度执行路径按任务行写入真实值 `dangerous_tools_context.set(bool(row.allow_dangerous_tools))`；② `finally` 复位为 `False`；③ 补一条审计事件「因 allow_dangerous_tools 放行」 |
| **验收断言** | ① `allow_dangerous_tools=false` + 危险工具 → **deny**（不变）；② `=true` → **allow**，审计 JSONL 有对应记录；③ 交互路径**恒为 deny**（ContextVar 默认 `False`） |
| **测试用例 ID** | `SEC-DANGER-01` |
| **回归风险** | 交互与调度共用 `enforce()`——必须确保 ContextVar **只在调度上下文**被置位（用 ContextVar 而非全局变量） |
| **回滚** | 单行赋值改动 |
