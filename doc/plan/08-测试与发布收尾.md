# 批次 08 · 测试与发布收尾

> **优先级**：P3 ｜ **规模**：3 人日 ｜ **依赖**：批次 06（体积与签名）｜ **来源**：`../design/14-测试与发布策略.md` §九 + `../design/09` 状态列
> **状态**：未开始

## 一、目标

把**已具备但没接线**的测试与发布能力补齐，让「每次发版可重复、可验证、可回退」。

现状（事实）：
- 四层测试已全绿（后端 325 / 前端 64 / 壳 27 / e2e 39），**但没有 CI 接线**——每次靠人跑；
- L0 契约脚本已存在（`doc/plan/_gate/check_endpoint_table.py`，端点表 ↔ OpenAPI **118/118 一致**），**未进门禁**；
- 迁移的 `downgrade()` 都实现了，**从未实跑演练**；
- 冒烟清单里「安装/卸载」「干净机验证」两项**仍是手工**；
- 壳单测 27 例，低于 `../design/10` 定的 ≥30。

## 二、范围

| 步 | 动作 | 完成判据 |
|---|---|---|
| 8.1 | **pytest 分层 marker**：`unit` / `integration` / `e2e` 三类 marker + `pyproject.toml` 注册 | `pytest -m unit` / `-m integration` / `-m e2e` 各自可单独跑 |
| 8.2 | **CI 流水线**：一条命令跑「静态 → 单元 → 契约 → 集成 → 前端/壳 → 端到端 → 打包自检」，任一层失败即非零退出 | 脚本 `scripts/ci-gate.mjs`（或等价）可本地复现 |
| 8.3 | **L0 文档门禁进 CI**：`check_endpoint_table.py` + `check_all.py` + `check_links.py` 纳入流水线 | 改一个端点不同步文档 → 门禁失败 |
| 8.4 | **迁移 `downgrade()` 实跑演练**：对 `0002`~`0007` 逐个 `upgrade → downgrade → upgrade`，断言 schema 一致 | 演练脚本 + 记录（可写进 `../design/12`） |
| 8.5 | **安装/卸载冒烟自动化**：NSIS 静默安装 → 启动自检 → 静默卸载 → 校验残留目录 | 脚本产出安装/卸载日志与残留清单 |
| 8.6 | **壳单测补到 ≥30 例**：补 `tray` / `shortcuts` / `notifications` 的单测（与 `../plan/02` 联动） | 壳 vitest ≥ 30 passed |
| 8.7 | **README 数字自动校对**：把 `backend/README.md` 等处写死的用例数改为「引用 CI 实测」或加校对脚本 | 脚本发现失实即失败 |
| 8.8 | **发布清单模板化**：每次发版产出「产物 + 冒烟结果 + 已知限制（体积/签名/自动更新）」 | 清单模板落在 `deploy/` 或 `doc/design/` |

## 三、验收标准

1. 回归基线**不下降**：后端 ≥ 326、前端 ≥ 64、壳 ≥ 30、e2e ≥ 39。
2. `scripts/ci-gate.mjs`（或等价）**本地一次跑通**并在 CI 配置里生效。
3. 迁移演练记录进 `../design/12-阶段交付台账.md`。
4. 文档：`../design/14` 的「尚未落地」表清空对应行并改为「✅」。

## 四、回滚

| 变更 | 回滚 |
|---|---|
| CI 流水线 | 不接 CI 即可（本地脚本仍可用） |
| 分层 marker | marker 只是标签，移除不影响用例 |
| 演练/冒烟脚本 | 独立脚本，删除即回滚 |
