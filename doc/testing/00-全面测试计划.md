## 0. 结论先行：现状不是"没测试"，而是"测试不可消费"

这个项目的测试资产比多数同类项目都厚：367 个后端用例、83 + 45 个前端/壳用例、59 条端到端、9 项打包自检，而且 `tests/common/harness.py` 已经做了数据隔离、失败截图、前端产物新鲜度校验。**问题不在用例数量，在五个"测了但用不上"的环节**：

| # | 现状事实（已核实） | 后果 |
| --- | --- | --- |
| 1 | 基线数字曾三处不一致（`design/14` 写 326/64/27/39，`analysis/00` 写 366/83/45/44，壳文档写 27）——**2026-10-30 已统一到 367/83/45/59**（`analysis/00` §5 常量表 C17/C18/C23/C24） | 口径已收敛；但**无自动校验脚本**，仍会漂移 → `doc/plan/05` P5-05 |

| 4 | 结果不可消费：`tests/report/` 已累积 **146 个 `report-*.md`**，无索引、无保留策略、失败无统一 `errorCode`/归类，`classify` 只存在于文档描述 | 失败复盘靠翻文件；flaky 无法定量；趋势不可得 |
| 5 | **无 `.github/`，无 CI**；`design/14` §11 已诚实声明"四层测试靠人跑" | 门禁靠自觉，`tests/pytest.ini` 也没有 `unit/integration/e2e` marker，无法只跑快层 |

另有三个**已被历史验证的坑**，本计划强制写进用例（不是建议）：

- **旧 dist 幻觉**：`harness.ensure_frontend_built()` 的注释记录了真实事故——`frontend/dist` 停在 10-25，WEB-33/34 报"速记形态失效""附件上限无提示"，重建后全过，产品无缺陷。**任何 UI 结论都必须带 `dist` 指纹**。
- **macOS 上"环境不具备"被当成跳过**：`electron_binary()` 早期只认 `electron.exe` / `electron`，漏了 `Electron.app/Contents/MacOS/Electron`，导致 3 个真机用例**在 macOS 上长期跳过**。**跳过必须分类为 `env_missing` 并计入覆盖率缺口，不能显示为"绿"**。
- **前端产物两处目录**：`frontend/web/vue-element-plus/dist` ≠ 后端托管的 `frontend/dist`，后者必须经 `build-frontend.mjs` 拷贝。测错目录 = 测了不存在的产物。

**本计划的五条主线**：

1. **一个口径**：所有数字只从 `report.json` 生成，文档不再手写（§12 提供 `check_doc_numbers.py`）；
2. **双宿主矩阵**：同一套 91 端点，必须分别在「Web 直连后端」与「Electron sidecar 托管」下验证，不能只测其一（§1.3）；
3. **打包态一等公民**：新增 `PAK-*`（产物/安装/签名/体积/卸载）+ `NAT-*`（托盘/速记/Boss Key/通知/自启），把 9 项自检扩成可回归矩阵（§4.6、§4.7）；
4. **结果规范**：`runId` 自包含目录 + 统一 schema + JUnit + 失败取证 + 自动归类（§5、§6）；
5. **门禁机器化**：L0–L5 分层、marker 划分、需求追溯表可校验、CI 接入路径（§11、§12）。

## 1. 被测形态：四层 × 三宿主 × 三部署

### 1.1 分层与既有资产

| 层 | 入口 | 技术栈 | 既有用例 | 工具 |
| --- | --- | --- | --- | --- |
| **后端** | `backend/app`（FastAPI） | Python 3.11+ / SQLAlchemy 2.0 / APScheduler / Milvus Lite / MCP | pytest **366 / 21 个 test_*.py** | pytest + httpx |
| **前端** | `frontend/web/vue-element-plus` | Vue 3 / Element Plus / Pinia / Vite 6 | vitest **83 / 18 文件** | vitest + jsdom |
| **桌面壳** | `frontend/desktop/src` | Electron 33 / electron-builder 25 / electron-updater 6.3 | vitest **45 / 8 文件** | vitest + mock |
| **端到端** | `tests/web`、`tests/desktop`、`tests/packaged`、`frontend/scripts/ui_probe` | Playwright **Python**（`_electron` + chromium） | **69 例**（web 44 + desktop 10 + packaged 15） | Playwright + pytest |
| **打包自检** | `scripts/verify_desktop_package.py` | Python stdlib + CDP | **9/9** | 自研脚本 |
| **部署** | `deploy/`、`docker-compose.yml` | Nginx / Compose | 无自动化 | 待建 |

> 关键决策：**端到端保持 Playwright(Python) 单栈**。项目已有 `_browser.py` 的三级回退（内置 Chromium → chrome → msedge → chromium）与 `_electron.launch` 用法，再引 TypeScript/WebdriverIO 只会分裂夹具与报告格式，收益为负。

### 1.2 三个运行态（桌面）

| 运行态 | 启动 | 内核/后端来源 | 前端来源 | `isPackaged` | 用例前缀 |
| --- | --- | --- | --- | --- | --- |
| **开发态** | `npm run dev`（Vite 5185）+ `uvicorn`（8000/8001） | 本机 `backend/.venv` | Vite dev server（proxy → 18040） | — | `WEB-` `DOM-` |
| **桌面开发态** | `electron`（`frontend/desktop`） | spawn `python -m ...` | 后端托管 `frontend/dist` | `false` | `DESK-` |
| **桌面打包态** | `release/win-unpacked/Agent.exe` / `Agent.app` | `resources/runtime/python.exe`（portable，`stage-runtime` 组装） | `resources/frontend`（extraResources） | `true` | `PAK-` `NAT-` |

> **打包态与本机开发态是两套运行时**：`paths.ts` 在打包态用 `process.resourcesPath`，开发态靠**向上查找 `package.json`**。`extraResources` 还额外要求 `alembic.ini` 随运行时复制——缺了它迁移失败直接中止启动（`analysis/13` §4）。这条**只有打包态能测出来**。

### 1.3 双宿主矩阵（本项目最容易被漏掉的一维）

同一套 API 有两个宿主，行为不同：

| 维度 | Web 直连 | 桌面 sidecar |
| --- | --- | --- |
| 端口 | 固定 8000/8001 或 Compose 8080 | **随机空闲端口**，写 `run-state.json` |
| 鉴权 | 无会话令牌（本地/内网） | **会话令牌 + Host 白名单**，未授权 → 401 `E_AUTH` |
| 引导 | 直接访问 `/` | `/__desktop/bootstrap?t=<nonce>` → 一次性 nonce → 下发 Cookie → 302 |
| 静态资源 | Nginx 或后端托管 | 后端托管 `resources/frontend` |
| 事件 | 前端直连 SSE | 壳解析 SSE → `BackendEvent` → 转发渲染层（`after_id` 续传） |
| 生死 | 独立进程 | 壳管理：握手 / 探活 / 重启 / 退出清理 / 孤儿回收 |

**规则**：凡 `API-*`、`SSE-*`、`RUN-*` 用例，标注 `host=web|desktop`，**P0 组两个宿主都要跑**；只在 Web 下通过的用例不能算通过。

### 1.4 三种部署形态

| 形态 | 判据 | 用例 |
| --- | --- | --- |
| 本地直跑 | `uvicorn` + `frontend/dist` | `DEP-LOCAL-*` |
| Docker Compose | 对外 8080、容器内 8000、Milvus 19530 | `DEP-COMPOSE-*` |
| 桌面安装包 | 无 Python、无 Node 的干净机 | `PAK-INST-*` |

### 2.2 Electron 三态驱动方式

```python
# 方式 A（首选）：打包产物内的可执行文件
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    app = p._electron.launch(  # noqa: SLF001  Electron 必须用 _electron，不是 chromium
        # Windows
        executable_path=r"frontend/desktop/release/win-unpacked/Agent.exe",
        # macOS: "frontend/desktop/release/mac-arm64/Agent.app/Contents/MacOS/Agent"
        args=["--user-data-dir=<tmp>/ud"],   # 必须独立，否则单实例锁让新实例直接退出
        env={**os.environ, "AGENT_DESKTOP_USER_DATA": "<tmp>/ud"},
        timeout=90_000,                      # portable runtime 首次解包
    )
    page = app.first_window()                # 等 bootstrap 完成后再操作
```

### 2.3 两条铁律

1. **断言的"事实源"必须在被测进程之外**：保存 → 查磁盘；调度 → 查 `scheduled_jobs.next_run_at` 与 `runs` 行；权限 → 查审计表与 401/403 响应体；退出 → 查进程树与 `run-state.json`。不能以 UI toast 或日志"看起来成功"为准。
2. **原生交互只做一次真实点击，其余注入**：托盘→速记窗、通知→`agent:open-run` 各做一次真机验证（`NAT-*`）；其余用例通过 `preload` 暴露的通道或后端 API 直接置状态。

### 3.1 运行域 A：双模式会话（`ENG`）

## 6. 错误分析：怎么从现象定位到层

### 6.1 四份日志 + 一个关联键

| 日志 | 来源 | 关键内容 |
| --- | --- | --- |
| `backend.log` | uvicorn stdout/stderr | 启动、迁移（alembic）、路由注册、SSE 建流/断开、异常栈 |
| `sidecar.log` | Electron `backend.ts` 捕获 | spawn 命令行、`AGENT_DESKTOP_READY` 握手行、探活失败、重启次数、退出码 |
| `shell.log` | 主进程 | 单实例锁、启动页→主窗口、`loadWithRetry`、状态机迁移、托盘/快捷键/IPC 注册 |
| `renderer.log` | `page.on("console"/"pageerror")` | 前端异常、fetch/SSE 失败、404、`E_*` 展示 |

**关联键**：`request_id`（后端每个响应与日志都有，响应头 `X-Request-ID`）+ `run_id` + `runId`（测试批次）。三者同时出现在 `report.json`、`sse.jsonl`、日志里即可端到端串联。

### 6.2 现象 → 首查证据 → 责任层

| 现象 | 首查证据 | 常见根因（本项目真实存在） | 责任层 |
| --- | --- | --- | --- |
| 窗口显示**错误页**而非主界面 | `sidecar.log` 尾部、`run-state.json` 是否存在 | sidecar 未起（runtime 缺 `alembic.ini`）；握手超时；端口被占 | 壳 / 打包 |
| 白屏 | `renderer.log`、`did-fail-load` | `resources/frontend/index.html` 缺失或为旧 dist；路由 base 错 | 打包 / 前端 |
| 反复 401 | `bootstrap` 请求次数、nonce 复用、Cookie | nonce 一次性被复用（重试逻辑重复请求）；Cookie 未下发；Host 白名单不含 `127.0.0.1:<port>` | 壳 / 后端 |
| 界面能开但"无数据" | `backend.log` 的 401/403、`fetch` 状态码 | 桌面态 Cookie 未带上；Web 态 CORS 白名单为空 | 前端 / 后端 |
| SSE 一直转圈 | `curl -N` 首字节、Nginx 配置 | `proxy_buffering on`（Compose）；响应头缺 `text/event-stream`；心跳缺失 | 部署 / 后端 |
| SSE 断线后内容重复/缺失 | `sse.jsonl` 的 `after_id` 序列 | 续传游标用了 `event_id` 而非自增 `id`；服务端未按 `after_id` 过滤 | 后端 |
| 定时任务"没跑" | `scheduled_jobs.next_run_at`、`runs` 行、时区配置 | 租约未释放；`max_concurrent=2` 占满；容器时区 UTC 与用户时区不一致 | 后端 / 运维 |
| 审批卡住不返回 | 审批通道活跃标记、`permission_approval_timeout=120` | 无人值守场景未降级 deny；通道断开后仍等 | 后端 |
| 权限"该拦没拦" | 审计表、裁决链日志 | 规则优先级错；路径归一化漏 UNC/符号链接 | 后端 / 安全 |
| 打包后启动慢/体积超 | `size-report.txt`、`stage-runtime` 日志 | runtime 813MB 未裁剪；`asarUnpack` 规则过宽 | 打包 |
| **开发态过、打包态挂** | `paths.ts` 分支、`process.resourcesPath`、`asar list` | 资源未进 `extraResources`；`asarUnpack` 只覆盖 `**/*.dll`，其他原生件（`.node`/`.pyd`）在 asar 内无法加载；`alembic.ini` 未随 runtime 复制 | **打包** |
| UI 用例失败但源码无关 | `env.frontendDistHash` 与源码 mtime | `frontend/dist` 陈旧（历史事故） | 测试自身 |
| macOS 上用例"跳过" | `skippedDetail.env_missing`、运行时探测日志 | `electron_binary()` 探测路径不全 | 测试自身 |
| flaky | 3 次重跑 + trace 时间线 | 固定 sleep、假 LLM 抖动、端口/临时目录冲突 | 测试自身 |

### 6.3 错误码表

| 错误码 | 含义 | 首查 |
| --- | --- | --- |
| `E_BACKEND_NOT_READY` | 握手超时/探活失败 | `sidecar.log`、`run-state.json` |
| `E_PACKAGED_BOOTSTRAP_FAILED` | bootstrap nonce/Cookie 失败 | 请求次数、403 响应体 |
| `E_AUTH` | 未授权（后端既有码） | 令牌、Host 白名单 |
| `E_SSE_NO_FIRST_BYTE` | SSE 2s 内无首字节 | 代理配置、路由 |
| `E_SSE_SEQUENCE_GAP` | 事件序列缺口 | `after_id` 过滤逻辑 |
| `E_RUN_NOT_TERMINAL` | 超时仍未进终态 | 状态机、工具超时 |
| `E_PERM_BYPASS` | 该 ask/deny 却放行 | 裁决链、审计 |
| `E_SCHED_NOT_FIRED` | 到点未触发 | 租约、时区、并发上限 |
| `E_ARTIFACT_MISSING` | 打包资源缺失 | `extraResources`、`stage-runtime` |
| `E_SIGNATURE_INVALID` | 签名/公证失败 | `codesign`/`signtool` 输出 |
| `E_DIST_STALE` | 前端产物与源码不一致 | `ensure_frontend_built` |
| `E_ENV_MISSING` | 环境不具备（必须计入缺口，不算通过） | 运行时探测日志 |
| `E_ASSERT_MISMATCH` | 期望值不符（业务缺陷） | 实际/期望摘要 |

### 6.4 失败自动归类（`classify.json`）

| 归类 | 判据（按优先级） | 处置 |
| --- | --- | --- |
| `env` | `E_ENV_MISSING`、端口耗尽、无显示、Playwright 浏览器缺失 | 修环境；**同时登记为覆盖率缺口** |
| `stale_artifact` | `E_DIST_STALE` 或源码 mtime > dist mtime | 先重建再判定，禁止直接开缺陷 |
| `packaging` | 仅 `runtime=packaged` 失败，或 `E_ARTIFACT_*`/`E_SIGNATURE_*` | P0，阻塞发布 |
| `shell` | `shell.log`/`sidecar.log` 异常、状态机非法迁移 | 壳缺陷 |
| `frontend` | `renderer.log` 有 pageerror、`E_SSE_*` 且后端正常 | 前端缺陷 |
| `backend` | 后端 5xx、`sse.jsonl` 缺口、裁决链异常 | 后端缺陷 |
| `test` | 3 次重跑 ≥2 次通过 | flaky，修测试并登记 |

**flaky 判定**：同用例重跑 3 次，≥2 次通过 → 标记 flaky，附 3 份 trace；允许 1 次自动重试仅用于抵消假 LLM 抖动，且必须记 `attempts`。禁止用 `retry` 掩盖真实失败（`design/14` §11 已有同款约束）。

### 6.5 崩溃与异常退出

| 类型 | 采集 | 判定 |
| --- | --- | --- |
| sidecar 崩溃 | `sidecar.log` 尾栈 + 退出码 + 状态机 | 是否按 `crashed` 广播并显示错误页（**不静默**） |
| 渲染进程崩溃 | `render-process-gone` | 是否重建窗口且 sidecar 存活 |
| 强杀（模拟断电） | `run-state.json` 残留 | 下次启动是否回收孤儿（PAK-10） |
| 迁移失败 | `backend.log` 的 alembic 报错 | 是否启动中止而非带病运行 |
