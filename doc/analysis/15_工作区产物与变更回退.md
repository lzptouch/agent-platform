# 工作区产物与变更回退

> **依据代码**：`apps/server/src/domain/workspace/{service,manifest}.ts`、`domain/run/{service,executor,workspace-bridge}.ts`、`domain/tools/builtin.ts`、`http/routes/{workspace,runs,files}.ts`（2026-11-01 复核）
>
> **⚠️ 重要事实（2026-11-01 复核）**：`changes` 表在当前 TS 代码里**只有读路径**
> （`/changes/{id}/diff`、`/changes/{id}/revert`、`/runs/{id}/changes`），
> **无任何写入方**（全仓无 `INSERT INTO changes`）——变更追踪的写前快照未接线，
> diff/revert 端点仅对存量数据有效。产物（artifacts）链路是完整生效的。

# 第一部分 现状事实

## 一、定位

把「工作目录」升格为一等资源：创建/列表/切换/归档；每次 run 绑定一个
工作空间（运行期锁死）；产物登记进 `artifacts` 表供结果区展示与下载。

## 二、目录结构约定（`manifest.ts`）

```
{workspace_root}/
├── .agent/               # 内部目录
│   ├── manifest.json     # 工作空间配置
│   ├── memory/  snapshots/{seq}/  audit/  runtime/  locks/
└── artifacts/            # 交付物（用户可见）
```

`ensureLayout()` 创建；`snapshots/` 预建但当前无写入方（见 §五）。

## 三、工作空间实体与 run 绑定

- **创建**：`POST /workspaces`——指定 `root_path` 复用用户目录；不指定则在
  `userData/workspace/` 下自动建 `wb-{YYYYMMDD}-{短id}/`；
- **当前空间**：进程内单例 `currentId` + 模块级 `currentWorkspaceDir`
  （`workspace/service.ts:18`）；`POST /workspaces/{id}/switch` 切换，
  **立即生效但不影响已绑定 run**；
- **run 绑定**：`RunService.createRun()` → `bindWorkspace()`（`run/service.ts:210`）：
  显式 workspaceId → 当前空间 → 自动创建独立空间；结果写 `meta_json`
  （`workspace_id` / `workspace_root`），运行期从 meta 取出并经
  `setCurrentRunContext()` 锁进执行上下文（`run/executor.ts:291`）——
  文件工具与代码执行的 cwd 都以它为基准（`tools/executor.ts:71`）；
- **归档**：`POST /workspaces/{id}/archive` 只改状态，**不删磁盘文件**。

## 四、`manifest.json`

字段：`writable_roots`（默认 `[工作区根]`）/ `default_policy`（allow/ask/deny，
默认 ask）/ `model` / `skills` / `extensions` / `snapshot_budget_mb`（默认 3000）。
`GET/PUT /workspaces/{id}/manifest` 读写（`validateManifest` 校验非法值 → 422）。
注意：主库 `workspaces.manifest_json` 列只写 `'{}'`（真实 manifest 在磁盘）；
manifest 字段当前**无运行期消费方**（权限引擎不读它）。

## 五、变更、快照与产物

### 5.1 产物（✅ 完整生效）

- 登记：Agent 循环内模型调 `emit_artifact` 工具 → `registerArtifact()`
  （`builtin.ts:220`）落 `artifacts` 表（path/title/mime/kind/size/previewable/url），
  同时发 `files` 语义由前端从 `/runs/{id}/artifacts` 拉取；
- 消费：结果区「产物」标签；`GET /runs/{id}/artifacts/{aid}/download`（带
  Content-Disposition）；`POST .../save-as`（复制到指定路径；相对路径落 outputs/）；
- kind 含 `browser`（浏览器页面截图 + 来源 URL），驱动结果区「浏览器」视图。

### 5.2 变更与回退（⚠️ 读路径生效，写路径未接线）

- `GET /runs/{id}/changes`、`GET /changes/{id}/diff`（读快照 + 当前文件做行级 diff）、
  `POST /changes/{id}/revert`（快照复制回原路径，记录 `op='revert'`）——
  端点对**存量** `changes` 行正常工作；
- 但当前 TS 代码**没有写入 `changes` 的调用方**（文件工具不写变更记录、
  不做写前快照）——旧库升级来的数据可查可退，新 run 不产生变更记录。

## 六、文件上传 / 下载 / 删除（`routes/files.ts`）

- 上传：`multipart` 逐 part 校验扩展名白名单（415）→ 落 `outputs/` →
  超 50MB 删除并 413；返回 `{ok, files, items}`；
- 列表/下载/删除以 `outputs/` 为根，`safeJoin` 防路径穿越；
- `GET /files/policy` 暴露当前生效白名单与限额（前端运行时拉取）。

## 七、工作空间 API

8 个端点（`05` §2 workspaces + changes 组）。桌面态另有
`GET/PUT /desktop/workspace`（当前工作区 + 切换，切换发 `workspace_changed` 事件）。

## 八、前端消费

`WorkspacePicker`（composer）、`SpacesView`（/spaces）、`ResultArtifacts` /
`ResultChanges`（结果区）、`FilesView`（/admin/artifacts）。

# 第二部分 原理剖析

## 九、为什么「一次运行一个工作空间」而不是「一个项目一个工作空间」

run 是**副作用的最小单位**：把每次运行的写盘约束在自己的目录里，
撤销/审计/对比都以 run 为边界，互不污染。工作空间切换是「接下来去哪」，
不是「改历史」——所以绑定写进 run 的 meta 并运行期锁死。

## 十、为什么产物要「登记」而不是「扫目录」

工作区里有大量中间文件（脚本、临时数据）。`emit_artifact` 让**模型显式声明**
哪个文件是交付物（带标题/类型/来源 URL），结果区只展示登记过的——
信噪比由产生者（最知道哪个是成品）控制，而不是靠后缀猜测。

## 十一、为什么回退要「写一条 `op=revert` 记录」而不是「删掉原记录」

回退本身也是变更。删记录会抹掉「曾经改过又退回」的轨迹；追加一条
revert 记录让账本保持**只可追加**（append-only），审计链完整。
（该语义在端点层保留；写入方接线状态见 §5.2。）

# 第三部分 已知边界

1. `changes` 写入方未接线（见文首 ⚠️）——`snapshots/`、`audit/` 目录预建无写入；
2. manifest 字段无运行期消费方（§四）；
3. `save-as` 的目标路径不做工作区限制（产物另存是**用户显式动作**，属预期）；
4. 当前工作空间是进程内状态，重启后回落默认目录（`desktop_preferences`
   的 `workspace_dir` 字段保留）。
