# 第二部分 原理剖析

## 九、为什么前端用原生 fetch 而不是 axios

| 维度 | 原生 fetch | axios |
| --- | --- | --- |
| SSE | ✅ `response.body.getReader()` 可流式读 | ❌ 默认缓冲整个响应，需额外配置 |
| AbortController | ✅ 原生 | 早期版本需 CancelToken（已废弃） |
| 体积 | ✅ 零依赖 | +~30 KB |
| 拦截器 | ❌ 需手写 | ✅ 内置 |

平台的三条 SSE 端点都需要流式读取，axios 的默认行为会把 `text/event-stream` 当普通响应缓冲完再返回，流式感完全丧失。因此选原生 fetch，代价是**拦截器、重试、请求队列都要手写**（`client.ts` 的 `request()` 就是手写的最小实现）。

## 十、为什么 SSE 解析要自研 `runSSE` 而不是用 EventSource

| 维度 | `runSSE`（自研 fetch） | 原生 `EventSource` |
| --- | --- | --- |
| 请求方法 | ✅ 支持 POST（`/agent/run` 需要 body） | ❌ 仅 GET |
| 自定义请求头 | ✅ 可带 `Authorization` 等 | ❌ 仅 URL 参数 |
| 取消 | ✅ `AbortController` | ❌ 需 `close()` |
| 自动重连 | ❌ 需手写（本项目用 `after_seq` 游标） | ✅ 内置（但协议级重连不含业务游标） |
| 事件名 | ❌ 本项目只用 `data:`，不用 `event:` 字段 | ✅ 内置 `event`/`id` 字段解析 |

`/agent/run` 是 POST + 请求体 + SSE 响应的组合，EventSource 根本发不出 POST，只能自研。本项目的后端只用 `data:` 行、不用 `event:` 行，因此 `runSSE` 只解析 `data:` 前缀，比完整 SSE 规范简单。

## 十一、为什么研究进度流要「断流续订 + 去重」三件套

`GET /research/{id}/stream` 的最长时长 1800 秒，期间任何网络抖动都会断流。前端的处理（`sse.ts:120-177`）：

1. **断流后回查状态**：流结束 ≠ 任务结束。断流后先 `GET /research/{id}` 查真实状态，只有仍是 `running` 才重订阅；
2. **全量重放 + 去重**：重订阅从 `sent=0` 全量重放，与已有事件按 `stage|timestamp` 去重，避免时间线出现重复阶段；
3. **限速**：每次断流后 `sleep(1000)`，避免疯狂重连。

这套机制的本质是：**把 SSE 从「一次性流」升级成「可恢复的轮询」**，用业务层的 stage 序号替代传输层的连接保活。

## 十二、为什么前后端契约要有一个「唯一事实源」

**现状（2026-10-28 起）**：项目**不再维护独立的前后端契约文档**——原前端 `docs/` 目录（`api-contract.md` / `sse-protocol.md` / `design-tokens.md`）已整体删除。契约的唯一事实源是**代码 + 本目录两篇**：

| 契约面 | 事实源 |
|---|---|
| HTTP 端点（路径 / 参数 / 错误码） | `05_HTTP接口总览.md` + `backend/app/api/v1/` + `backend/app/schemas/*.py` |
| 前端端点常量与类型 | `frontend/web/vue-element-plus/src/api/endpoints.ts`、`frontend/web/vue-element-plus/src/api/types.ts` |
| SSE 事件（类型 / 字段 / 消费方） | `03_Agent执行引擎与事件协议.md` + `frontend/web/vue-element-plus/src/api/types.ts` |
| 设计 Token | `frontend/web/vue-element-plus/src/styles/tokens.css` |

**为什么不再单独写一份契约文档**：平行文档必然与代码漂移——被删除的那份契约文档就出现过端点数 35 vs 58、事件数 15 vs 18、端口 5173 vs 5185 的漂移，根因是它与代码**不同库不同构**、没有自动同步机制。把事实写进「与代码同库的分析篇目」，再用 `_gate/check_refs.py`（`path:line` 存在性校验）与 `_gate/check_endpoint_table.py`（端点表 ↔ OpenAPI）守门，比维护一份平行文档更省事也更可靠。

- 端点与事件的事实写进 `05_HTTP接口总览.md`（后端）与本篇 §4/§5（前端），**两处都带行号**；
