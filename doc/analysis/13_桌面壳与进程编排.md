# 第一部分 现状事实

## 一、进程拓扑

```
Agent Desktop（Electron 33，单实例锁）
├── 主进程 apps/desktop/src/main/
│   ├── index.ts        入口：锁 → 退出清理 → 启动页 → 孤儿回收 → 托盘/IPC/热键/更新
│   ├── backend.ts      BackendSupervisor：fork / 握手 / 探活 / 重启熔断 / 优雅退出
│   ├── window.ts       主窗口：创建 / 引导加载 / CSP / 加载失败重试 / 导航守卫
│   ├── quick.ts        速记面板（Cmd/Ctrl+Shift+Space，640×160 置顶迷你窗）
│   ├── tray.ts         托盘（图标/菜单/角标/点击唤起）
│   ├── shortcuts.ts    全局热键（速记面板固定；Boss Key 默认不绑定）
│   ├── settings.ts     壳设置（userData/config.json：自启/最小化/Boss Key）
│   ├── notifications.ts 系统通知
│   ├── updater.ts      electron-updater（publish 为空则不检查——诚实不误导）
│   ├── backend-events.ts 订阅后端 SSE 事件流 → 解析（parseSseBuffer 纯函数）
│   ├── state.ts        后端状态机（starting/ready/degraded/crashed/stopping/stopped）
│   ├── ipc.ts          IPC 白名单（preload 不直接碰 ipcRenderer）
│   ├── paths.ts        installDir（resourcesPath）与 userDataDir 两类根解析
│   └── navigation.ts   导航守卫纯逻辑（origin 精确比较；后端未就绪一律拒绝）
├── preload/index.ts    白名单桥（contextBridge）
└── utilityProcess（Node sidecar）= apps/server 编译产物
```

## 二、启动序列（`main/index.ts:47`）

1. `app.requestSingleInstanceLock()`——第二实例唤起主窗口后退出；
2. **先武装退出清理**（before-quit + SIGTERM/SIGINT 双路径），再启动后端——
   否则落在「已写 run-state 但未就绪」窗口的终止信号会残留孤儿；
3. `showSplash()` → `cleanupOrphans()`（见 §7）→ 托盘 / IPC / 热键 / updater；
4. `supervisor.start()`（**幂等**：in-flight Promise 收敛，重复调用复用）；
5. 握手成功 → `createMainWindow()`；失败也建窗（错误页显示原因）+ 系统通知。

## 三、sidecar 编排（`main/backend.ts` 的 BackendSupervisor）

| 环节 | 机制 | 参数（`shared/protocol.ts`） |
|---|---|---|
| 拉起 | `utilityProcess.fork(entry, {cwd, env, stdio:'pipe'})` | 注入 13 个 `AGENT_*` + `PLAYWRIGHT_BROWSERS_PATH` |
| 握手 | 监听 stdout 的 `AGENT_DESKTOP_READY {json}` 行 | 超时 90s；握手前退出**立即**失败（不干等） |
| 探活 | `GET /__desktop/ping`（带 token Header） | 30s 间隔，连续 3 次失败判挂死 |
| 重启 | 退避 1s/2s/4s | **熔断 3 次连续失败** → degraded（不再无限重启） |
| 熔断复位 | 连续健康 ≥60s 才清零计数 | 握手成功**不**复位（「起来秒崩」必须累积） |
| 优雅退出 | POST `/desktop/shutdown` → `child.kill()` → 2s 后 SIGKILL 进程组 | Windows 兜底 `taskkill /T /F` |
| 事件流 | 握手后订阅 `/desktop/events`（SSE） | 断连用 `after_id` 补发 |

## 四、引导与访问边界（`http/bootstrap.ts` + `main/window.ts`）

安全模型（`../design/04` §5.2）：

1. 壳生成**两个独立随机数**：常驻令牌 `AGENT_DESKTOP_TOKEN`（只走 Header，
   **永不出现在 URL**）与一次性 nonce `AGENT_DESKTOP_BOOTSTRAP_NONCE`；
2. 主窗口导航到 `http://127.0.0.1:<port>/__desktop/bootstrap?t=<nonce>`；
3. 后端校验 nonce（常量时间比较、**用过即作废**）→ 下发
   `agent_desktop_session` Cookie（HttpOnly + SameSite=Strict + 8h TTL）→ 302 回 `/`；
4. 此后 `/api/v1/` 请求凭 Cookie（页面）或令牌 Header（壳的 Node 侧）；
   **会话 ID 独立随机生成**，无法从 Cookie 反推令牌；
5. Host 白名单：仅 `127.0.0.1`/`localhost` 且端口 == 本进程端口，否则 421
   （防 DNS rebinding）；静态资源豁免；
6. 重启后令牌更换 → `rebootstrap()` 重新引导。

## 五、导航与渲染守卫

- `navigation.ts`：will-navigate 拦截，**origin 精确比较**（`new URL` 解析后比对，
  不用前缀——`127.0.0.1:8080.evil.com` 这类前缀欺骗被排除）；后端未就绪一律拒绝；
- 窗口 CSP 收敛；加载失败自动重试；
- 电源事件：挂起 → 状态置 `degraded`（冻结探活误判）；唤醒 → `onResume()`
  重新探活 + `markReady` + 调 `/desktop/scheduler/resume-scan` **补跑错过任务**。

## 六、壳设置与首启向导

- `userData/config.json`：开机自启（`app.setLoginItemSettings`）、启动最小化到托盘、
  Boss Key 绑定（默认不绑定，避免与系统快捷键冲突）；
- API Key 等写入后端可读的位置（桌面态不依赖 `.env`——`resources/` 只读，
  环境变量由壳注入，见 `09` §五）。

## 七、孤儿回收（`backend.ts:626`）

上次异常退出残留的 sidecar 不能放任（占端口、持旧令牌）：

1. 读 `run-state.json`（pid / port / started_at / **exe 全路径**）；
2. `isProcessAlive(pid)` → 已死则删记录；
3. **归属校验**：命令行含 sidecar 入口 `main.js` 或记录的 exe 路径——
   PID 被系统复用时**绝不能**发信号（会误杀无关进程）；
4. SIGTERM → 等 2s → SIGKILL → **确认退出后**才删 run-state；
   无法确认归属（`not-ours`/`alive`）则**保留**记录下次再试；
5. run-state 只在**应用正常退出**（before-quit / SIGTERM/SIGINT）时主动删除。

## 八、事件桥（后端 → 壳 → 渲染进程）

`backend-events.ts` 连 `/desktop/events`：`parseSseBuffer` 纯函数解析（可单测），
断连自动重连 + `after_id` 补发；事件经 `supervisor.onBackendEvent` →
`webContents.send('agent:backend-event')` 到渲染进程（权限审批、工作区切换、
补跑结果驱动 UI 与系统通知）。后端状态变化另走 `agent:backend-state`
（渲染侧据此展示启动中/降级/崩溃/已停止四态）。

# 第二部分 原理剖析

## 九、为什么用 `utilityProcess` 而不是 `spawn` 系统 Node

桌面安装包不能假设用户装了 Node。`utilityProcess.fork()` 用 **Electron 内嵌的
Node 运行时**拉起 TS sidecar：随包自带、版本确定、崩溃隔离（独立于主进程），
且由 Electron 托管生命周期（`kill()` 即可结束）。代价：ABI 是 Electron 的
（130）而非系统 Node（137）→ 原生模块需双 ABI 加载（见 `04` §一 与
`../knowledge/10_双ABI原生模块与数据层.md`）。

## 十、为什么握手走 stdout 而不是 IPC 消息通道

utilityProcess 有自带消息通道，但 stdout 握手有个关键性质：**它是后端自己
宣布就绪**（端口、数据目录、版本都是后端绑完套接字后才知道的）。一行
`AGENT_DESKTOP_READY {json}` 是自描述协议——不依赖 Electron 消息时序，
且普通 `node main.js` 裸跑后端时同样可观测（开发/测试友好）。
协议号、端口、pid、路径都在载荷里；**令牌不在其中**（凭据只走环境变量与 Header）。

## 十一、为什么熔断计数「握手成功不复位」

如果握手成功就清零，「起来 → 秒崩」的故障循环会永远达不到熔断阈值
（每次握手都成功）→ 无限重启打满 CPU。只有**持续健康 60s**才证明这次启动
真的稳住了。这是用「时间」给「假康复」去魅。
