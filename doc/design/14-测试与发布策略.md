## 一、测试分层模型（红线）

| 层 | 名称 | 覆盖对象 | 允许的外部依赖 | 触发时机 | 目标时长 |
|---|---|---|---|---|---|
| **L0** | 静态与契约 | 类型、未使用导出、**端点常量与 OpenAPI 一致**、事件类型一致 | 无 | 每次提交 | < 90s |
| **L1** | 单元 | 纯函数与单类：判定算法、归一化、RRULE、压缩模板、扫描规则、路径解析 | 无（纯本地） | 每次提交 | < 60s |
| **L2** | 契约 | 端点存在性、错误体结构、分页、事件协议、幂等键语义 | 仅本地后端 | 每次提交 | < 90s |
| **L3** | 集成 | 迁移与约束、调度幂等与租约、审批链路、快照回退、MCP 会话、权限判定全链路 | 本地后端 + 临时 SQLite | 每次提交 | < 300s |
| **L4** | 端到端 | 浏览器真实路径：工作台、计划审批、权限审批、结果区、定时任务 | 本地后端 + 前端 + 可选真实模型 | 每日 + 阶段出口 | < 900s |
| **L5** | 打包冒烟 | 产出包 → 启动 → 握手 → 加载 → 关闭 → 卸载 | 打包机 | 阶段出口 + 发布 | < 600s |

**分层红线**（不可突破）：

- L0~L3 **禁止真实 LLM 调用**（用 `FakeClient`）；真实调用只在 L4 且带额度上限；
- L1 禁止起进程、禁止访问网络与磁盘（除 `tmp_path`）；
- L3 允许起子进程（MCP / 执行器），但用假执行器替代真实命令；
- L5 只在发布与阶段出口跑，不进 PR 门禁。

## 二、测试数据与隔离

| 类别 | 规则 | 现状 |
|---|---|---|
| 数据库 | 每例独立临时 SQLite 文件（`tempfile.mkdtemp`）+ 每例后清空全部表；**不用 `:memory:`**（多线程不可见） | ✅ |
| 表清理 | 用例新增表必须同步进 `tests/conftest.py` 的清理清单（**新增表漏清理 = 串用例**） | ✅ |
| 时间 | 业务函数显式接收 `now`（默认 `utcnow`），测试传固定时间；少用 `freezegun`（线程时钟不一致） | ✅ |
| LLM | `FakeClient` / `make_tool_call_response` / `make_text_response` | ✅ |
| 文件系统 | `tmp_path`；工作空间测试用独立根；**禁止写真实 `data/`** | ✅ |
| **插件目录** | 插件安装目标必须是**用户数据目录**（`settings.custom_skills_dir`），**不得写源码树** `skills/` | ✅ 2026-10-28 修正并加隔离测试 |
| MCP | 假 server（本地 stdio 脚本）或 mock 客户端；不连外部服务 | ✅ |
| 调度 | 注入短间隔 trigger + mock 执行器；不依赖真实时钟等待 | ✅ |
| 端口 | 桌面态用 `:0` 分配端口 | ✅ |
| **临时目录** | 统一 `vitest --basetemp=.vitest_tmp`；**禁止使用默认共享 basetemp**（多项目共用会互相删目录，且大批量删除会被环境安全护栏拦截） | ⚠️ 统一 basetemp 待接 → `09` 附录「08-二次全面审计整改计划」 |
| 清理动作 | 测试内不得删除项目目录；涉及删除的用例只作用于 `tmp_path` | ✅ |

## 三、Mock 与替身策略

| 被测对象 | 替身 | 说明 |
|---|---|---|
| LLM | `FakeClient` | 支持 tool_call 序列 |
| 执行器 | `FakeExecutor` | 记录调用序列与取消行为 |
| MCP Server | 本地 stdio 假 server | 覆盖建连、工具、超时、异常 |
| 投递通道 | 内存 sink | 断言载荷与重试次数 |
| 系统通知 | 内存 sink | 断言通知内容与点击行为 |
| 剪贴板 | 内存实现 | 速记预填测试（速记形态未做 → `13` 附录「02-能力接线与扩展落地」） |
| 时间 | 显式 `now` 注入 | 不打桩全局时钟 |

**原则**：替身只替代**边界**（外部系统、时钟），不替代**被测逻辑**；权限判定、上下文裁剪、调度幂等等核心逻辑必须走真实实现。

## 四、CI 流水线（**已建成** → `.github/workflows/ci.yml`，P5-04 · 7 层）

```
PR / 提交
 ├─ L0  类型检查（vue-tsc、tsc）+ 契约检查（前后端常量 vs OpenAPI）
 ├─ L1  单元（vitest -m unit, vitest×2）
 ├─ L2  契约（端点/错误体/事件/分页）
 └─ L3  集成（vitest -m integration）        ← 合并主干前必须全绿
合并主干
 ├─ L4  端到端（四条主路径 + 定时任务路径）
 └─ L5  打包冒烟（仅阶段出口或发布触发）
```

**门禁规则**：

| 层级 | 失败后果 |
|---|---|
| L0~L3 | 阻断合并 |
| L4 | 阻断阶段出口（可先合并主干，但不得推进阶段） |
| L5 | 阻断发布 |

**成本控制**：L4/L5 不在每次提交跑；真实 LLM 调用仅在 L4 且设额度；Windows + Linux 双跑仅在每日与阶段出口。

> **现状（2026-10-28）**：四层测试**全绿但靠人跑**；L0 端点表校验脚本已存在
> （`apps/scripts/ui_probe/contract_check.py`，当前 **118/118 一致**）但**未进 CI**；
> vitest 分层 marker（`unit`/`integration`/`e2e`）未加。→ `09` 附录「08-二次全面审计整改计划」

## 八、缺陷管理

| 级别 | 定义 | 响应时限 | 归属 |
|---|---|---|---|
| **P0 阻断** | 阶段无法出口：功能不可用、数据损坏、安全绕过、构建断裂 | 当日修复 | 当前阶段 |
| **P1 严重** | 主路径错误、崩溃、明显断点 | 2 个工作日 | 当前阶段 |
| **P2 一般** | 次要路径异常、文案与交互瑕疵 | 进入后续阶段 | 记入 [`../analysis/12`](../analysis/12_能力覆盖与风险台账.md) |
| **P3 建议** | 优化项 | 排期外 | backlog |

**流程**：发现 → 记录（含复现步骤、期望/实际、证据路径）→ 定级 → 修复 → 回归 → 关闭。
**禁止**：P0/P1 挂到「下一阶段」——否则阶段出口失去意义。
**台账**：缺陷台账在 [`../analysis/12`](../analysis/12_能力覆盖与风险台账.md)（含优先级与 plan 批次）。

## 十六、数据迁移与回退策略

| 阶段 | 迁移 | 回退方式 | 风险 |
|---|---|---|---|
| S1 | `0003`：`sessions.mode` 归一（plan → work + `plan_first`） | `downgrade()` 还原；`plan_first` 留在 `config_json` 不丢 | 低 |
| S2 | `0004`：权限规则扩展 + 决策日志表 | `downgrade()`；旧列保留一个版本 | 低 |
| S3 | `0005`：工作空间 / 变更 / 产物三表 | 表留空不删；旧代码路径不依赖 | 低 |
| S5 | `0006`：计量与记忆索引两表 | 表留空不删 | 低 |
| S6 | `0007`：角色 / 插件 / 黑板四表 | 表留空不删 | 低 |
| S7 | （未新增迁移；`rrule` 字段待接） | `cron_expr` 保留双读 | 低 |

**原则**：

1. **一次一阶段一迁移**，不合并；
2. 显式 DDL，**不用 `create_all`**（新迁移一律 `op.create_table`/`op.add_column`）；
3. 迁移幂等或可重复执行（用 inspector 判存）；
4. **删除列为最后一步**——任何「清理旧列」的迁移必须延后一个版本；
5. 每次迁移都要在**存量库**（有真实数据的副本）上跑一次，不能只在空库验证（⏳ 未做 → `09` 附录「08-二次全面审计整改计划」）。

### P6-07 · 桌面端孤儿回收语义修正　<sub>来源：`design/09` **R-62**　<sub>2026-10-30 打包自检跨平台修复后追加</sub></sub>

| 要素 | 内容 |
| --- | --- |
| **现象** | 打包态自检第 8 项「重启后写出新的 run-state（旧孤儿被回收）」失败：强杀 sidecar 后 `run-state.json` **未残留**，与「残留供下次启动回收」的预期语义不一致（自检实测 `残留=False`） |
| **根因** | `run-state.json` 的清理路径与「进程已死但文件应保留」的语义冲突——正常退出时会删、SIGKILL 时不删，形成「有时残留、有时不残留」的不确定行为 |
| **整改** | 明确 `run-state.json` 的生命周期：**只有正常退出才删，异常终止必留**；强杀场景保证文件与其中 pid 仍在，供下次启动的 `cleanupOrphans()` 回收 |
| **验收断言** | ① 强杀后 `run-state.json` **存在**且 `pid` 指向已死进程；② 重启后写出**新的** `run-state.json`（pid 不同）；③ 旧 pid 对应的 sidecar 被回收 |
| **测试用例 ID** | `DESK-ORPHAN-01`（`tests/docs/testing/00` §4.9.5）+ 打包自检第 8 项 |
| **回归风险** | 低——仅影响退出时的文件清理时机，不改变运行期行为 |
| **回滚** | 恢复原清理钩子（单点） |
