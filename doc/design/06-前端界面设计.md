# 06 · 前端界面设计（Frontend UI）

> **依据**：现状取自 2026-10-26 对 `apps/ui/src/` 的盘点；目标取自仓库根 `文档.md` §8（交互逻辑参考）与 §11.6（结果区四视图）、`doc/reference/01-桌面竞品交互对标.md` 的 45 条交互模式目录。
> **整理日期**：2026-10-26　**对应基线**：commit `c4dac22`
> **文档性质**：本篇定义**界面结构、交互状态与数据来源**。目标态的核心变化有三处：两栏 → 三栏（加结果区）、权限双轨 → 单一三态、"停止"从假中止 → 真中止 + 可转向。

## 2. 目标信息架构

### 2.1 三栏工作台

```
┌─ 左栏 280px ─────────┬─ 中栏 flex:1 ───────────────────────┬─ 右栏 380px ─────────┐
│ ⊕ 新建任务            │  [任务标题]      [模式][模型][权限]  │  结果区（Tab 切换）    │
│ ⬡ 任务（运行中 N）     │                                     │  ┌ 产物 │ 文件 │ 变更 │ 浏览器 ┐
│ ▤ 工作空间（可切换）    │  对话流                            │  │                    │ │
│ ⚙ 能力（技能/角色/MCP）│   · 用户消息                        │  │  · 本次运行的产物    │ │
│ ⏱ 自动化              │   · 助手消息 + 轨迹折叠              │  │  · 中间产物         │ │
│ ▤ 资料库              │   · 计划确认卡                      │  │  · 变更列表 + diff  │ │
│                       │   · 审批卡（权限）                   │  │  · 浏览器会话截图    │ │
│ ── 任务列表（分组）──   │                                     │  │                    │ │
│  · 运行中（含进度条）   │  ┌───────────────────────────────┐ │  └────────────────────┘ │
│  · 已完成               │  │ 输入区                       │ │                          │
│                        │  │ @ 引用 · / 技能 · 📎 · 工作空间 │ │                          │
│                        │  │ [发送 / 停止]  [追加指令]      │ │                          │
│                        │  └───────────────────────────────┘ │                          │
└────────────────────────┴─────────────────────────────────────┴──────────────────────────┘
```

### 2.2 三栏与现状的差异

| 差异 | 现状 | 目标 | 阶段 |
| --- | --- | --- | --- |

## 3. 关键界面线框

### 3.1 权限审批卡（新增，S2）

```
┌────────────────────────────────────────────────────────┐
│ ⚠ 需要确认 · 高风险                                     │
│ 工具：builtin.fs.write_file                             │
│ 目标：C:/Users/me/Documents/预算.xlsx                    │
│ 理由：超出当前工作空间（可写根：D:/work/wb-20261026-x1） │
│ ┌────────────────────────────────────────────────────┐ │
│ │ 预览：将被写入 1 个文件（约 42KB）                  │ │
│ └────────────────────────────────────────────────────┘ │
│ [ 仅本次允许 ] [ 本工作区始终允许 ] [ 拒绝 ]           │
│ ⌛ 120s 后自动拒绝                                       │
└────────────────────────────────────────────────────────┘
```

**规则**：`critical` 风险不提供"全局始终允许"；超时按拒绝；拒绝后模型收到明确原因。

### 3.2 运行中干预（S4）

```
输入区（running 态）：
┌────────────────────────────────────────────────────────┐
│ 当前命令执行中：python build.py（已运行 12s）            │
│ 追加的指令将在当前命令结束后生效  [仍然停止]              │
├────────────────────────────────────────────────────────┤
│ 输入补充指令…                            [追加] [停止]   │
└────────────────────────────────────────────────────────┘
```

**诚实提示是硬要求**：阻塞式执行器无法中断正在跑的命令，UI 不得显示"已生效"。

### 3.3 变更视图（S3）

```
变更（3）   ⓘ 全部可回退
├─ D:/work/wb-x1/report.docx      修改  +12 −3   [查看] [回退]
├─ D:/work/wb-x1/chart.png        新建  128KB    [查看] [回退]
└─ D:/work/wb-x1/data.csv         修改  +1 −1    [查看] [回退]
```

### 3.4 空态与首任务引导

保留现状的空态 hero + 能力 Chip（已对齐 WorkBuddy 首页结构），**追加**："选择工作空间"入口与"权限档位"提示，避免用户第一任务就撞上审批弹窗。

## 4. 交互规范（状态 → 交互 → 数据源）

| 交互 | 状态 | 行为 | 数据源 / 端点 |
| --- | --- | --- | --- |
| 模式切换 | 三态 | `plan` 自动新建任务（现状已实现） | `stores/workspace.ts` |
| 权限档位 | 三态徽标 | 点击打开规则面板；显示**当前档位**（由后端 `effective_level` 汇总），不再是本地布尔 | `GET /desktop/permissions`（目标：`GET /permissions/rules`） |
| 计划确认 | pending/approved/rejected | 步骤可编辑后确认 | `POST /agent/runs/{id}/approve` |
| 权限审批 | pending | 阻塞；倒计时；四选项 | `POST /permissions/decisions/{id}` + `permission.requested` 事件 |
| 停止 | running | 调 `POST /runs/{id}/cancel`（**必须调**），UI 进入"正在停止" | `runs/{id}/cancel` |
| 追加指令 | running | 调 `POST /runs/{id}/steer`，显示"将在当前命令结束后生效" | `runs/{id}/steer` |
| 产物 | 有/无 | 右栏"产物" Tab；点击预览/另存 | `GET /runs/{id}/artifacts`、`POST /artifacts/{id}/save-as` |
| 变更 | 有/无 | 右栏"变更" Tab；diff 抽屉；回退 | `GET /runs/{id}/changes`、`POST /changes/{id}/revert` |
| 耗时 | 完成 | 三段时间戳（发送→首 token→完成） | 事件流时间戳 |
| 折叠 | 完成 | 自动折叠该轮并给摘要，可展开 | `stores/rounds.ts`（**接入**） |
| 并行观察 | 多任务 | 侧栏显示状态与进度；可切换观察 | `GET /runs/active` |
| 成本 | 完成 | 展示本次消耗与区间 | `GET /runs/{id}/cost` |

## 6. 状态管理与数据流

### 6.1 store 划分（目标）

| store | 职责 | 关键状态 |
| --- | --- | --- |
| `workspace` | 当前任务、模式、工作空间、任务流 | `sessionId`、`mode`、`workspaceId`、`tasks[]` |
| `session` | 会话列表与详情 | 已有 |
| `config` | 模型、技能、MCP、开关 | 已有 |
| `permissions` | 规则、当前档位、审批队列 | 扩展：档位来自后端；审批队列新增 |
| `desktop` | 桌面能力与状态 | 扩展：订阅 `agent:backend-state` |
| `runs`（新增） | 运行中任务、进度、成本 | `active[]`、`costByRun` |
| `result`（新增） | 右栏四视图数据 | `artifacts`、`files`、`changes`、`browser` |

### 6.2 SSE 消费规范

| 规范 | 内容 |
| --- | --- |
| 单一入口 | 所有流式数据经 `api/sse.ts`；视图不得直接 `new EventSource` |
| 断线续传 | 统一用 `after_seq` / `after_id` 游标；重连后按游标补齐 |
| 去重 | 以 `(run_id, seq)` 去重（现状 `streamResearchWithReconnect` 已有去重逻辑，可复用） |
| 降级 | SSE 不可用时降级为轮询 `/runs/{id}/events`（后端已有该端点） |
| 事件类型 | 与后端 `run_events` 保持一致；前端类型集中在 `api/types.ts` |

## 7. 验收标准（前端域）

| # | 标准 | 验证方式 |
| --- | --- | --- |
| 1 | 三栏结构成立 | 截图断言：左/中/右三区可见且可折叠 |
| 2 | 权限单轨 | 工作台与设置页显示同一档位；改一处另一处同步 |

| 6 | 变更可回退 | 点回退 → 文件恢复 → 变更列表出现 revert 记录 |
| 7 | 耗时可见 | 每条回复显示耗时，完成后定格 |
| 8 | 折叠可用 | 完成后自动折叠，展开内容完整 |
| 9 | 并行可观察 | 两个任务同时运行，侧栏均显示状态与进度 |
| 10 | 无孤儿常量 | `endpoints.ts` 与 api 封装一一对应（契约检查通过） |
