# 01 · 功能需求规格（Requirements）

> **依据**：目标形态取自仓库根 `文档.md`（§8 交互逻辑、§9 三维对标、§11 实现规格）；现状取自 2026-10-30 **代码级复核**（逐条 grep + 实跑）。
> **整理日期**：2026-10-26 首版 / **2026-10-30 全量复核并补「实现状态」列**
> **对应基线**：commit `7385dcd` + 工作区未提交改动（`apps/server/src/` + `apps/ui/src/` + `apps/desktop/src/`）
> **文档性质**：本篇是**需求的唯一清单**：每条需求有编号、验收标准、所属阶段与优先级。**2026-10-30 起每条额外带「实现状态」列**——这是「哪些功能已实现、哪些还没实现」的**逐条权威答案**。
> **编号规则**：`F-<域>-<序号>`。域：`SEC` 安全 / `WS` 工作空间与产物 / `RUN` 运行控制 / `CTX` 上下文与成本 / `EXT` 扩展与协作 / `SCH` 自动化与集成 / `UX` 界面交互 / `ENG` 工程质量。**编号一经分配不再复用**。
>
> **实现状态判定口径**（与 [`09-差距矩阵与整改清单.md`](./09-差距矩阵与整改清单.md) §六 1.2 同源，**代码级复核**）：
>
> | 标记 | 含义 | 判定依据 |
> |---|---|---|
> | **✅ 已实现** | 生产路径真的生效 | 代码有生效逻辑 **且** 有测试覆盖 **且** 有阶段执行记录 |
> | **⏳ 部分** | 骨架在，但能力不完整或只在部分形态/路径生效 | 存在「实现了但没接线」「只覆盖一半」「口径不符」 |
> | **⛔ 未实现** | 完全没做 | 无生效逻辑；或已明确登记为「不做」 |
>
> **⏳ / ⛔ 的唯一去向**：[`../plan/`](../plan/README.md) 的 P1~P6 六批次。本篇不写施工方案。


> **📌 状态横幅（2026-11-01 · 单运行时改造后）**：本文中「**Web 形态**」「浏览器形态」
> 「`web-e2e`」「CORS」「API Key 鉴权」等表述描述的是**改造前**的形态，**现已退场**
> （design/16 §9.1）。现行形态只有**桌面安装包**（Electron 壳 + 内嵌 TS sidecar）：
> - 渲染进程与 sidecar **同源** → **无跨域、无 CORS、无 API Key**；
> - 鉴权改为「**Host 白名单 + 一次性引导 nonce + 会话 Cookie**」；
> - `tests/web/`（44 例）与 `tests/deploy/`（8 例）随之删除。
>
> **后端路径**同时由 `backend/app/**`（Python）迁到 `apps/server/src/**`（TypeScript）；
> **前端**由 `frontend/web/vue-element-plus/` 迁到 `apps/ui/`。
