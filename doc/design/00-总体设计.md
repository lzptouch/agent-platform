## 1. 产品定位

**一句话**：本地优先的通用 Agent 工作台——用自然语言下达办公与轻量研发任务，Agent 在**授权范围内**自主规划、调用工具、产出可直接验收的成果；全程**过程留痕、可回溯、可撤销**。

三条定位边界：

| 维度 | 定位 | 含义 |
| --- | --- | --- |
| **执行位置** | 本机执行 | 读写授权目录内的文件、运行脚本、生成文档/表格/PPT；模型推理可云可本地 |
| **能力来源** | 扩展层可插拔 | 技能 / 角色 / 连接器 / MCP / 插件包 / 资料库 / 记忆 |
| **风险姿态** | 边界内自动、边界外询问 | 默认工作区内常规读写直接放行；越界、删除、执行、联网按规则询问；高危直接拒绝 |

**与 Web 形态的关系**：同一后端、同一套能力链、同一份数据与配置；桌面形态只是**多一个壳**（Electron + sidecar），并额外获得在世交互（托盘、热键、剪贴板、通知）与本机文件访问。两形态**能力完全对齐**，不存在"桌面版功能更多"的口径。

## 3. 核心概念模型

> 概念之间只允许**单向依赖**：`任务 → 工作空间 → 权限规则 → 运行 → 产物/变更`。

| 概念 | 定义 | 关键属性 | 与现状的关系 |
| --- | --- | --- | --- |
| **会话 Session** | 一段对话的容器 | `mode ∈ {chat, plan, work}`、标题、归属、归档 | 已有（`sessions` 表）；`mode` 枚举需统一 |
| **任务 Task** | 一次执行的容器（= 一个 run 的业务视角） | 触发方式（手动/定时/API）、工作空间、模式、审批状态 | 已有（`runs` 表，8 态状态机） |
| **工作空间 Workspace** | **任务的落地边界**：一个独立目录 + 一份 manifest | 可写根、默认策略、模型、技能、启用的连接器 | **新增概念**：现状是全局可变目录 |
| **权限规则 Permission Rule** | 对"什么动作"给"什么裁决" | scope(file/command/tool/network)、pattern、action(allow/ask/deny)、priority、risk | 已有简化版（3 scope、无 priority），需扩展 |
| **决策 Decision** | 一次权限判定的留痕 | 命中规则、原因、裁决来源、耗时 | **新增表** |
| **运行 Run** | 一次执行的全过程账本 | 状态、计划、耗时、token、成本、产物、变更 | 已有（`runs` + `run_events`） |
| **产物 Artifact** | 可交付物 | 类型、预览、来源 run、路径 | **新增表**（现状为 `files_json`） |
| **变更 Change** | 对既有文件的修改 | 前后哈希、快照引用、操作、工具 | **新增表** |
| **技能 Skill** | 一组可执行工作流 | `SKILL.md` + scripts/references/assets、启停、来源 | 已有（文件为真相 + 表索引） |
| **角色 Role** | 人设 + 方法论 + 工具集 | 身份、边界、工作流、风格 | **新增概念**（现状 `teams` 是技能组合） |
| **连接器 Connector** | 外部服务账号接入 | 类型、授权方式（公共/个人）、凭据位置 | **新增概念**（现状靠 MCP Server 近似） |
| **记忆 Memory** | 跨会话的用户事实与偏好 | 作用域（用户/工作区/项目）、摘要、标签 | **新增概念** |
| **审计 Audit** | 动作级留痕 | JSONL：时间/run/工具/参数/裁决/规则 | **新增** |

**概念更名的三条硬规则**（避免同一物两名）：
1. `teams`（现状：技能组合 + 编排策略）→ 拆成 **`roles`（角色）** 与 **`orchestrations`（编排策略）**；
2. `workspace`（现状：全局目录）→ 升格为**资源实体**，与"目录路径"区分；
3. `plan` 不再作为 `mode` 的第三个值存在——**只有 `chat | plan | work` 三态**，DB 落库时 `plan` 归一为 `mode=work + plan_first=true`（与前端 `toBackend()` 现状一致）。

## 4. 目标态系统架构（鸟瞰）

```
┌──────────────────────────────────────────────────────────────┐
│ 入口层（三形态，同源同配置）                                     │
│  ┌─────────────┐  ┌──────────────┐  ┌────────────────────┐   │
│  │ Electron 壳 │  │ Web 前端      │  │ CLI（headless）     │   │
│  │ 托盘/热键/通知 │  │ Vue3 SPA      │  │ 计划任务/CI        │   │
│  └──────┬──────┘  └──────┬───────┘  └─────────┬──────────┘   │
│         │  同源 HTTP/SSE（127.0.0.1:动态端口）                   │
└─────────┼────────────────┼────────────────────┼──────────────┘
          ▼                ▼                    ▼
┌──────────────────────────────────────────────────────────────┐
│ 后端（FastAPI，sidecar 单实例）                                │
│  引导与边界：nonce → Cookie → Host 白名单 → 守卫中间件            │
│  ┌──────────────────────────────────────────────────────┐    │
│  │ 执行域                                                  │    │
│  │  Agent 主循环（规划→执行→反思→汇总）· 角色编排 · 上下文治理 │    │
│  │  工具注册表 → 权限判定 → 工具执行（内置 / MCP / 技能）      │    │
│  └──────────────────────────────────────────────────────┘    │
│  ┌────────────┬──────────────┬─────────────┬────────────┐    │
│  │ 运行账本    │ 工作空间      │ 权限与审计    │ 调度       │    │
│  │ runs/events│ manifest/快照 │ rules/decisions│ RRULE/租约 │    │
│  └────────────┴──────────────┴─────────────┴────────────┘    │
│  能力链：Skill · MCP · RAG · Web Research · Deep Research       │
└──────────────────────────────────────────────────────────────┘
          │                    │                     │
   ┌──────▼──────┐      ┌──────▼──────┐       ┌──────▼──────┐
   │ SQLite(WAL) │      │ Milvus 向量  │       │ 模型（云/本地） │
   │ 11 表 → 目标态 │      │ 随 data_dir  │       │ 按角色分档    │
   └─────────────┘      └─────────────┘       └─────────────┘
```

**三条结构原则**：
1. **单一入口协议**：所有形态走同一套 `/api/v1` + SSE 事件协议，不存在"桌面专用接口"与"Web 专用接口"两套语义；
2. **单一真相**：同一事实只有一处权威存储（DB 表 / 文件系统 / 配置），其余是索引或投影；
3. **单向依赖**：入口层 → 执行域 → 基础域（账本 / 工作空间 / 权限 / 调度），执行域不反向依赖入口层。

## 6. 设计原则

| # | 原则 | 具体含义 | 可检验的体现 |
| --- | --- | --- | --- |
| P1 | **权限优先于能力** | 任何会改本地状态的动作必须先过权限判定，且判定只有一个落点 | `tool_registry.dispatch()` 是唯一入口；规则命中原因可查 |
| P2 | **边界内自动、边界外询问** | 用信任分层代替逐条弹窗，避免授权疲劳 | 工作区内常规读写零弹窗；越界/高危才询问 |
| P3 | **事实不可变，结论可重建** | 文件系统里的 `SKILL.md` 是真相，表是索引；索引可强制重建 | `skills` 表可整表重建且结果一致 |
| P4 | **幂等靠约束** | 同一槽位、同一序号、同一权限规则都靠唯一键保证 | `runs(task_id, scheduled_for)`、`messages(session_id, seq)`、`permission_rules(scope, target)` |
| P5 | **失败必须可解释** | 错误要能被用户看懂、被运维定位 | 全局异常处理 + 请求 ID + 决策日志 + 审计 |
| P6 | **上下文是有限资源** | 工具、记忆、历史都要按需装载与压缩 | 50 轮会话上下文占用不线性增长 |
| P7 | **诚实优于完备** | 做不到的能力要显式标注，不靠硬编码假装支持 | `sandbox_available` 由探测得出；无沙箱时 UI 明示 |
| P8 | **形态等价** | 桌面 / Web / CLI 能力等价，只是壳不同 | 三形态共用端点与事件协议 |

## 7. 非目标

| 非目标 | 理由 |
| --- | --- |
| 移动端 / 网页版 / IM 远程下发 | 需账号体系与云端同步存储；当前是单用户本机模型 |
| 企业私有化与 VPC 专享 | 单机形态优先；企业管控（SSO/IP 白名单）留到企业版 |
| 人机双写（框选修订）与 Diff 审阅 | 文档编辑器 / 代码编辑器范式，与本平台定位不符 |
| 分布式队列与工作流编排引擎 | 单机部署，APScheduler + 自有表 + DB 租约已足够 |
| 自研 PTY / 终端渲染 | 需要时复用 `node-pty` 方案 |
| 把后端改写为 Rust 内嵌库 | 工具生态迁移成本高；现有 sidecar 形态已满足核心诉求（见 `文档.md` §11.13） |
