## 2. 目标形态

```
┌──────────────── Electron 主进程 ────────────────┐
│ 单实例锁 → 资源就绪检查 → spawn sidecar         │
│   ← AGENT_DESKTOP_READY {port, token, nonce}    │
│   → 写 run-state.json（pid/port/启动时间）       │
│   → 窗口 loadURL(http://127.0.0.1:<port>/)       │
│   ← GET /__desktop/bootstrap?t=<nonce> → Cookie │
│ ⇄ 订阅 GET /api/v1/desktop/events（SSE）        │
│   → 转 agent:backend-event → 渲染进程            │
│ 状态机变化 → agent:backend-state → 渲染进程      │
│ 电源事件（suspend/resume）→ 调度补偿扫描         │
│ 退出 → 优雅关闭 sidecar → 删 run-state.json      │
└───────────────────────────────────────────────────┘
```

**三条不变式**：
1. **同源**：窗口加载后端托管的页面（`http://127.0.0.1:<port>/`），前端零改动、无跨源；
2. **单实例**：第二个实例把参数转交已有实例并退出；
3. **不留孤儿**：sidecar 的 pid/端口始终记录在 `run-state.json`，异常退出后下次启动可回收。

## 3. 进程编排细节

### 3.1 启动时序

| 步 | 动作 | 失败处理 |
| --- | --- | --- |
| 1 | 单实例锁；已有实例 → 转发参数 → 退出 | — |
| 2 | 读 `run-state.json`；若 pid 存活 → 判定为孤儿 → 回收 | 回收失败则忽略并覆盖 |
| 3 | 资源自检（图标、splash、前端 dist 存在） | 缺失 → 记录并继续（不阻塞启动） |
| 4 | `spawn python -m app.desktop.launcher`（env 带 `AGENT_DESKTOP*`） | spawn 失败 → 弹错误页 + 状态置 `crashed` |
| 5 | 读 stdout 握手行 `AGENT_DESKTOP_READY {json}`（90s 超时） | 超时 → 读 stderr → 展示可读原因 |
| 6 | 写 `run-state.json`（pid、port、started_at） | — |
| 7 | 健康探活（`/__desktop/ping`，30s×3） | 失败 → 重启退避 |
| 8 | 建主窗口 → nonce 引导 → 加载 URL | 加载失败重试 3 次 → 降级错误页 |
| 9 | 订阅后端事件 SSE → 建立事件桥 | 断线 → 指数退避重连 + `after_id` 续传 |
| 10 | 注册全局热键、托盘、电源事件 | 失败 → 降级（不影响主流程） |

### 3.2 崩溃恢复与休眠

| 场景 | 处理 |
| --- | --- |
| sidecar 崩溃 | 退避重启 1/2/4s，3 次熔断 → 状态 `crashed` → 通知用户 + 保留日志 |
| 熔断后 | 不再自动重启；提供"重新启动后端"动作（`desktop:restart-backend`） |
| 系统休眠（suspend） | 记录挂起时刻；唤醒（resume）后调用 `POST /desktop/scheduler/resume-scan` 补偿错过的定时任务（窗口默认 6h） |
| 合盖运行 | 由 OS 挂起进程，**必须如实告知用户**"合盖后长任务可能中断"，并在设置页给出说明 |

### 3.3 退出

| 顺序 | 动作 |
| --- | --- |
| 1 | 通知渲染进程准备退出 |
| 2 | `POST /desktop/shutdown`（sidecar 内部 `should_exit=True`） |
| 3 | 等待 3s；超时则进程树 kill（`killTree`） |
| 4 | 删除 `run-state.json` |
| 5 | 退出主进程 |

## 4. 事件桥设计（补齐断链）

### 4.1 链路

```
后端 domain 事件 → desktop/events.py bus.publish()
   → GET /api/v1/desktop/events（SSE，after_id 续传）
   → 壳 main 订阅（EventSource 或 http 流）
   → 转换为 agent:backend-event 载荷 → webContents.send
   → preload 的 onBackendEvent(cb) → 渲染进程
```

### 4.2 载荷契约

```jsonc
{
  "id": 128,                 // 事件序号（续传游标）
  "type": "run_finished",    // 事件类型
  "ts": "2026-10-26T09:12:33Z",
  "payload": { "run_id": "...", "status": "success" }
}
```

事件类型（壳→渲染）：`backend-state`（状态机变化）、`run-started`、`run-progress`、`run-finished`、`workspace-changed`、`scheduler-rescued`、`notification`（需弹系统通知）、`permission-requested`（需弹审批）。

**渲染进程的订阅方**必须存在，否则事件仍然断在最后一跳——S0 的验收项之一就是"每个 `agent:*` 通道都至少有一个生产者和一个消费者"。

## 8. 验收标准（桌面域）

| # | 标准 | 验证方式 |
| --- | --- | --- |
| 1 | 可产出可安装包 | `npm run dist:win` 产出安装包，CI 留档 |
| 2 | 资源可入库 | `git check-ignore` 对 `frontend/desktop/resources/**` 无命中 |
| 3 | 事件桥贯通 | 后端 publish → 渲染进程收到（e2e） |
| 4 | 状态可感知 | sidecar 崩溃 → UI 进入降级态并提示 |
| 5 | 不留孤儿 | 强杀 sidecar → 重启应用能回收并记录 |
| 6 | 壳有测试网 | `npm test` 用例数 ≥ 15，覆盖 IPC/状态机/路径/事件桥 |
| 7 | 跨平台测试可跑 | Windows 与 Linux 下 e2e 脚本均可执行 |
| 8 | 同源无跨源 | 窗口内无 CORS 报错；`preload` 未暴露 `fs`/`child_process` |
