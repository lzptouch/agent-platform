| 决策 | 理由 | 现在的落点 |

## 一、这批要解决什么

本轮复核的核心发现：**S6（扩展三层）与 S7（自动化）两个阶段存在系统性的「能力虚高」**——
代码写完了、测试也写了、文档也标 ✅，但**生产路径根本不走它**。

判定方法（全仓引用分析）：

```
引用来源只有测试  →  ⬜ 未接线
只有 API 层消费    →  ⚠️ 仅 API 层生效
被运行主链路调用  →  ✅ 已实现
```

**13 个未接线模块清单**（`analysis/12` §1.4）：

| **回归风险** | **高**——跨事件循环持有 `ClientSession` 是当初选「每次新建」的原因（见 `mcp_manager.py:6-8` 的注释）；池化必须保证**同事件循环内复用** |
| **回滚** | 路 A 可回退为「每次新建」（单函数改动）；路 B 需保留旧文件 |
