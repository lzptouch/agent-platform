# 10 · 测试与验收策略（Test & Acceptance Strategy）

> **依据**：现状取自 2026-10-26 对 `backend/tests/`、`frontend/web/vue-element-plus/src/**/*.spec.ts`、`frontend/desktop/`、`frontend/scripts/ui_probe/`、`backend/scripts/` 的盘点；阶段划分见 [`07-实施路线图与风险.md`](./07-实施路线图与风险.md)；需求验收见 [`01-功能需求规格.md`](./01-功能需求规格.md)。
> **整理日期**：2026-10-26　**对应基线**：commit `c4dac22`
> **文档性质**：本篇定义**测试怎么分层、每阶段跑什么、门禁是什么、测试基建先修什么**。原则：**每个阶段都能独立证明自己没破坏上一阶段**。

## 2. 测试分层

| 层 | 名称 | 范围 | 工具 | 运行时机 | 目标时长 |
| --- | --- | --- | --- | --- | --- |
| **L0** | 静态与类型 | 类型、导入顺序、未使用导出、契约常量 | `vue-tsc`、`tsc`、ruff/pyright（可选）、`contract_check.py` | 每次提交 | < 60s |
| **L1** | 单元 | 纯函数与单类：权限判定、路径归一、槽位计算、压缩模板、扫描规则 | pytest、vitest | 每次提交 | < 120s |
| **L2** | 契约 | 端点存在性、错误体结构、事件类型、OpenAPI 与前端常量一致 | `contract_check.py` + 契约测试 | 每次提交 | < 60s |
| **L3** | 集成 | DB 迁移与约束、调度幂等与租约、审批链路、快照与回退、MCP 会话 | pytest（带临时库） | 每次合并 | < 300s |
| **L4** | 端到端 | 真实浏览器跑用户路径：v3 工作台、计划审批、权限审批、结果区、定时 | Playwright（`ui_probe/*`） | 每日 + 阶段出口 | < 600s |
| **L5** | 打包与冒烟 | 产出安装包 → 安装/解压 → 启动 → 握手 → 加载 → 关闭 | `build-desktop.mjs` 自检 | 阶段出口 + 发布 | < 600s |

**分层原则**：
- **L1 不许碰网络与真实模型**（现有 `FakeClient` 模式保持）；**L3 允许起进程但用假执行器**；**L4 才允许真实模型**（用受控账号 + 小额度）；
- 真实 LLM 调用在 CI 中**默认关闭**，用 `AGENT_TEST_LLM=1` 显式开启（避免成本与不稳定）；
- 每层失败都必须能指出"哪条需求没满足"。

## 3. 阶段门禁

> **门禁 = 进入下一阶段的必要条件**。未达成的阶段不得"带病前进"（风险 R12）。

| 阶段 | 必跑层 | 必须新增的测试 | 量化门槛 | 出口判定 |
| --- | --- | --- | --- | --- |
| **S0** | L0 + L1 + L5 | 壳单测 ≥15（IPC/状态机/路径/事件桥）；打包自检 | 壳测试全绿；e2e 在 Windows 可执行；后端 pytest 全量回归 | 桌面可打包可启动 |
| **S1** | L0 + L1 + L2 + L3 | 错误码契约、mode 一致性、配置单源静态检查 | 契约检查通过；pytest 全绿且用例数不下降 | 一套主循环 + 统一错误体 |
| **S2** | L0~L4 | 判定函数单测 ≥20；越界写集成测；审批三态（通过/拒绝/超时）；审计断言 | 权限相关用例全绿；**无"跳过判定"路径** | 越界被拦且可解释 |
| **S3** | L0~L4 | 快照与回退集成测；产物契约；敏感信息单测；右栏组件测试 | 改→回退内容一致 | 变更可查可回退 |
| **S4** | L0~L4 | cancel/steer 集成测（假长命令）；并发上限；前端干预 e2e | 点停止后 run 状态为 `interrupted` | 停止真停、steer 生效 |
| **S5** | L0~L4 | 压缩单测（九段/阈值）、工具装载、预筛 ≤5、成本计算（历史不随单价变）、50 轮长会话回归 | 上下文占用曲线非线性增长 | 上下文与成本达标 |
| **S6** | L0~L4 | 插件安装/回滚、scanner 每类规则一例、黑板依赖调度、上下文隔离 | 安装失败可完整回滚；high/critical 技能被拒 | 扩展三层可用 |
| **S7** | L0~L4 | RRULE 展开、投递重试、幂等回归（既有 14 例必绿）、MCP 三传输、日志字段 | 调度既有用例全绿 | 自动化闭环 |
| **S8** | L0~L5 | 前端组件测试 ≥40；三栏与折叠 e2e；发布自检 | vitest ≥40；L5 自检通过 | 可发布 |

**跨阶段硬性约束**：
1. **回归不可减少**：后端 pytest 用例数、vitest 用例数**逐阶段不得下降**（S0 基线 **122 collected / 0 failed**（既有 1 失败在 S0 修复）· 前端 17 · 桌面 0 → 15）；
2. **新增能力必带测试**：无测试的需求视为未完成（`01` §10 校验规则）；
3. **契约检查进 CI**：L2 不通过即阻断合并。

## 5. 覆盖率与回归基线

| 指标 | 当前基线 | 目标（S8） | 统计口径 |
| --- | --- | --- | --- |
| 后端 pytest 用例 | **147 collected / 147 passed / 0 failed** | ≥220 collected，0 failed | `pytest --collect-only` |
| 前端 vitest 用例 | 17 | ≥40 | `it()` 计数 |
| 桌面壳 vitest 用例 | 0 | ≥30 | 新增 |
| 端点契约覆盖 | 未纳入 CI | 100% 端点有前端封装或显式标注"无前端" | `contract_check.py` |
| 权限判定分支覆盖 | 无 | 判定函数分支覆盖 ≥90% | pytest-cov |
| 关键路径 e2e | 5 个脚本（未门禁） | 4 条主路径（v3 工作台 / 计划审批 / 权限审批 / 结果区）纳入每日门禁 | Playwright 报告 |

**不追求数字，追求关键路径**：上述"目标"是**下限提示**，不是 KPI。任一阶段若用例数达标但关键路径未覆盖，视为未达标。

## 6. 测试数据与隔离

| 类别 | 做法 |
| --- | --- |
| 数据库 | 每例独立临时 SQLite 文件（`tempfile.mkdtemp`）+ 每例后清空全部表；**不用 `:memory:`**（多线程不可见） |
| 时间 | 业务函数显式接收 `now`（默认 `utcnow`），测试传固定时间；少用 `freezegun`（线程时钟不一致） |
| LLM | `FakeClient` / `FakeCompletions` / `make_tool_call_response`（现状已有）；新增能力沿用 |
| 文件系统 | 工作目录用 `tmp_path`；快照与产物测试用独立根，避免污染真实 `data/` |
| MCP | 假 server（stdio 起本地脚本）或 mock 客户端；不连外部服务 |
| 定时 | 注入 `IntervalTrigger(seconds=1)` + mock 执行器，不依赖真实时钟等待 |
| 端口 | 桌面态测试用 `:0` 分配端口（现状 `launcher.py` 已是此法） |

## 7. CI 流水线（目标形态）

```
提交/PR
 ├─ L0 类型与契约     (vue-tsc, tsc, contract_check)
 ├─ L1 单元           (pytest -m unit, vitest ×2)
 ├─ L2 契约           (端点/错误体/事件类型)
 ├─ L3 集成           (pytest -m integration)
 └─ 合并到主干
      ├─ L4 端到端    (Playwright 四条主路径)
      └─ L5 打包冒烟  (build-desktop + 自检)   ← 仅在阶段出口或发布触发
```

**失败处理**：
- L0~L3 失败 → 阻断合并；
- L4 失败 → 阻断阶段出口（可先合主干但不得推进阶段）；
- L5 失败 → 阻断发布。

**成本控制**：L4/L5 不在每次提交跑；真实 LLM 调用仅在 L4 且带额度上限。

## 8. 阶段出口验收清单（模板）

每阶段结束前逐条核对，全部打勾才算完成：

```
[ ] 1. 本阶段"必达需求"（见 01 §10）全部实现，无 TODO 占位
[ ] 2. 本阶段新增测试全部通过，且回归基线未下降
[ ] 3. 契约检查通过（新增端点均有前端封装或显式标注）
[ ] 4. 迁移可正向执行并演练过 downgrade
[ ] 5. 端点数 / 表数 / 用例数已同步到 doc/analysis/00_README.md 与 backend/README.md
[ ] 6. 文档未出现"已支持"但代码无对应实现的情况
[ ] 7. 回滚演练完成（代码回退 + 数据回退）
[ ] 8. 风险登记中本阶段相关风险已复核并更新概率/对策
```
