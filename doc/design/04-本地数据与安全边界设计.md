## 2. 威胁模型

平台把任意本地执行能力放进了用户机器，威胁只有三类，但每类都要独立设防：

| 威胁 | 场景 | 后果 | 主防线 |
| --- | --- | --- | --- |
| **T1 非预期文件操作** | 模型推理出错或被提示注入，触发 `rm -rf`、覆写文档、读取凭据 | 影响范围超出当前目录 | 工作区可写根 + 禁止路径 + 快照回退 |
| **T2 命令执行失控** | 调用磁盘格式化、注册表改写、停止安全服务、串联多条命令 | 系统级破坏 | 命令规则集 + 前置拦截 + 审计 |
| **T3 技能投毒** | 第三方技能包内含网络回传、递归删除、混淆代码 | 数据外泄与静默破坏 | 安装前静态扫描 + 分级 + 默认拒装 + 技能权限受同一套规则约束 |

**贯穿三类的共性原则**：**破坏半径可被限制、可被回滚、可被追溯**。对应三条工程要求：边界（可写根 + 禁止路径）、回滚（写前快照）、追溯（审计 + 决策日志）。

## 3. 权限模型

### 3.1 规则存储

```sql
-- 目标态（迁移 0003）：现有 permission_rules 扩展 + 新增决策日志
CREATE TABLE permission_rules (
  id            INTEGER PRIMARY KEY,
  scope         TEXT NOT NULL CHECK (scope IN ('file','command','tool','network','action')),
  pattern       TEXT NOT NULL,
  action        TEXT NOT NULL CHECK (action IN ('allow','ask','deny')),
  risk          TEXT NOT NULL DEFAULT 'normal' CHECK (risk IN ('normal','elevated','critical')),
  workspace_id  TEXT,                    -- NULL=全局；S2 期间存工作目录标识（sha1(path)[:12]），S3 建表后映射为 workspaces.id
  priority      INTEGER NOT NULL DEFAULT 100,
  enabled       INTEGER NOT NULL DEFAULT 1,
  origin        TEXT NOT NULL DEFAULT 'user' CHECK (origin IN ('builtin','user','enterprise')),
  expires_at    TEXT,                    -- 临时规则的失效时间（永久规则为 NULL）
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL,
  UNIQUE (scope, pattern, workspace_id)
);
CREATE INDEX idx_perm_rules_lookup ON permission_rules(scope, enabled, priority);

CREATE TABLE permission_decisions (
  id             INTEGER PRIMARY KEY,
  run_id         TEXT,
  tool_name      TEXT NOT NULL,
  request_json   TEXT NOT NULL,
  action         TEXT NOT NULL,
  matched_rule_id INTEGER,
  reason         TEXT NOT NULL,          -- 直接展示在审计面板
  decided_by     TEXT NOT NULL CHECK (decided_by IN ('user','policy','timeout','fallback')),
  latency_ms     INTEGER NOT NULL,
  created_at     TEXT NOT NULL
);
CREATE INDEX idx_perm_decisions_run ON permission_decisions(run_id);
```

**scope 语义**：

| scope | pattern 形式 | 例子 |
| --- | --- | --- |
| `file` | 路径 glob（**最长前缀优先**） | `C:/Users/**/Documents/*` |
| `command` | 命令前缀（首 token / 前两 token 组合） | `git reset --hard`、`npm publish` |
| `tool` | 工具命名空间前缀 | `mcp.corp-docs.*`、`builtin.fs.*` |
| `network` | 域名后缀 | `*.internal.corp` |
| `action` | 高危动作分类（保留现状语义） | `batch_delete`、`system_config_write` |

### 3.2 判定算法（唯一落点）

判定只在 `tool_registry.dispatch()` 之前执行一次，任何工具调用都从这里过。

```
1. 归一化
   file     : 展开 ~ → 绝对路径 → resolve 符号链接 → 判存在性 → (canonical_path, op)
   command  : argv 归一（去引号/去重定向）→ cmd_key = 首 token [+ 次 token]
   network  : URL → host + port → 是否本地地址
   tool     : 命名空间 mcp.<server>.<tool> / builtin.<domain>.<tool>
2. scope 分流：按请求类型只查对应 scope
3. 规则匹配：priority 升序遍历，首个命中即定 action
              同优先级时 deny > ask > allow
4. 未命中 → 信任分层回落（见 3.3）
5. action = ask → 写 decision(pending) → 推 permission.requested → 阻塞等待
                  · 用户选择 allow_once    → 本次放行
                  · allow_session        → 写内存临时规则（不落库）
                  · allow_workspace      → 落库规则（scope=file/tool + workspace_id）
                  · deny                 → 拒绝
                  · 超时（默认 120s）     → 按 deny 处理并记 decided_by=timeout
6. 无论路径，finally 写 permission_decisions（含命中规则 ID 与原因）
```

**关键约束**：
- `ask` 必须**阻塞等待**，不能把提示交给模型让模型自己决定（现状即如此，G-01）；
- 超时按 **deny** 处理，**绝不默认放行**；
- 判定结果必须能在 UI 上解释"为什么被拦/为什么放行"。

### 3.3 信任分层（替代逐条弹窗）

逐条弹窗会造成授权疲劳，用户会麻木点"允许"。目标分层：

| 层 | 条件 | 默认裁决 |
| --- | --- | --- |
| L0 只读 | 任何读取类动作（工作区内或外） | allow |
| L1 工作区内常规读写 | 目标在当前工作空间可写根内，且非删除、非执行、非网络 | allow |
| L2 工作区外写 | 目标不在可写根内 | ask |
| L3 破坏性动作 | 删除、批量删除、执行脚本或外部程序、联网、敏感路径 | ask（critical 时先给影响预览） |
| L4 禁止目标 | 命中禁止路径（凭据目录、配置目录、系统目录） | **deny，不询问** |

**默认档位**：`desktop_preferences.default_action` 默认为 `ask`（工作区内常规读写的放行由 L1 自动提供，不需要额外开关）。可切换为 `allow`（等价于现状"完全访问"）与 `deny`（只读工作台）。

### 3.4 规则集与策略

```json
{
  "version": 1,
  "default_action": "deny_write",
  "read": "allow",
  "writable_roots": ["{workspace}", "{workspace}/.workbuddy/runtime"],
  "forbidden_paths": [
    "~/.ssh/**", "~/.gnupg/**", "~/.aws/**", "~/.azure/**",
    "~/.kube/**", "~/.config/**", "~/.workbuddy/**",
    "C:/Windows/**", "C:/Program Files/**"
  ],
  "forbidden_commands": [
    "rm -rf /", "rm -rf ~", "mkfs", "format", "diskutil erase",
    "dd if=", "shutdown", "reboot", "reg delete", "sc stop", "taskkill /f"
  ],
  "recursion_guard": ["~", "~/Desktop", "~/Downloads", "~/Documents"],
  "audit": { "format": "jsonl", "path": "{workspace}/.workbuddy/audit/" }
}
```

**语义**：`default_action = deny_write` = **全盘可读、仅白名单根可写**——比"默认只读"更贴近办公场景（用户要的是"能读我的资料，但别乱改"）。

**归一化要求**（现状缺失，是黑名单被绕过的根因）：
- 路径：解析符号链接与 `..`；Windows 大小写不敏感；UNC 路径单独判定；
- 命令：剥离引号与重定向后取前缀；`;` `&&` `|` 串联命令**逐段判定**；
- 脚本：Python 代码按行扫描危险调用（`os.remove`、`shutil.rmtree`、`subprocess.*`）。

### 3.5 沙箱能力诚实化

当前无沙箱。目标：**先诚实，后增强**。

| 平台 | 目标隔离 | 实现 | 阶段 |
| --- | --- | --- | --- |
| macOS | `sandbox-exec` + App Sandbox / FileProvider / NetworkExtension | 由规则集生成 profile，子进程带 profile 启动 | S2 之后（增强项） |
| Windows | 增强型 Hook（ntdll Hook + 子进程传播） | 路径/命令前置拦截 + 子进程创建 Hook | S2 之后（增强项） |
| 全部平台（兜底） | 规则集 + 写前校验 + 回收站 + 审计 | S2 内交付 | S2 |

**兜底档必须显式告知用户**：能力探测接口返回 `sandbox: {available: false, level: "policy_only", enforced_paths: [...], enforced_commands: [...]}`，UI 在设置页与首次高危操作时如实展示"当前无系统级沙箱，仅策略层拦截"。**禁止**继续返回硬编码 `false` 而不说明替代机制。

## 4. 工作空间与数据边界

### 4.1 目录布局

```
{workspace_root}/{workspace_id}/         # workspace_id = wb-{yyyyMMdd}-{短ID}
├── .workbuddy/
│   ├── manifest.json                    # 工作空间元信息
│   ├── memory/                          # 项目级长期记忆
│   ├── snapshots/{seq}/                 # 写前快照
│   ├── audit/                           # JSONL 审计
│   ├── runtime/                         # 临时产物、shell 快照
│   └── locks/                           # 任务锁
├── artifacts/                           # 交付物
└── (用户文件；可与工作空间根重合)
```

`manifest.json` 字段：`workspace_id`、`owner_session`、`created_at`、`roots[]`（可写根绝对路径）、`default_policy`、`model`、`skills[]`、`extensions[]`、`snapshot_budget_mb`。

**规则**：
- 未指定目录 → 自动创建 `wb-{日期}-{短ID}`；
- 指定目录 → 以其为根，manifest 落其 `.workbuddy/`；
- **项目级隔离**：`<项目>/.workbuddy/` 承载该项目的工作空间清单、MCP 配置与记忆；
- 工作空间与**会话解绑**：一个会话可切换工作空间，但**一个 run 全程锁定工作空间**（防止运行中被换目录）。

### 4.2 快照、变更与回退

| 项 | 设计 |
| --- | --- |
| 快照时机 | 写工具执行**前**，目标已存在且在可写根内 → 复制到 `snapshots/{seq}/{相对路径}` |
| 快照频次 | 同一文件**每轮对话首次修改前备份一次**（避免同轮反复写入产生多份） |
| 预算 | 共享备份空间默认 3000MB，超限按 LRU 清理（清理动作写审计） |
| 变更记录 | `changes` 表：`run_id / path / op(create,modify,delete,move) / before_hash / after_hash / snapshot_ref / tool / size_before / size_after` |
| 展示 | 按 path 聚合；文本走行级 diff；二进制给哈希 + 大小 + 类型 |
| 回退 | 从 `snapshot_ref` 恢复；回退动作本身也走权限判定并留一条 change 记录（op=revert） |

### 4.3 敏感信息保护

| 阶段 | 处理 |
| --- | --- |
| 入模前 | 扫描请求与工具结果中的密钥/凭证模式（正则 + 熵值双判） |
| 落盘前 | 写文件内容同样扫描 |
| 处置 | 按规则：`allow` / `allow_and_encrypt`（密文参与上下文，输出时还原）/ `deny` |
| 默认 | `allow_and_encrypt`（推荐档），密钥类默认 `deny` |

### 4.4 暴露面收敛

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 绑定地址 | `settings.host` 默认 `0.0.0.0` 且无人读取 | 默认 `127.0.0.1`；所有绑定点统一读配置 |
| CORS | 未配置时 `["*"]` + `allow_credentials=True` | 默认空；必须显式白名单；桌面态恒为空（同源） |
| 桌面鉴权 | nonce + Cookie + 常驻 Token + Host 白名单（**已实现**） | 保持；补充 `/api/v1/**` 全覆盖校验与审计 |
| Web 鉴权 | 无 | 至少加一个共享令牌或反向代理鉴权（Web 形态为团队场景） |
| 敏感配置 | `.env` 在 `.gitignore`（**已正确**） | 保持；新增"配置项泄漏扫描"进 CI |

## 7. 验收标准（安全域）

| # | 标准 | 验证方式 |
| --- | --- | --- |
| 1 | 越界写入被阻断 | 集成测试：工作区外路径写入 → 决策日志出现 deny/ask 记录 |
