# 阶段 4：前端整合（工作台 / Plan 审批）+ 端到端验收

> 前置：阶段 1~3
> 交付：对话与工作双界面、Plan 人工确认、团队/技能选择器复用、定时任务页、E2E 与性能验收
> 影响文件：前端新增 8 个、修改 7 个；后端新增 1 个 SSE 端点

---

## 1. 目标

1. **对话模式**（ChatView）：气泡流 + 只读工具 + 多轮历史。
2. **工作模式**（WorkView）：任务工作台——目标输入、步骤时间线、审批计划、产物网格、"转为定时任务"。
3. **Plan 审批闭环**：`approval_required` → 用户确认/编辑/拒绝 → 继续执行并流式展示。
4. 团队/技能选择器、运行时间线、产物网格三处复用。
5. 导航重组 + E2E 五场景 + 性能与部署文档更新。

## 4. 前端改造计划

### 4.1 路由与导航

```
/            → redirect /chat
/chat        ChatView        对话模式（Ask）
/work        WorkView        工作模式（Craft / Plan）
/schedules   ScheduleView    定时任务
/teams       TeamsView       技能团队
/skills      SkillsView      Skill 管理（增强）
/mcp /rag /web-research /research /files /settings /status  保持
```

侧边栏分组：**协作**（对话 / 工作 / 定时任务 / 团队）、**资源**（Skill / 文件）、**能力链**（MCP / RAG / Web Research / Deep Research）、**系统**（设置 / 状态）。

`/` 默认进入对话模式；工作模式不默认，避免误触发写操作。

### 4.2 新增 `src/stores/session.ts`

```ts
state: { mode: 'chat'|'work', currentSessionId, sessions: Session[], loading }
actions: switchMode(mode)   // 切换后清空当前会话、按 mode 拉列表
         loadSessions(), newSession(), selectSession(id), rename(), remove(), archive()
```

- `mode` 持久化 `localStorage`；会话列表按 `updated_at` 倒序；
- 会话切换时取消进行中的 SSE（`AbortController.abort()`），避免串流污染。

### 4.3 新增 `src/composables/useAgentStream.ts`

把 `ChatView` 里的 `switch` 抽成统一事件归约器，输出 UI 状态：

```ts
runStream(payload, {
  onMeta, onDelta, onSteps, onFiles, onApproval, onError, onDone
})
```

- 内部调用现有 `streamAgent`；
- 维护 `answerText / reasoningText / steps[] / files[] / approval`；
- `done` 或 `error` 后统一 `refreshSessions()`；
- WorkView 与 ChatView 共用，避免两份事件逻辑漂移。

### 4.4 修改 `ChatView.vue`（对话模式）

- 移除 work 相关开关（技能多选收入"高级"折叠区，默认不加载）；
- 顶部左侧：会话抽屉（新建/选择/重命名/删除/归档）；
- 顶部右侧：模式切换（对话 ↔ 工作，路由跳转）；
- 只显示 `model_text / reasoning / tool_result / files / error`；
- 输入框占位"问点什么…"，展示当前会话标题；
- 空状态引导：示例问题 3 条。

### 4.5 新增 `src/views/WorkView.vue`（工作台）

布局：

```
┌ 左侧 260px ──┬────────────── 主区 ──────────────┐
│ 工作会话列表  │ 目标输入（多行） + 团队/技能 + 开关 │
│ 状态点/产物数 │ 运行中：RunTimeline（步骤流）        │
│              │ 审批中：PlanCard（确认/编辑/拒绝）    │
│              │ 完成：结果 Markdown + ArtifactGrid   │
│              │ 底部：转为定时任务 / 重新运行         │
└──────────────┴──────────────────────────────────┘
```

- **团队/技能**：`SkillTeamPicker`（互斥），选中团队显示成员 chips 与策略；
- **Plan 模式**：开关 `plan_first`；收到 `approval_required` 后显示 PlanCard，可拖拽排序/编辑步骤文本，确认调 `POST /agent/runs/{run_id}/approve`，随后订阅 `GET /runs/{run_id}/stream` 继续渲染；
- **产物**：`ArtifactGrid` 按类型渲染图片缩略图 / Markdown / 代码 / 其他，点击预览（复用 FilesView 的预览组件，若无则新写轻量预览抽屉）；
- **转为定时任务**：把当前 `prompt + mode + team_id/skills + 开关` 预填进 Schedule 抽屉（`?prefill=<session_id>` 或 Pinia 传参），默认 `enabled=false`，强制用户确认计划与风险后再启用；
- **取消**：`AbortController` 中止 SSE，后端标记 `interrupted`。

### 4.6 新增 `src/views/ScheduleView.vue`

- 列表列：名称 / 调度（`schedule_text`）/ 下次运行 / 上次状态（`el-tag` 着色）/ 连续失败 / 启用开关 / 操作；
- 新建/编辑抽屉（分组）：
  1. 基本：名称、prompt、模式、`plan_first`；
  2. 调度：cron / 间隔二选一；cron 输入防抖 500ms 调 `/schedules/validate`，展示未来 3 次触发；时区选择；
  3. 执行：团队/技能、4 个能力开关、MCP 只读服务器；
  4. 安全：`allow_unattended_tools`（work 必勾）、`allow_dangerous_tools`（默认关，红色警示）、每日上限；
- 行展开运行历史：状态/触发/耗时/摘要/产物/错误；点击打开事件回放抽屉（调 `/runs/{id}/events` 分页 + `ProcessSteps` 渲染）；
- "立即运行"：`run-now?wait_seconds=0` → toast 带 run_id，轮询 `/runs/{id}` 直到终态（最长 60s）。

### 4.7 新增/修改组件

| 组件 | 说明 |
| --- | --- |
| `SkillTeamPicker.vue` | 团队单选 / 技能多选互斥；禁用态说明文案 |
| `RunTimeline.vue` | 现有 `ProcessSteps` 的增强：支持 `approval` / `notice` / 折叠思考 / 耗时 |
| `PlanCard.vue` | 计划步骤编辑、确认、拒绝；展示"定时任务将自动批准"提示 |

### 4.8 `src/api` 扩展

- `types.ts`：`AgentMode`、`RunRequest` 新字段、`Session`、`Team`、`Schedule`、`Run`、`RunEvent`、`AgentEvent` 增补 `meta/approval_required/notice`；

## 5. 后端补充（本阶段唯一新增）

### 5.1 `GET /api/v1/runs/{id}/stream?after_seq=0`

- 实现：DB tail SSE。每 300ms 查询 `run_events WHERE run_id=? AND seq>?`，有则批量 yield，`seq` 推进；run 进入终态且无新事件后 yield `done` 并关闭；总时长上限 30 分钟（与 `schedule_run_timeout` 对齐）；
- 用途：Plan 审批后继续观看执行、定时任务运行实时观看、断线重连（`after_seq` 续传）；
- 与现有 `streamAgent` 的区别：数据源是 DB，不依赖原 HTTP 连接存活，天然支持多标签页/刷新恢复。

### 5.2 运行状态接口补充

`GET /runs/{id}` 返回 `plan_json`、`files`、`status`、`error`、`duration_ms`，供前端轮询兜底。

## 6. 测试计划

### 6.1 前端单元/组件（Vitest + Vue Test Utils）

| 用例 | 断言 |
| --- | --- |
| `useAgentStream` 归约 | 给定事件序列，`answerText/steps/files/approval` 状态正确；未知事件忽略 |
| 中断 | `abort()` 后不再接收增量，状态为 cancelled |
| `SkillTeamPicker` | 选团队 → 技能多选禁用；清空团队 → 恢复 |
| `PlanCard` | 编辑步骤后 approve 请求体携带 `edited_plan`；拒绝调用 reject |
| `RunTimeline` | 步骤顺序、状态着色、耗时展示 |
| `ArtifactGrid` | 图片/文本/其他分类渲染与链接正确 |
| 会话切换 | 切换时 abort 旧流，列表状态不串 |

### 6.2 E2E（Playwright，`frontend/web/vue-element-plus/e2e/`）

| # | 场景 | 断言 |
| --- | --- | --- |
| 1 | 对话模式 | 新建会话 → 两轮问答 → 第二轮引用第一轮信息；页面无"写文件"类工具卡片；刷新后历史仍在 |
| 2 | 工作模式 | 目标"用 data-analysis 生成 CSV 并总结" → 步骤流出现 → 产物出现在 ArtifactGrid → FilesView 可见 |
| 3 | 团队 | 建 sequential 团队 → WorkView 选中 → 发送 → 消息头显示团队名与成员顺序标签 |
| 4 | Plan 审批 | 开 `plan_first` → `PlanCard` 出现 → 编辑一步 → 确认 → 执行完成；另测拒绝 → 会话显示已拒绝且无产物 |
| 5 | 定时任务 | WorkView"转为定时任务" → 预填校验 → 设 1 分钟间隔 → 运行历史出现 success → 事件回放可打开 → 关闭开关后不再新增 |
| 6 | 重启恢复 | 容器重启 → 会话/团队/任务/历史全部保留；运行中的 run 显示"已中断" |

E2E 环境：`docker compose up -d` + `DATABASE_URL` 指向临时卷；LLM 用 **mock server**（返回固定 function call 与文本）保证确定性；仅 `@live` 标记的用例访问真实模型。

### 6.3 性能与稳定性

| 项 | 方法 | 阈值 |
| --- | --- | --- |
| 会话列表 | 5000 会话 / 20 万消息，`GET /sessions?page=1` | P95 < 100ms |
| 消息分页 | 单会话 5000 条，`GET /sessions/{id}?before_seq=` | P95 < 80ms |
| 并发流 | 10 路 work SSE 同时运行 2 分钟 | 无事件串流、内存增长 < 200MB |
| 调度并发 | 20 个任务同刻触发（并发上限 2） | 无重复执行、其余记录 skipped(busy) |
| 事件回放 | 单 run 2000 事件 | 首屏 < 1s，分页 500/次 |
| DB 体积 | 10 万消息 + 5 万事件 | < 200MB，WAL 检查点正常 |

工具：`locust` 或 `pytest + httpx.AsyncClient` 并发脚本；前端用 Playwright trace 记录。

### 6.4 回归与发布
