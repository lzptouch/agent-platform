# 阶段 1：数据基座 + 双模式 + 会话 —— 代码修改计划与测试计划

> 前置：无｜依赖：SQLite / SQLAlchemy 2.0 / Alembic
> 交付：可用的关系型数据层、`chat|work` 双模式（含 `plan_first` 计划态）、会话与运行账本、历史注入
> 影响文件：新增 9 个，修改 8 个

---

## 1. 目标与范围

1. 建立 **SQLite(WAL) + SQLAlchemy 2.0 + Alembic** 数据层，支持 `DATABASE_URL` 切换 PostgreSQL。
2. 落库：`sessions / messages / runs / run_events`（团队/技能/定时任务表在阶段 2、3 建，但迁移文件一次规划好）。
3. `mode=chat|work` 的**真实**行为差异：工具档案、迭代上限、反思开关、Skill 默认策略、历史策略。
4. `plan_first=true` 的工作模式：产出结构化计划 → `awaiting_approval` → 确认后执行。
5. 多轮历史：按会话读取并安全回放。

**不在本阶段**：前端改版（阶段 4）、团队、定时任务。

### 2.1 依赖与配置

`backend/app/core/config.py` 新增：

```python
database_url: str = ""          # 空则用 sqlite:///{PROJECT_ROOT}/data/app.db
db_echo: bool = False
session_history_limit: int = 10         # 回放轮数（消息条数）
session_history_max_chars: int = 8000   # 历史字符预算
chat_max_iterations: int = 5

@property
def database_url_abs(self) -> str:
    if self.database_url.strip():
        return self.database_url
    return f"sqlite:///{(PROJECT_ROOT / 'data' / 'app.db').as_posix()}"
```

`ensure_dirs()` 增加 `data/`（SQLite 文件所在目录）。注意 SQLite 相对路径以 CWD 解析，必须用绝对路径。

### 2.2 新增 `backend/app/db/base.py`

- `engine_factory(url)`：`create_engine(url, connect_args={"check_same_thread": False, "timeout": 30}, pool_pre_ping=True, future=True)`。
- `@event.listens_for(engine, "connect")` 设置：`journal_mode=WAL`、`synchronous=NORMAL`、`foreign_keys=ON`、`busy_timeout=5000`。
- `SessionLocal = sessionmaker(bind=engine, expire_on_commit=False, autoflush=False)`。
- `@contextmanager db_session()`：commit / rollback / close。
- `retry_on_locked(fn, attempts=3)`：捕获 `OperationalError` 且信息含 `database is locked`，指数退避 50/100/200ms。
- 测试钩子 `configure_engine(url)` / `reset_engine()`，供 pytest 指向临时库。

> 全项目复用**同一个 engine**，禁止各模块自建；避免 SQLite 多连接写锁混乱。

### 2.3 新增 `backend/app/db/models.py`

按 00 文档 §7 定义 ORM（`DeclarativeBase` + `Mapped` / `mapped_column`）。本阶段启用：

- `Session`（表名 `sessions`）：`id/mode/title/team_id/config_json/owner/archived/created_at/updated_at`
- `Message`：`id/session_id/run_id/seq/role/content/steps_json/files_json/meta_json/created_at`，`UniqueConstraint(session_id, seq)`
- `Run`：`id/task_id/session_id/trigger/scheduled_for/status/plan_json/started_at/finished_at/duration_ms/result_summary/error/files_json/created_at`，`UniqueConstraint(task_id, scheduled_for)`
- `RunEvent`：`id/run_id/seq/type/payload_json/created_at`，`UniqueConstraint(run_id, seq)`

时间统一 UTC ISO8601 字符串（`datetime.now(timezone.utc).isoformat()`），前端本地化展示；避免 SQLite 无时区类型。

### 2.4 Alembic 接入

- `backend/alembic.ini`（`script_location = app/db/migrations`）
- `backend/app/db/migrations/env.py`：从 `settings.database_url_abs` 取 URL；`render_as_batch=True`；`compare_type=True`
- `versions/0001_init.py`：建 `sessions/messages/runs/run_events` + **`teams` 与 `scheduled_tasks` 表骨架**（为 `runs.task_id / sessions.team_id / scheduled_tasks.team_id` 提供外键目标，业务接口分别在阶段 2、3 启用）+ 索引；`0002` 加 `skills / team_skills`，`0003` 给 `scheduled_tasks` 补列。
  - 若不在 0001 建这两张骨架表，后续需对 SQLite 做 batch 模式加外键，成本更高且易失败，故一次规划到位；表为空不影响阶段 1 运行。
- `backend/scripts/migrate.py`：`alembic upgrade head` 的编程式入口。
- 启动策略：容器 `entrypoint.sh` 执行 `python -m scripts.migrate`；`lifespan` 内在 `init_app_state` 之前调用一次（幂等，开发态友好）；失败则启动中止并打印原因（不静默降级）。

### 2.5 新增 `backend/app/services/session_service.py`

```python
class SessionService:
    def create(mode, title="", skills=None, team_id=None, db=None) -> SessionOut
    def list(mode=None, page=1, page_size=20, include_archived=False) -> Page[SessionOut]
    def get(session_id, message_limit=None, before_seq=None) -> SessionDetail
    def rename(session_id, title)
    def archive(session_id)
    def delete(session_id)                      # 级联 messages；runs.session_id 置 NULL
    def build_history(session_id, limit=10, max_chars=8000) -> list[dict]
    def append_message(session_id, run_id, role, content, steps=None,
                       files=None, meta=None)   # seq = max(seq)+1，事务内
```

`build_history` 规则（关键）：

1. 取最近 `limit` 条 `role IN ('user','assistant')` 且 `content != ''`；
2. 跳过 `assistant` 且 `meta_json.tool_only == true` 的中间态消息；
3. 按字符预算从旧到新裁剪，裁剪后**首条必须是 user**（否则丢弃，避免 OpenAI 兼容接口报错）；
4. 合并相邻同角色消息（`"\n\n".join`）；
5. **绝不回放 `tool` 消息与带 `tool_calls` 的 assistant 消息**（`_stream_loop` 内部会重新生成本轮工具链）。

### 2.6 新增 `backend/app/services/run_service.py`（运行账本）

```python
create_run(db, *, trigger, task_id=None, session_id=None,
           scheduled_for=None, plan_first=False) -> Run
mark_running(run_id)
save_plan(run_id, plan: list[dict])            # status=awaiting_approval
approve_plan(run_id, edited_plan=None) -> Run  # status=running
reject_run(run_id, reason="")                  # status=rejected
finish(run_id, status, summary="", files=[], error=None)
append_events(run_id, events: list[dict])      # 批量 INSERT，seq 自增
list_events(run_id, after_seq=0, limit=500)
```

批量事件写入策略：每 20 条或每 2 秒 flush 一次（避免逐条事务拖慢 SSE）。

### 2.7 新增 `backend/app/services/run_executor.py`

把"Agent 执行 + 落库"从 HTTP 层解耦，供 `/agent/run` 与定时任务复用：

```python
class RunExecutor:
    def execute_stream(prompt, *, mode, session_id, team_id, plan_first,
                       model=None, skills=None, enable_*..., trigger="api") -> Iterator[dict]
    def execute_sync(prompt, **kwargs) -> RunResult
```

`execute_stream` 内部：

1. **在生成器内部** `with db_session() as db:`（不能用 FastAPI `Depends`：`StreamingResponse` 返回时依赖已关闭）；
2. 建 `Run(running)`，`session_id` 不存在则按 `mode` 新建会话并回填 `meta.session_id`；
3. 写 user 消息（`seq` 事务内生成）；
4. 调 `AgentService.stream(..., mode, history)`，逐事件 yield + 批量入库；
5. `plan_first`：首轮只产计划（LLM JSON-mode，复用 reflection planner 的 JSON 解析），落 `plan_json`，状态 `awaiting_approval`，yield `{"type":"plan","plan":[...],"run_id":...}` 后结束；
6. 正常结束：`finish(success)` + 写 assistant 消息（`content` 取最终文本、`steps` 取精简步骤、`files` 取产物）；
7. 异常：`finish(failed, error=...)` 并 yield `{"type":"error"}`；生成器被客户端断开时捕获 `GeneratorExit`，标记 `interrupted`。

> 兼容：`session_id=None` 且 `mode` 未传时，行为与现状一致（不落会话），仅新增 run 记录；可用 `settings.persist_anonymous_runs=false` 关闭。

## 4. 测试计划

### 4.1 测试基座

新增 `backend/tests/conftest.py`：

```python
@pytest.fixture()
def db(tmp_path, monkeypatch):
    configure_engine(f"sqlite:///{tmp_path/'test.db'}")
    Base.metadata.create_all(engine)
    yield
    reset_engine()
```

- 用**临时文件库**而非 `:memory:`（多线程需要共享同一文件；内存库必须 `StaticPool`，易掩盖并发问题）；
- 每个用例独立 DB，避免顺序依赖；
- 所有涉及 LLM 的用例注入 fake OpenAI client（复用现有测试的 monkeypatch 风格）。

### 4.2 数据层单元测试（`test_db.py`）

| 用例 | 断言 |
| --- | --- |
| 迁移 up/down/up | 空库 `upgrade head` → 表齐全 → `downgrade base` → 无残留 → 再 upgrade 成功 |
| PRAGMA | 连接后 `journal_mode=wal`、`foreign_keys=1` |
| 外键级联 | 删 session → messages/run_events 级联删除；`runs.session_id` 置 NULL |
| 唯一约束 | 重复 `(session_id, seq)` 抛 `IntegrityError` |
| 幂等约束 | 相同 `(task_id, scheduled_for)` 第二次插入失败 |
| 并发写 | 8 线程 × 20 条 append → 160 行、seq 连续无重复、无 `database is locked` 逃逸 |
| 事务回滚 | 中途抛异常 → 该 run 的全部事件不落库 |

### 4.3 模式行为测试（`test_mode.py`）

### 4.5 SSE 与运行账本测试（`test_agent_run.py`）

| 用例 | 断言 |
| --- | --- |
| meta 事件 | 首个事件含 `run_id/session_id/mode` |
